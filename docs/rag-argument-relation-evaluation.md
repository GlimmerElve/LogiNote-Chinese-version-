更新日期：2026-10-04。状态：离线评测、首轮分类对照和第二轮方向校验对照已完成，尚未独立人工验收或生产接入。

## 目的与范围

先回答“错在论证单元、关系分类还是证据不足”，再决定提示词、模型或流程改造。当前阶段只评估**给定端点的关系分类**，不声称已覆盖单元抽取、候选边召回、跨段联合推理或事实核验。

第一阶段新增独立评测模块、开发样本、实验提示词和 CLI，没有调用云端。第二阶段在用户明确授权全部 38 条样本后调用既有 DeepSeek 配置完成对照。两个阶段都不修改现有九类节点、生产 support/oppose 类型、编辑器、质量评分、知识准入、索引版本、IPC、检索排序、工作流注册或 AgentSkill，没有下载数据/模型或重建用户索引。

## 标注规范 v1

定义以 `src/services/argumentRelation/contract.ts` 为准。标签只属于评测契约，不直接成为生产图谱边：

- `support`：source 给 target 增加理由或证据，保留条件和不确定性。
- `oppose`：source 反驳或削弱同一对象、条件下的 target。
- `explain`：展开内容或步骤，不增加相信 target 的独立理由。真正作为理由的因果解释仍可能是 support。
- `restate`：改写同一命题，没有新增理由。
- `define`：命名、定义、术语对应。定义参与具体推导时不能仅凭节点类型排除 support。
- `compare`：不同对象、条件、维度的异同，并非对同一命题的反证。
- `insufficient_evidence`：可能存在论证联系，但缺少数据、必要前提、正确端点或限定；不建论证边。
- `unrelated`：不存在可识别的论证或篇章联系。

标注先看方向、对象、时间、条件、否定和模态。命名不证明现象存在；表格介绍不等于表格数据；作者说“由此可见”也不是自动准入条件。上下文重复 target 不能充当独立证据。多个必要前提必须齐全；只有其中一个前提不等于完成推导。

判断的是文本内部的理由关系，不是为原文事实真实性背书。给定端点的错误方向通过方向对照样本体现；当前 `polarityErrors` 仅指支持/反对标签混淆，不冒称所有方向错误率。

## 样本与诚实边界

默认 32 条原创合成开发样本，每类 4 条，包括正反方向、完整/缺失联合前提、相关升级因果、表格缺数据、不同研究条件、英文命名和资料内指令等。

可选读取本地 `data/rag-evaluation/graph-review-v3.json` 与 `graph-review-candidates-v3.json`，只将历史审查显式列出的 6 条问题边转为待复核样本，合计 38 条。这 6 条包括命名误当支持 2 条、表格介绍误当证据 3 条、反对关系端点不当 1 条。

本地历史数据中有 30 条候选边、21 条已准入边；6 条被标记的问题边都在已准入集合。**不能由此推出整体精确率为 15/21**：其余边没有独立正确性标注，问题分类本身也仍待人工裁决。

全部样本均明确标为 `assistant_draft`。合成样本不是用户真实流量；本地样本是问题集中子集，不是随机抽样。当前没有独立留出集。未来划分时按 `groupId` 分组，同一文档、同一命题的正反方向和改写不得跨越训练/验证边界。

本地原文不写入受版本控制的样本；仅在明确传入 `--local-dir` 时从本地加载。`--export-inputs` 会向标准输出输出选中的原文，可能包含私人资料；不会联网，使用外部服务前仍须确认数据范围和授权。

## 运行

```powershell
npm.cmd run check:argument-relations
npm.cmd run evaluate:argument-relations
npm.cmd run evaluate:argument-relations -- --local-dir data/rag-evaluation
```

前者是程序自测；后两者没有预测文件时只显示样本清单和历史审查计数，不输出伪造的模型准确率。

生成实验提示词和不含答案的输入（直接运行 node 避免 npm 标题混入 JSON）：

```powershell
node --experimental-strip-types scripts/evaluate-argument-relations.ts --export-inputs
```

`--local-dir data/rag-evaluation` 可与 `--export-inputs` 组合。输出包含 datasetFingerprint、prompt 和 inputs，不包含 expectedLabel、annotationReason、现有边标签或问题分类提示。

模型预测文件格式：

```json
{
  "datasetFingerprint": "从相同样本导出时取得的指纹",
  "predictions": [
    {
      "id": "pair-001",
      "label": "support",
      "evidenceSentenceIds": ["s1", "s2"],
      "explanation": "依据文本说明方向与限定"
    }
  ]
}
```

```powershell
npm.cmd run evaluate:argument-relations -- --predictions path/to/predictions.json
```

如果预测使用了本地样本，评测时也须传相同 `--local-dir`。指纹绑定正文、端点、标签和标注元数据；任意变化后旧预测不能直接复用。命令不自动落盘报告，不读取 API 密钥，不调用模型，不更改生产开关。

## 指标与防止虚高

- 输出完整率、八类准确率、macro F1、逐类 P/R/F1、混淆矩阵。
- 支持/反对的精确率与召回要求极性正确；误建边率以非论证样本为分母。
- 同时报漏边、极性错误及证据不足类别表现。一律拒绝建边不可能通过有效边召回检查。
- 漏返回计错误，不转成正确的“证据不足”；重复 ID、非法标签、外来样本 ID、格式错误直接失败。
- 缺少源/目标证据句或引用不存在的 ID 单独报告。`contractEligible` 只表示结构契约完整，不表示语义关系有效，更不表示已生产准入。
- 无预测边时 precision 为 null，不记成 100%。没有模型预测文件时不报告模型成绩。
- 自测使用理想预测只验证计分公式，不计入模型实验结果。

### 首轮结果（开发集，不是上线验收）

两组输出覆盖均为 38/38，证据 ID 形状检查均无错误。

- 三类判定正确数：基线 21/38（55.3%），候选 37/38（97.4%）。
- 非论证样本误建边：基线 17/30，候选 1/30。

### 剩余错误与下一步

最重要的错误是 pair-028：输入要求“概括结论 → 具体数据”，模型解释却正确描述了“具体数据 → 概括结论”，最后仍输出 support。这说明**识别出相关论证不等于正确绑定给定方向**。下一阶段应将关系方向显式回填并独立核对，而不是依赖自然语言解释。

其余 5 个细分类别错误均未产生论证边：pair-009、pair-010 把展开说明判成证据不足；pair-012 将分工展开判成重述；local-001 将分歧元陈述判成无关；local-002 将命名判成重述。应分别评估篇章标签优先级与指代理解，不以“不建边正确”掩盖标签问题。

当前观察支持先改善任务拆分和判定策略，不支持宣称已测得模型能力上限。两组提示词同时改变标签空间和判定指导，因此不能把收益单独归因于八类标签数量。

下一阶段先加入显式方向检查与新的方向/限定对照样本，再扩充真实正例及独立留出评测。不得只针对本轮错误修改提示词、在同一开发集重跑后就声明泛化提升。生产策略继续不切换。

## 第三阶段：方向契约与新增样本实测

### 实现范围

新增 `src/services/argumentRelation/direction.ts` 与未注册的 v2 提示词。对 support/oppose 要求回填实际理由端、结论端、方向及前提完整性；程序检查它们与给定端点的 ID 集合一致。

- 明确逆向、方向不确定或前提缺失的候选降为 insufficient_evidence，不自动交换端点。
- 字段缺失、类型错误、外来 ID、端点不匹配属于协议失败，不伪装成正确拒答。
- 非论证标签不要求论证方向字段；合法反驳可能双向成立，不能统一拒绝所有反向样本。
- 模型原始预测、校验后预测、每条方向校验状态分别保存；分别统计过滤前后指标，防止隐藏误杀。

这是一致性校验，不是独立语义验证器：模型可以将错误的理由/结论角色填成与请求完全一致的字段，程序无法仅据这些字段识别其语义错误。实验提示词与字段均未接入生产服务或用户编辑器。

### 新样本与固定输入

保留原 38 条样本，新增 12 条方向挑战（6 组同正文正反端点，包括两方向都合法的反驳）和 3 条结合完整上下文复核的本地“问题/收益 → 改进建议”正例，共 53 条，其中有效论证标签 18 条、非论证标签 35 条。

本地正例依据源、目标、上下文三者的 hash 锁定，不根据历史置信度或 admission 自动判真。私有选择记录位于被忽略的 `data/rag-evaluation/argument-positive-selection-v1.json`，原文仍从原始本地审查快照读取，源码中不复制私人正文。

新增真实正例只有 3 条，且其中两条同文同上下文；仍与历史样本来自同一批文档。全部标注继续为 assistant_draft，**不是新的独立留出集**。三条正例表示作者的建议理由，不认证作者所述方法确实有效。

### 剩余问题与下一阶段

v2 剩余误建边为 pair-027（缺少个案前提）、dir-duration-r（差值反推起止数值）、local-005 与 local-006（仍把表格介绍当作实际表格证据）。后三类现象都说明：方向字段与输入一致，并不保证模型实际上按该方向推理或获得充分证据。

当前策略没有消除模型自证式误判。下一阶段应优先设计独立的证据—主张核验步骤，分别列明可用前提、缺失前提和 target 的限定，独立判断支持是否充分；同时继续扩充真实负例/正例及独立人工标注。不能靠继续叠加字段或提高置信度阈值宣布问题已解决。
