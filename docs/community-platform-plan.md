# LogiNote 资源共享与学友互助平台策划

更新日期：2026-10-25

文档状态：完整产品策划与后续实施依据。本文描述目标行为，不表示社区功能、云资源或应用已经建成上线。

## 一、产品定位与已确定边界

延续 LogiNote「静默生长」的主题，帮助用户找到资源、解决学习问题、建立互助关系、持续完成学习目标。核心闭环是：发现资源 → 加入自己的学习 → 与学友交流或共学 → 形成成果 → 自愿分享。

- 面向成年自主学习者，以大学生、职场学习者为主，交友围绕共同目标、兴趣和互助展开。
- 提供独立网站、桌面社区入口和 iOS／Android 原生应用。手机具备完整社区、资源阅读收藏、轻量计划与打卡；复杂图谱、场景练习和深度 AI 学习衔接桌面端。
- 完整功能一次上线，内部按依赖顺序开发验收。首发免费共享，资源纠错采用评论反馈与作者更新，不加入交易、多人实时编辑、音视频房间或模型密钥共享。
- 正式部署采用阿里云中国大陆 ECS。以万人注册、日活 500、百人同时在线为初始验证目标，实际开放容量由采购与压测决定。
- 月运营预算控制在 500 元以内，开发、签名和应用商店费用单列。CloudBase 资源点及其他云服务按量费用属于全阶段开发约束，功能设计、实现和验收均须考虑消耗控制，具体规则见 10.3.1 与 11.15。预算目标不是已获得的服务报价或承载保证。
- 全平台优先级：用户当前学习目标 → 用户主动关注 → 正在参与的交流 → 可选发现内容。不以信息消费时长、未读清零或互动数量作为核心体验目标。
- 2026-10-25 用户明确平台与终端边界：监督互助沿用现有关注和私聊，不增加独立搭子发布、匹配或结对关系；预约专注、学习计时与周回顾属于 LogiNote 终端，不在社区重建。平台可以在用户明确同意后展示终端用户画像中的学习统计，例如连续学习天数；这里的「活跃情况」指学习坚持度与活跃统计，不是在线状态或最近使用状态。具体内容、可见范围与撤销规则见 5.1.1。本决定替代本文此前相应的平台待办，不将移出平台的终端功能继续列为平台未完成项。
- 2026-10-25 用户确认跳过复杂共创：段落批注、修订建议比较／合并、贡献署名及独立共创工作流移出当前必做范围，已有群任务保留。评论与资源更新维持现状：原资源更新产生新版本并保留同一评论区；另发一份新资源使用新评论区，不自动迁移旧评论。不新增评论版本标记或按版本拆分讨论。本轮已接线 5.1.1 的终端学习画像统计授权展示并完成本地合成验证，真实用户核对及其余阶段验收仍按实际缺口继续，不因取消共创直接把阶段标为通过。
- 2026-10-25 用户确认资讯采用编辑审核方案，并支持普通用户投稿、管理员审核。统一「资讯与公告」入口，收录前沿资讯、官方文章和平台公告；自动收录只进入待审队列，经管理员确认后公开。首版先完成来源管理、人工编辑、投稿与审核闭环；AI 摘要及个性化日报保留为后续可选能力，默认关闭，不作为本轮或首发的必需验收项。具体范围见第八节及 11.8。

## 二、全平台设计规范

### 2.1 信息精简适用于所有页面

以下规则覆盖首页、资源市场、交流、共学、消息、个人主页、资讯、反馈与管理后台；与现有学习页面衔接的入口也采用相同原则。

1. 每页先明确用户当前要完成什么，突出主要内容及主要操作；次要功能按需出现。
2. 首屏不同时展开推荐、排行、统计、动态和任务等多个模块。不为填满页面加入无关内容，允许适当留白。
3. 同一信息有明确归属，其他页面只提供必要摘要和入口，不重复展示完整内容。
4. 内容优先围绕用户的关注、当前目标和正在参与的活动。可解释推荐原因，允许关闭推荐或屏蔽主题与来源。
5. 历史、统计、完整说明、高级筛选默认收起，但入口名称清晰，避免多层菜单和只能悬停才能发现的操作。
6. 不采用无限滚动、自动轮播或自动播放。用户阅读时不自动插入内容、重排列表、滚动页面或抢占焦点。
7. 返回后保留浏览位置、筛选条件、展开状态和草稿；小操作尽量在原处完成。
8. 访问范围、费用、失败原因及操作影响属于重要信息，不能为简洁而隐藏。

### 2.2 最少输入与流程

- 用户先表达目的，再由系统整理标题、分类和辅助标签。已有上下文可以继承，但不能自动附带未选择的私人资料。
- 普通操作直接执行，以局部状态和可撤销反馈代替「确定吗」等重复确认。
- 自动整理不依赖付费 AI 才能完成；解析或分类失败不阻止发布。
- 内容主题与个人兴趣分开：前者决定动态／资源筛选，后者用于公开资料与找同好。主题也不等于资源类型，数学内容可以是笔记、路线或练习。
- 学科方向用于整理和检索，具体话题允许交叉，如「线性代数、机器学习、论文共读」；「协作」是各主题下的参与方式，不作为排他的学科分类。
- 发布时可选最多三个话题，正文即可发布。引用作者主动选中的资源时带入其话题，群内短分享可继承群话题；原创内容不自动贴标签。不选话题时隐藏空标签，不显示「未分类」，不按作者兴趣猜测。
- 发布区只保留轻量「添加话题」入口，选择后才显示可移除话题。关键词建议仅在展开选择器后排序候选，不自动采用；草稿保留选择。多话题不改变访问权限、作者关注、个人兴趣或群成员关系。
- 草稿自动保存。失败保留内容和附件状态，重试不重复创建记录。
- 覆盖本地修改、不可恢复删除、严重管理处罚等保留与影响相称的保护；不为每次点击增加审批或向导。

### 2.3 主题与控件分工

沿用项目现有暖纸色、黛绿、字体、圆角、明暗主题与语义变量，复用适用的组件和焦点管理。避免另建风格割裂的社区界面。

- 侧边抽屉／浮窗：资源预览、问题详情、作者简介、工单详情；保留原页面位置，可进一步打开独立详情页。
- 小型浮层：发布范围、简短筛选、状态切换、更多操作；选择后直接生效。
- 居中弹窗：登录、不可恢复删除等确需集中注意力的操作，不用于普通成功提示。
- 折叠区域：完整来源、版本历史、详细群规、统计和高级设置。
- 页内展开：回复、补充说明和已有评论讨论。
- 滑块：仅用于连续数值，如个人学习时长目标；旁边显示数值并允许直接输入。分类、权限、日期不使用滑块。
- 悬停／聚焦提示：解释图标或缩略信息；重要功能也能通过点击、键盘和触屏访问。
- 局部反馈：按钮或内容旁显示「已收藏」「已完成」等状态，必要时附撤销；错误不自动消失。

同一时刻只保留一个主要抽屉或弹窗，不层层叠加。手机长详情使用全屏页面，短选项采用底部面板。关闭后恢复入口焦点与原位置，支持键盘操作及减少动态效果设置。

### 2.4 分类与话题的信息架构

根据用户对标签冗余的反馈，第十至十一轮已实现以下本机交互：取消固定学科导航、可选多话题、话题搜索与聚合、折叠市场筛选，以及话题词表维护。正式服务端词表、鉴权、审核与跨设备同步仍待后续阶段接入。

- 主导航按用户要做的事情组织：首页、关注、资源市场、共学。学科不再作为每页常驻的顶层按钮；首页公共交流保持简洁，关注页仍只显示主动关注的作者内容。
- 内容类型描述资源形态，如笔记、路线、练习、链接，由选定资源自动带入；仅在资源市场需要时展开筛选。它不与主题混为一个标签体系。
- 话题描述具体内容，如线性代数、机器学习、论文共读。允许一篇内容关联多个话题，最多三个；不要求每篇必选、不会因未填写阻止发布，不在普通动态中强调未分类。
- 发布区只提供轻量的「添加话题」可选入口，选中后才显示话题；通过入口搜索已有话题或直接新建话题，不同时要求填写学科、分类、兴趣和关键词。系统建议按需展开，作者可忽略，不能仅靠关键词把内容强制发布到某个领域。
- 首页移除人工智能／数学／阅读与写作的固定筛选排。用户从搜索或内容上主动添加的话题进入聚合内容；相关动态、资源与共学通过页内切换查看，避免同时堆满。资源市场默认少量内容和搜索，需要时展开类型／话题筛选。
- 公共交流的「筛选」融入栏目栏右侧，默认收起，使用低对比图标和文字，不在发布框下单独占一行。按关键词、话题和动态类型（全部／求助／资源分享／分享发现）组合过滤。关键词匹配原帖标题、正文、引用资源标题／摘要、作者和话题别名，多个空格分隔的关键词同时匹配；没有标签的内容仍可通过关键词找到。求助即使引用资源也归求助，不把分享形式与话题混淆。选择立即生效，无需跳转或确认。
- 收起筛选后显示当前条件摘要，保留清除入口；无结果时说明原因并允许查看全部。筛选先于分页，改变条件回到少量结果，主动加载更多；条件和已展开数量保存在本机原型存储，返回详情或刷新后保留，评论和发布草稿独立保留。不按个人兴趣自动筛选，不混入群内、已删除或错误公开引用的私密资源；关注页仍只按已关注作者显示。
- 人工智能、数学等大方向可用于后台索引与话题关系；一条话题可以关联多个方向，不把交叉学习硬塞进唯一学科。「阅读与写作」可以覆盖方法类话题，「协作」则作为跨主题的参与方式。
- 个人兴趣为用户主动填写的公开自我介绍，不自动给其所有帖子贴标签；共学群为实际成员与协作空间，一个话题可关联多个群，一个群可讨论多个话题，关注话题不自动加入群。
- 话题词表使用稳定 ID 管理名称、简介、别名和相关方向。优先复用已有话题，管理员可合并同义项、调整关系、限制滥用；合并保留内容与引用。话题建议、新建或人工维护不阻塞当前正文发布；内容违规独立判断，不能因为分类错误直接处罚作者。

参考：[Reddit 帖子分类标记](https://support.reddithelp.com/hc/en-us/articles/15484545678996-Post-Flair)将社区内分类与用户／管理权限结合；[Discourse 分类与标签说明](https://blog.discourse.org/2017/10/its-time-we-talked-about-tags/)区分少量分类和可跨分类的多标签。此处取其组织原则，页面布局与静默提醒规则仍按本项目要求执行。

## 三、页面布局与默认内容

### 3.0 真实数据归属与访问范围（2026-10-24 补充）

账号认证成功只证明身份，不能据此把原型内容变成真实用户数据。服务模式必须使用独立服务端数据，不读取、迁移或认领本机演示人物、发布、收藏、会话和群成员关系；未接入的能力如实显示准备状态，接口失败不能降级显示演示内容。界面布局继续复用已确认的设计。

- **公开内容**：用户明确发布为公开的动态、求助、资源及其公开讨论；公开昵称、头像、一句介绍和主动填写的兴趣；公开群名称和介绍；已审核发布的资讯、用户投稿、官方文章和公告。资讯稿件的草稿、待审版本及审核意见只供作者与有权审核的管理员读取，不能混入公开详情、搜索、计数、附件或分享预览。公开页面不输出邮箱、内部角色、CloudBase subject、令牌、私人学习数据或消息。公开发布才进入公共索引。
- **本人专属**：邮箱和账号安全资料，收藏、关注列表、我的学习清单与进度、草稿、个人筛选与提醒设置，以及本人提交的反馈。关注关系决定自己的关注流，不默认公开关注名单；收藏公开资源不等于公开收藏记录。学习状态从本人的空记录开始，不继承资源作者的掌握度或学习进度。本地笔记、终端目标和学习画像不随登录上传。
- **限定共享**：群内动态、资源、讨论和群聊天仅当前有效成员可读；私信仅会话参与者可读。群主和管理员能管理本群成员与群内容，不能查看成员私信、私人收藏或私人学习记录。平台运营只按治理授权查看相关投诉与封存证据，不因后台身份获得普通私密内容浏览入口。
- **反馈和管理数据**：投诉提交人查看自己的工单；运营人员按真实角色、管理验证和案件权限处理。被投诉者只看到允许告知的结论及申诉信息，不直接取得投诉人邮箱或全部证据。处置和敏感查看保留审计。

个人页的“我的分享”从当前账号的真实发布读取，“收藏”从当前账号收藏关系读取，“共学”从当前账号有效成员关系读取；不从公共列表猜测拥有者。作者页只展示允许公开的资料和公开发布，不复用“我的”页面的私人集合。资源正文与“我是否收藏／加入学习／完成学习”分别存储，公共资源可被多账号引用，每个账号的个人状态独立。

所有请求的操作者由服务端 Cookie 会话确定，拒绝由客户端指定 ownerId、accountId 或角色来认领他人数据。列表、搜索、分页、计数、详情、评论、引用和下载都校验相同访问范围；先按权限过滤再分页。私密资源不能通过公开帖、引用卡片、话题或转发扩大访问范围。退出或切换账号时清除旧账号的页面缓存和请求，迟到响应不能填回新账号页面；不把临时隐藏当作权限控制。

本轮默认先实现公开交流／资源与个人关系的真实闭环，并以两个独立账号交叉验证。群和私信按各自阶段接入前，不继续显示合成会话或冒充已加入群。验收需证明 A 的私人收藏、学习清单、草稿和设置不出现在 B；A 的公开发布能被 B 查看，未公开和群内发布不能混入公共入口。

实现直接采用成熟社区的内容与关系分离方式：正文保存一份，收藏、加入学习、关注分别保存“账号＋目标”的关系；读取公共内容时才附上当前用户自己的状态和允许公开的聚合人数。参考 Mastodon 官方的 [Status 数据模型](https://docs.joinmastodon.org/entities/Status/) 和 [当前用户收藏接口](https://docs.joinmastodon.org/methods/bookmarks/)，借鉴其公开内容与用户状态分离的原则。关注名单是否公开等产品取舍仍按本项目隐私要求执行。

2026-10-24 本机进展：公开动态、资源正文、搜索／话题、作者页、关注、回应和本人数据已接通真实服务。阶段 3 收敛为网页／视频链接、资料文件与单篇只读快照；多篇／项目打包及结构化导入暂停，保留历史实验代码和证据，不作为当前验收结论。最新范围以 4.1—4.4.1 与 11.5 为准；不代表正式云端上线通过。

### 3.1 导航结构

网站采用紧凑导航加中央主内容，不设置默认常驻的右侧推荐栏。根据交互原型反馈，主导航调整为「首页、关注、资源市场、共学」。首页是公共区域，可以看到尚未关注作者的公开分享；关注页只显示已关注作者的公开动态，不用公共推荐填充空白。个人主页从头像进入，作者主页从动态、资源署名或「找同好」进入，不再设置含义模糊的「学友」主导航。顶部保留搜索、中性消息入口和头像；「资讯与公告」为首页的轻量入口，不新增顶层导航。

桌面端在现有导航增加「社区」，社区内部采用相同结构，保留本地学习首页的核心地位。手机底部为「市场、交流、共学、消息、我的」，恢复上次位置，首次进入「我的」。

### 3.2 各页面的主次关系

- 首页：公共交流、找同好和我的参与按页内切换，默认少量公开分享，不设置固定学科标签排；可以直接关注陌生作者，不要求先加好友。人物发现不与全部动态同时铺开。
- 关注：仅显示自己关注的作者，支持取消和管理关注；没有内容时引导去公共区域，不混入陌生作者推荐。话题发现通过搜索或内容上的话题进入，不混入作者关注流。

### 4.1.1 现有项目资源与网页能力的对应

本地存在某种模型或导出器，不代表社区应直接上传完整对象。当前分享适配只读取选定单篇的标题、正文和必要图片，不沿子级、双向链接或引用扩展范围；关联的私密笔记正文、个人画像、掌握度、复习、排期、令牌、本地路径和元数据不公开。

网页原创图文可编辑 Markdown、插图和可选介绍；文件类由作者编辑分享标题／用途说明，文件名、大小和版本自动读取；链接由用户粘贴，不要求再填写来源等重复字段。单篇本地快照在发布面板只读预览，修改正文应回到原笔记再生成快照。正文支持列表、表格、代码与公式，不执行代码、原始 HTML 或远程图片请求。

真实附件每份资源共最多 8 个、单文件最多 100 MB；快照图片最多 7 张、单张最多 2 MB。PDF 使用受控页面绘制预览，文字／Markdown 使用同一正文渲染器；其他格式按实际支持提供文件保存，不能仅因扩展名被识别就显示可预览／已可检索。

2026-10-25 容量与粘贴交互调整：头像原图支持 10 MB，选择后自动裁切、去除元数据并压缩保存；资料文件支持 100 MB，网页、接口、数据库约束与桌面分享／接收共用同一上限，每账号累计上限调整为 1 GB。继续保留全站实际存储与下载额度。增加新数据库迁移，不修改已执行的旧迁移或删除既有文件。

公共动态、群学习记录、求助、评论和资源正文共用图片粘贴能力：Ctrl+V 或选择图片后直接显示缩略图，允许移除与失败重试，不要求填写图片说明，也不把图片引用语法显示在输入框。正文仍可继续编辑，文本末尾空格与换行保持原样。粘贴原图最多 10 MB，自动压缩为单张不超过 2 MB 的正文图片，发文／评论每条最多 8 张，资源正文最多 7 张；资料主文件／附件的 100 MB 上限独立保留。群／本人草稿保留图片，发布与文件归属在同一事务中提交；评论图片随原帖、群图片随成员权限校验，撤回原帖或退出群后，旧下载授权也无法继续访问。私信与群聊沿用现有截图／图片／表情包输入。验收记录见 容量与图片粘贴检查。

保存人数来自服务端账号关系去重，不代表已学习或掌握；收藏、接收排队、文件入库和索引可用分别记录。新账号不继承示例人物或示例数据。

### 4.4.1 网页保存、云端待同步与桌面接收

## 五、个人状态、学友交流与协作

### 5.1 个人展示

个人资料的手工编辑只保留昵称、头像、介绍与兴趣标签。头像在「编辑资料 → 更换头像」选择图片，支持替换和恢复默认；兴趣标签在同一面板选择或添加，主页提供「编辑兴趣」入口。不设「自愿公开状态」、手填在线状态或可答疑状态字段。用户授权后可只读展示终端学习画像中的选定统计，不要求用户重复填写数值。

当前目标后续从 LogiNote 客户端读取，不在社区手工重复填写。预留只读目标接口，未接入时不展示演示目标冒充同步结果；正式接入须通过账号授权，仅返回选定目标，不自动读取或上传私人笔记、画像与完整日程。介绍与兴趣、学习目标分别设置可见范围，目标默认仅自己。原型当前只返回 not_configured。

本人发布的公开或群内动态，在右上角「… → 删除动态」直接删除，原处移除并提供 8 秒撤销，不加确认弹窗。删除同步影响首页、群页和本人主页的对应动态；资源引用动态删除后，市场原资源与已发送的引用卡片保留，资源下架另行处理。生产阶段由服务端校验作者身份，并实现软删除及撤销期限；原型仅保存在本机。

能力画像、认知风格、薄弱点、原始语音、私人复盘和完整日程保持私密，不用于公开社交排名。用户可主动整理成果，但不能把 AI 推断的个人特征直接公布。

头像交互统一为：鼠标停留约 0.4 秒显示非模态资料卡，快速划过不弹出；卡片展示公开昵称、简介、兴趣与关注入口，授权范围允许时可附一行学习画像摘要，例如连续学习天数与本月活跃天数，不展示未授权指标、在线状态或整套画像图表。允许移入卡片操作，移开后收起，滚动或跳页关闭，同一时刻只显示一张。点头像直接进入该用户主页，手机轻触直接进入，不增加先打开卡片的步骤。会话列表点击头像查看主页，点击会话文字区域切换聊天。关注入口集中在头像资料卡与个人主页，动态右上角不再重复显示关注按钮。键盘聚焦可预览，Escape 收起，Enter 进入主页。

### 5.1.1 经同意展示终端学习画像统计（已接线，真实使用待验收）

- **来源与含义**：读取已绑定同一社区账号的 LogiNote 终端计算的学习画像统计。现有终端画像页已经提供「连续学习天数」「本月活跃天数」「日均学习分钟数」，由 `ProfileOverviewView`／`homepageViewModel` 读取已有学习轨迹与统计口径；平台复用这些结果，不另做签到计数或按发帖、登录、设备心跳推算学习天数。当前设备 `last_seen_at` 仅供设备管理，不能作为这组统计的数据源。累计学习天数等新增指标须先在终端明确来源与计算口径，不宣称已经存在。
- **授权入口**：在个人主页「编辑资料 → 学习统计」折叠项提供展示开关，默认关闭，不新增独立设置页。在同一处说明并选择展示哪些指标、向谁展示，由本人主动开启；沿用公开／指定共学群等已有访问范围。关注、互关、接受私信、入群或绑定桌面接收设备均不自动开启画像授权，群主不能代开。当前目标仍使用单独授权，不随统计一并公开。
- **页面表现**：个人主页在介绍下方用一行轻量数字展示本人选择的指标：连续学习、本月活跃、日均学习（最多三个），数字稍大、单位与标签弱化，以细分隔线区分；沿用米白、深绿与衬线字体，不增加大卡片、图表或排行榜。未选择的指标不占位，手机端压缩间距并允许必要换行。头像资料卡和有权限的群成员资料只显示一行摘要，不把整套画像图表、日历或明细铺到每个页面。没有授权不展示；指标读取失败显示未更新或不可用，不填演示数字，也不把未知值写成 0 天。
- **最小数据**：只同步已选指标的聚合值，以及统计截止日、时区、计算口径版本和更新时间等必要校验信息，不上传原始轨迹来让平台重算。笔记正文、文件名、本地路径、完整日程、逐日明细、私人复盘及未选择的画像维度不随统计上传；能力评估、认知风格与薄弱点仍按既定私密规则处理。预约专注和周回顾继续在终端完成，用户可通过普通分享主动发布选定成果。
- **同步与成本**：复用账号绑定与授权通道，新增学习统计用途的明确校验。已授权指标变化、终端完成一次统计或日期切换需要重新计算时，合并、节流上传小型快照；不为展示学习天数建立高频心跳或逐次上游认证。网页在现有资料读取中附带允许的统计，不为每个头像单独轮询。
- **统计一致性与新鲜度**：沿用终端的有效学习日、连续天数、统计周期及日界线口径，不以平台登录续天数，也不在终端离线时擅自增加或清零。快照过期或统计日期不是当前日期时，应明确「截至某日」或待更新，不能把旧数值冒充今日结果。无数据、读取失败和真实的 0 值分别处理；多设备／知识库不能简单相加造成重复计数，来源归属在终端接线时验证。
- **撤销与隔离**：本人可随时关闭、取消某个指标或缩小范围；服务端立即停止向无权限查看者返回相应统计，终端停止后续上报。退出指定群、设备解绑、账号切换和权限撤销须重新校验；缓存不能跨账号或越过授权有效期。图片／资料接收授权不等于画像统计授权。
- **验收**：默认关闭、逐项选择、公开／群内范围、陌生人和退群访问、撤销与缓存失效、断网与旧快照、跨日及不同时区、账号和知识库切换均须覆盖；平台与同一来源终端在同一截止日显示一致，不上传私人明细、不因登录或发帖增加学习天数。分别记录本地合成验证和真实终端接线结果。2026-10-25 已完成 API、PostgreSQL、真实 CommunityHost 与轨迹文件读取、个人主页／资料卡和逐项授权设置的本地接线。隔离合成数据覆盖默认关闭、字段白名单、来源／账号／知识库隔离、群成员退出、撤销、设备重新绑定、受限账号撤销、旧快照日期、日界线／夏令时以及统计失败不阻断接收；桌面与 375 px 手机布局已检查。用户真实终端须重启以加载新代码，再核对本人统计，尚不记作公网或真实用户统计验收通过。证据见 学习统计接线记录。

### 5.2 求助与讨论

求助只要求一个输入框和「发布求助」按钮，占位建议为：「我在学……，这里没弄懂……可以贴题目、截图，或者直接说说你的困惑。」占位建议不作为正文提交。

不强制填写标题、背景、难度、学科和已尝试方法。标题可从首句生成，主题优先继承当前上下文；识别失败不阻止发布，缺失信息通过自然追问补充。图片、链接和笔记引用由用户主动添加。

动态下方采用常规评论区：默认预览最近 2 条一级评论，每条最多预览 1 条回复；点「回应」原地展开输入框，点某条评论的「回复」标明被回复人，支持继续回复他人的回复。发表后原处显示，不跳页、不弹成功窗。不增加「回复某某／取消回复」独立提示行；空输入框提示回复对象，提交按钮显示「回复某某」，点原帖「回应」切回评论原帖。评论及草稿按原帖 ID 隔离，同一资源被不同动态引用时也不混用评论。

「查看全部讨论」在原帖下原地展开，可收起并保留输入草稿；已经全部显示的评论不再重复放展开入口。独立详情入口放在动态右上角「…」旁边，使用轻量图标，标题不再承担跳转操作。详情顶部保留同一原帖的作者、正文、资源引用与访问范围，下方按一级评论和楼内回复展示完整讨论，较长楼层主动展开，更多评论主动加载。未知或已删除的原帖显示明确结果，不退回其他示例帖子；退出群后不再显示群内原帖及评论。动态下的「分享资源」使用锚定轻浮层，选择目标、填写可选留言并提交后留在原页面；「查看分享」是可选操作。

支持追问、引用、公式、代码、图片及采纳多个互补回答。资源问题通过现有评论提出，作者可回复说明并自行修改、更新原资源，保留资源版本和同一评论区；复杂共创不作为当前必做项。

### 5.3 学友与互助

- 作者发现属于公共区域：公开动态、资源署名和「找同好」均可进入作者主页；按公开昵称、兴趣与已授权目标搜索。关注是单向订阅，一步完成、无需对方批准；关注与现有私聊承接联系、鼓励和监督互助，不额外建立搭子关系。关注不自动授权读取终端状态，连续私信仍沿用现有申请／接受规则。
- 不使用一个独立「学友」主导航直接进入某个示例人物。管理关注从关注页进入，具体作者主页始终显示当前选中的人。

- 用户可通过普通动态表达目标与互助意向，其他人从现有发现、关注和私信入口联系；不增加独立搭子发布、自动匹配、结对申请或搭子管理页面。
- 学友发现只使用本人主动填写或授权公开的资料，不从私人认知数据推断互助关系，不因终端活跃度新增社交推荐排名。
- 支持关注／取消关注、私信申请／接受、拉黑和举报。陌生人先发送一条申请，接受后开启对话，默认每天最多向三人申请。
- 私信与群聊支持文字、截图、PNG／JPG／GIF／WebP、常用表情和资源卡片；图片选择、粘贴、拖入共用发送前预览，可移除，可点击放大。会话草稿独立保存，不把上一会话的图片或文字带入另一人。GIF／WebP 保留原动画；阶段 1 只保存本机图片，尚未上传或实际投递。
- 已关注作者的悬停资料卡提供私信入口。私信更多菜单支持删除会话、拉黑／解除拉黑及举报；删除会话在本机阶段只移出列表，消息保留并可撤销、重新发起。拉黑时禁用私信发送和资源卡片直发，允许保留、查看自己的历史与草稿；真实阻止对方投递、跨设备同步与关系权限在服务端实现。
- 协作沿用已有群任务、讨论、资源与成果分享，支持论文精读、读书计划和小项目的交流；不另建共创任务、修改审批或贡献管理系统。
- 鼓励有效答疑、被采用资源和持续协作，不以在线时长、发帖量、未读清零或打卡排名驱动参与。

## 六、共学监督群

建群只要求群名，一句目标以占位提示建议、允许后补。周期、人数、时间、入群方式与群规使用可见默认值，在「更多设置」调整。默认每群 50 人，每人最多创建三个、加入十个群，后台可调整。

建群后进入自己的新群，不填充其他群的帖子或学习记录。开放群点击加入即成为成员；申请群提交后明确显示待处理，群主批准前不展示群内内容。邀请使用只包含公开群介绍的卡片，接收者仍按群设置加入。创建、搜索、申请、批准、退出和成员移除需在真实服务阶段分别验证。

- 共同计划：群目标拆为周任务，成员选择自己的任务和投入，不要求与所有成员保持相同步调。
- 学习记录：直接分享真实收获、阶段成果或困难，默认只显示正文框和一排小工具。标题、Markdown 格式、链接与话题按需展开，不铺成完整表单，不设置独立的空白打卡按钮。引用资源采用粘贴链接：先在市场或群资源页找到目标，再复制链接回到分享框；不在编辑器列出全部资源。本站资源链接解析为原资源卡片并标明市场／本群，外部 HTTP／HTTPS URL 插入正文为可打开链接，不自动抓取外站。当前群只引用市场公开资源与本群可见资源，公开动态不能引用群内资源，不自动读取终端笔记；未知或越权链接保留草稿并就地说明。
- 监督互助：成员使用已有关注、私聊与群交流相互鼓励、提醒和答疑，不新增搭子角色、绑定关系或监督管理流程。用户是否展示连续学习天数等画像统计按 5.1.1 单独授权，提醒仍由接收者主动设置。
- 终端能力衔接：预约专注、计时和结束复盘在 LogiNote 终端完成，社区不提供重复的预约、计时或复盘页面；经本人同意，只读展示选定的学习画像统计。
- 鼓励求助：提供鼓励回应、困难求助和待答问题清单，不用公开羞辱或连续打卡施压。
- 资源与答疑：按任务、主题和周次归档，聊天中的有效内容可主动转存。
- 成果分享：周回顾由终端生成和保存。成员如愿意公开成果，沿用普通动态或资源分享主动选择内容与范围，平台不另行收集私人记录、自动生成群周报或发布周回顾。

群主和群管理员管理入群、公告、群资源、群内禁言及移出成员，平台级处罚由后台执行。群主离开前转让权限，否则进入只读归档。群组管理责任与平台责任分别落实。

### 6.1 一个群的主要作用和唯一交流入口

共学群围绕共同目标持续学习：组织学习安排、交流困难与解答、保存资料、留下成果及互相鼓励。群的价值不以消息量衡量。「今天」保留原来的问题卡片与学习记录布局；「交流」是同一份群对话，置顶话题只放在会话室内部顶部；「资源」沉淀资料；「成员」处理参与关系，后二者不重复显示置顶话题。消息中心的共学群仅提供列表和进入该群交流的入口，兼容旧消息链接，不另建一套聊天记录或输入框。

### 6.2 群讨论话题与参与方式

目标规则：任何成员可以发起具体学习讨论，群主或管理员将值得持续探讨的原帖置顶为群讨论话题；保留真实发起人和原帖，不默认每天用 AI 生成问题。作者可以补充说明，整理为资源；不把管理员替别人创作的问题标成该成员原创。它是可持续交流的讨论帖，不是每日打卡题，也不与资源分类话题混同。

「今天」的问题卡片保留原来的图标、标题与说明，主按钮统一为「进入讨论」：原地切换到该群「交流」，不跳到学习记录分享框，也不另开评论抽屉。话题成为现有群会话的讨论上下文，置顶条在会话框内部保留，展开可看说明与发起人；从今天进入时默认展开。文字、截图、表情及资源继续用同一个消息框，消息仍写入同一份群会话，记录发言当时的话题 ID，不逐条重复话题标签。群消息滚动时话题仍在消息框顶部，其他栏目不显示此条。

当前原型沿用线性代数群的演示原帖，新建群不自动生成置顶问题。旧回答和楼内回复作为此前话题讨论显示在同一个会话室，保留作者与回复对象，原数据不复制、不删除；旧话题草稿仅在群消息草稿没有正文和图片时迁入现有消息框，已有文字或图片时不自动合并，旧草稿继续保存。普通学习记录和群会话草稿保持分开；旧讨论详情链接仍可读取历史评论。真实的成员发起与群主／管理员置顶管理服务在账号及权限接入后实现。

### 6.3 群管理责任与权限

群主默认为建群者，负责群目标与群规、管理员任免及群主转让；管理员由群主任命，协助处理入群申请、公告、资源整理、问题置顶、群内广告和骚扰。成员可以分享、发起问题、回答和举报，不能任意删除别人的正常成果。群内移除、禁言、移出成员等动作要有依据、范围、期限与审计记录；有争议时可向平台申诉。平台运营处理跨群违规与平台级处罚，群管理员不能查看无关私信或自动开启成员提醒。

当前只存有演示创建人、加入状态和申请记录；管理员任命、真实申请审核、置顶、处罚、转让、审计与申诉需要账号和服务端权限接入，不能仅以前端按钮宣称完成。


## 七、默认安静的消息机制

### 7.1 全局默认

用户主动查看是默认方式，减少消息对专注的争夺。

- 全站不显示常驻红点、未读数字角标，不闪烁、不跳动，不在网页标题或应用图标提示未读。
- 点赞、收藏、关注、资源更新和普通资讯只在相关页面合并记录，不逐条制造待办。
- 私信、回复和群内 @ 默认进入消息中心，不弹窗、不发声、不振动、不触发系统推送。
- 消息入口使用中性图标和文字，不随普通新消息改变视觉强度。当前阅读的会话可自然显示新消息，读历史时不自动滚到底部。
- 用户可为指定学友、群和活动主动开启提醒，选择渠道、频率、安静时段，随时关闭；不强制开启系统通知权限。
- 群任务、私信和互助互动提醒默认关闭，仅按用户主动设置生效；学习画像统计更新不触发通知。
- 收藏、提交、任务完成等在按钮或内容旁显示结果，避免连续成功提示条；失败留在操作处并可重试。

### 7.2 专注学习期间

- 暂停全部普通社区提醒，包括此前开启的普通提醒。
- 账号级专注状态供多设备遵循，发送提醒前重新检查，避免只在前端隐藏而手机仍推送。
- 被暂停的普通提醒不在退出专注后集中补发；消息和事项保留原位置，由用户主动查看。
- 不在退出学习后自动弹出消息汇总，不播放提示声或展示积压数量。
- 学习计时结束等用户主动设置的学习提醒可以按约定生效。
- 保存失败在当前学习界面明确反馈；正在发生的严重账号安全风险可采用必要提示。普通 @、公告或催促不得升级为紧急提醒。

### 7.3 消息中心

按「待回应」「其他消息」整理，可进入具体会话与对象，不要求清空消息，不以未读数量评价参与度。相同资源、讨论或活动的普通更新合并，去重并避免跨设备重复提醒。待回应表示方便处理的事项，不代表用户有强制回复义务。

## 八、资讯与公告、用户投稿及可选 AI 日报

2026-10-25 本地接入：用户富文本投稿、官方文章／公告、人工审核与公开阅读已接通，并补齐固定 RSS 来源、有限调度、持久去重及治理工单。六个原站通过生产传输取得 53 条待审候选，审核前公开内容和提醒均为零，全部在隔离数据库验收；真实业务库的八个来源仍默认关闭。入口、预算和操作说明见 阶段 6 记录 与 真实采集证据。AI 摘要和日报仍为后续可选，不影响资讯与公告独立使用；实际管理员运营演练与阿里云公网验收单独保留。

### 8.1 内容来源与栏目

- **前沿资讯**：论文与研究进展、技术发布、开源工具、课程、方法和学习活动。管理员配置允许收录的机构官网、论文原站、项目发布页及 RSS／API，系统按配置收录到待审队列；管理员也可手工添加原文链接和介绍。不绕过付费墙，不默认转载全文。
- **用户投稿**：普通用户提交原创文章、学习方法、专题介绍，或推荐值得收录的原文链接。与自动收录进入同一审核体系，通过后在资讯栏目展示，保留真实投稿者署名及原文作者／来源；「审核通过」不改成「官方原创」。
- **官方文章与平台公告**：由平台管理员撰写、编辑和发布，包括使用教程、专题说明、版本更新、维护与规则调整。普通用户不能将投稿标为官方文章或公告，群管理员身份不赋予平台资讯审核权限。首版不另建编辑岗位；以后如需授权编辑，再明确其可操作范围。

每条公开内容只显示阅读所需的标题、简短介绍、署名／来源和日期，正文内区分研究结果、预印本、产品发布和个人观点。原文链接自动显示真实来源域名；来源、原文日期和平台发布日期分开保存，不把收录日期冒充原文日期。主题沿用已有话题，可选且可交叉，不新增必填的学科表单。

### 8.2 轻量投稿与本人管理

流程为「写正文或粘贴链接 → 提交审核」。复用现有正文编辑、图片粘贴、草稿和外链提示；标题、介绍、话题按需补充，标题可从首行生成，链接元数据读取失败仍可提交，不要求作者重复填写来源域名、发布人、账号等系统已有信息。不自动上传终端私人笔记、学习画像或关联资料。

投稿、官方文章和公告共用可视化富文本编辑器，沿用项目已使用的开源 MDXEditor。支持一至三级标题、加粗、斜体、列表、引用、链接、表格、分隔线和正文插图；可以选择图片、粘贴截图或拖入图片，在编辑和预览中直接看到图文排版。正文保存为 Markdown，阅读端使用同一格式渲染。原文链接和话题收进「更多」，保留自动草稿，不增加发布确认页。图片通过现有账号授权上传，待审图片不对外公开；正文不直接加载未经授权的远程图片。

- 资讯页提供一个「投稿」入口；编辑器内明确按钮为「提交审核」，避免误以为已经公开。提交成功在原处显示待审核状态，不增加第二次确认。
- 本人可从个人主页的「我的分享」按需筛选投稿，查看草稿、待审核、退回修改、不予采用和已发布状态，以及管理员给出的原因；不另设常驻投稿看板。失败保留正文和附件，重试不重复入队。
- 待审稿只供作者与有权审核的管理员读取。作者可以撤回，修改后重新提交；重新提交产生新的待审版本，旧版本的审核结果不能发布新版本。编辑中的变化不会覆盖管理员正在核对的固定版本。
- 已发布稿件修改后重新审核，审核期间继续展示上一公开版本；审核通过才更新原页面，保留原链接、署名和评论。作者主动撤回或管理员下架后，公共列表、搜索、正文、评论及附件访问按同一状态收回；审核记录保留。另发一篇使用独立页面和评论区。
- 退回修改或不予采用要说明原因，本身不构成账号违规处罚。用户可以补充说明后重投；涉及违规时另按第九节的事实、处置和申诉流程处理。

### 8.3 管理员审核与自动收录

三条内容路径分别为：自动来源收录／管理员手工收录 → 去重提示与来源核对 → 待审核 → 发布；用户投稿 → 待审核 → 发布、退回修改或不予采用；管理员撰写官方文章／公告 → 草稿预览 → 发布。自动摘要、来源白名单或主题匹配都不能替代人工发布决定。

- 后台复用待审核内容队列，按需筛选自动收录与用户投稿。列表仅显示标题、投稿者或来源、提交时间和状态；审核详情查看固定版本正文、图片、原文链接及已有审核记录。
- 审核核对相关性、来源与署名、重复内容、事实表述和明显风险。可以补充编辑介绍或选择话题，保留操作与修改记录；需要改写投稿正文或核心观点时退回作者修改，不在保留其署名的同时静默改写。重复来源仅提示合并或不予采用，不自动抹去投稿者署名。
- 管理员可通过并发布、退回修改、不予采用、下架已发布内容及按审核规则恢复；理由、操作者、时间和被审核版本可追溯。普通用户不能自审、查看他人待审稿或执行发布，群管理员不能越权操作。
- 审核动作校验稿件当前版本与状态。两个管理员同时处理、作者撤回或重新提交、网络重试时，不重复发布，不用过期审核覆盖新稿；保留必要的管理记录，不为投稿者增加多步确认。
- 自动收录只处理配置允许的来源，不根据用户随意提交的 URL 发起服务端抓取。未开启来源不运行抓取；开启后按设定频率分批处理，复用来源条目与已有记录，失败有次数、并发和费用边界。来源无法读取时保留原因，允许管理员手工收录，不编造正文或摘要。

### 8.4 前台阅读与安静反馈

「资讯与公告」共用一个页面，采用「资讯」「官方」两个页签，默认显示少量条目，主动查看更多。搜索、话题、来源和内容类型筛选默认收起；不设置推荐侧栏、排行、自动轮播或每天必须查看的入口。官方栏目用轻量类型标识区分文章与公告，普通公告不触发强提醒。

详情显示文章正文或编辑介绍、署名、原文出处与日期，复用已有收藏、评论和标题加链接的分享方式。外部原文遵循已有离站提示；投稿通过、退回、发布和普通公告不新增红点、声音、弹窗或系统推送。本人主动查看投稿状态与审核原因。资讯被收录不自动再复制一条首页动态，作者可自行分享该页面链接；保存到资料库或发起群讨论同样由用户主动操作，不自动创建任务或改写终端计划。

### 8.5 后续可选：AI 摘要与个性化日报

AI 日报指由 AI 辅助整理已审核资讯，再按用户主动选择的话题组成少量精选；内容可以涵盖数学、阅读、人工智能等领域，不读取私人笔记、私信、终端学习回顾或学习明细。它不代表目前已具备自动搜索或生成能力。

此能力默认关闭，启用范围与服务额度另行确认后再实施；本轮和首发不依赖它完成。以后启用时继续遵守以下约束：

- 仅从已审核公开的内容组装，不把未审稿、已撤回或已下架内容加入日报。摘要有原文链接、内容日期和 AI 标识，不冒充作者原文或官方结论；原文或审核状态变化后更新或移除对应摘要。
- 每人每天最多一份、五条，默认展开前三条，其余主动查看。同一来源摘要全站复用，默认每天最多生成 20 条新摘要，日报按用户选定话题筛选组合。
- 日报安静保存，不推送、不加红点，不用无关内容补满。支持关闭个性化、按时间查看、屏蔽来源和不感兴趣，不占首版独立页面或导航位置。
- 生成失败保留人工介绍或来源卡片，说明状态，不编造摘要；额度耗尽停止新增调用。纠错能更新相关摘要，已有公开内容不因 AI 不可用而无法阅读。

## 九、反馈、投诉、违规处置与后台

### 9.1 用户入口与工单闭环

资源、帖子、评论、已发布资讯／投稿／官方文章／公告、账号、群和消息均可举报；帮助中心支持问题反馈、建议、版权投诉和处罚申诉。自动关联对象，选择原因或填写一句说明即可提交；特殊案件按需补充证明，不先要求填写冗长表单。私信举报由举报者选择提交相关上下文。

流程：提交 → 自动回执 → 分级去重 → 核实或补充材料 → 处置 → 反馈 → 申诉或关闭。工单展示编号、状态及下一次反馈时间。普通结果进入消息中心，不打断学习。

运营目标为：高危事件立即进入隔离与紧急队列，普通投诉两工作日内首次人工反馈，建议五工作日内分类反馈。上述是运营目标，不是法定时限或无人值守的处理保证。

### 9.2 内容如何判断和处置

- 诈骗、隐私泄露、暴力威胁、恶意附件等：先限制传播，保留必要证据，人工核实后处理，涉及法定报告义务时执行相应流程。
- 版权与授权争议：暂停争议分发，核验权利证明及申辩材料后恢复、整改或下架。
- 骚扰、广告、灌水、刷量与垃圾内容：按事实及程度移除内容或限制相关功能。
- 知识错误、学术分歧：优先纠错、补来源、标争议，不因观点不同或回答错误直接处罚账号。

### 9.3 用户处罚与申诉

按事实与影响采取提醒整改、限制发布或私信、临时禁言、取消建群资格、长期封禁。严重情况可直接限制，无须机械逐级升级；自动系统可隔离风险，永久处罚必须人工确认。

每次处罚记录事实、证据、规则条款、范围、期限、操作者和申诉入口。申诉改判后恢复权限与内容，纠正违规记录。恶意举报需有证据，投诉未成立本身不算恶意举报。

投诉成立时反馈必要处置结果，不暴露举报者及第三方隐私；证据不足说明需补充什么，不成立说明理由并提供申诉。建议分为已采纳、待评估、重复、暂不采纳，并解释原因；采纳后关联版本，在工单中反馈。

### 9.4 管理者使用方式

独立后台采用多因素认证，包含总览、内容、用户、群、工单、申诉、建议、资讯与投稿审核、资讯来源、配置、费用和审计。资讯稿件复用待审核内容队列，来源配置、官方草稿和历史按需进入，不新增另一套重复工单。投稿审核与违规处罚分别记录；收录决定本身不产生账号处罚。

首页只突出紧急风险、待处理举报、待审核内容、费用或服务异常。列表仅显示对象摘要、原因、风险和等待时长，打开详情抽屉后看证据与历史，统计报表另行进入，不把后台做成满屏仪表盘。

自动系统负责初筛、限速、隔离、重复合并和排序，个人运营集中处理有争议的队列。管理者可单独订阅重大安全或服务故障提醒，与用户社区的默认安静规则分开配置，避免把所有待办都升级为警报。

群管理员只能处理本群事务，未来客服和审核员按岗位授权。私密证据访问、导出和处罚均记录审计；不能因为管理员身份无条件浏览私人消息。账号注销、内容撤回与证据保留按适用规则处理，保留范围和期限在正式隐私规则中说明。

## 十、系统、部署与费用控制

### 10.1 现有项目衔接

项目已有计划、笔记、教材、资料、场景、复习与画像，且将个人状态单独存储。复用学习能力，新增社区账号、云端服务与治理系统，不把个人知识库整体改为自动云同步。

网站使用 React／TypeScript，手机使用 React Native，复用业务类型、校验和 API 客户端。服务端采用 TypeScript 模块化服务，统一管理账号、资源、交流、群组、消息、资讯和治理，首发不拆微服务。

新增类型包括公开资料与状态授权、资源及版本、导入记录、主题关注、问题回答、群任务、会话、消息偏好、资讯稿件及审核版本、收录来源、可选日报、工单、处罚和申诉。通过版本化 HTTP API 提供业务、WebSocket 提供实时消息。权限、封禁、限流、附件和配额由服务端校验；资讯公开版与待审版分开授权，作者与审核者从会话确定，客户端不能指定官方身份或自行将稿件改为已发布。

2026-10-23 补充决定：当前本地产品尚无账号管理，阶段 0 只预留 CommunityIdentityPort 和权限预检接口。未接入时明确返回 not_configured，不生成假账号，不将学习画像或设备身份视为账号。真实注册、验证、会话及找回在阶段 2 接入；阶段 1 使用合成身份演示不能获得真实服务权限。代码边界与 API 清单见 阶段 0 接口说明。

2026-10-24 用户确认改用 CloudBase 托管账号认证。CloudBase 负责邮箱注册、验证码验证、密码登录和密码找回；社区 BFF 以 HttpOnly Cookie 提供会话，上游访问／刷新令牌以 AES-256-GCM 加密保存在服务端，不进入浏览器持久化存储。社区 PostgreSQL 继续保存业务账号、权限、群身份、限制、工单与审计。关联使用提供方、环境和稳定用户标识，不凭同邮箱认领旧账号，不把上游 `sub` 当作社区 UUID 或管理权限。环境未配置时明确不可用，不降级旧本地认证；详见 CloudBase 接入记录。

本地 NoteItem 与 UserProfile 不直接作为公开接口。当前只通过单篇快照白名单连接社区，网页保存经账号接收协议进入资料库或本地引用，不恢复笔记体系、不创建计划／掌握度／复习。阶段 7 的原生手机端复用相同权限与任务协议；复杂类型另行设计。

### 10.2 阿里云路线

以本次策划确定的阿里云中国大陆 ECS 为社区业务正式路线。此前「网站设计」对话准备过 Nginx、Node、HTTPS、自启动、备份和回滚模板，但未完成真实 ECS 验收。2026-10-24 的最新决定将 CloudBase 托管认证纳入账号路线；此前“CloudBase 仅用于开发测试”的约定不再适用于新社区认证。

- ECS 运行 Nginx、社区服务及后台任务，PostgreSQL 首发同机部署且不对公网开放。
- OSS 私有存储保存附件与异地备份，服务端鉴权后签发短时访问链接，关闭公开列举和匿名写入。
- CloudBase 托管账号认证，ECS／PostgreSQL 负责社区业务与权限；不把旧 SQLite 登录下载实现当作完整社区后端，不自动复用旧 CloudBase 测试环境或旧账号关联。

#### 10.3.1 资源点消耗与开发成本约束

2026-10-25 确定：节约资源点是当前及后续各阶段的设计、开发和验收要求。新增或修改涉及云端的功能时，先识别计费调用、数据库活跃时段、存储、出站流量及失败重试，再选择满足体验和安全要求的低消耗实现；不能等上线后再统一处理费用。

- **分别核算各环境。** CloudBase 当前承担账号认证，本地 PostgreSQL 和文件的开发用量不能当作已发生的云端消耗；阿里云 ECS／OSS、CloudBase 数据库等按实际选定的部署路线分别测算，不重复计算，也不把本机运行视为免费云端容量。开发测试额度与正式运营额度分开配置和记录，CloudBase 点数计入既定月运营总预算。
- **额度由配置决定。** 记录套餐、地域、账期、资源点总额、业务可用额度和计费延迟预留量，预留至少 20% 的资源点应对统计延迟与波动。免费体验版的 3000 点／月不能写成通用生产配置；不自动升配、加购或开启按量付费。预估不满足已批准额度时，先优化和复测；仍不满足则明确记录容量或预算待决项，不将功能直接标为通过。
- **避免重复上游认证。** 使用可信的社区会话、受验证的令牌或有明确有效期的认证结果，按到期、身份变化和撤销事件刷新；普通列表读取、轮询和每条消息不应无条件触发一次 CloudBase 用户信息查询。并发刷新合并为一次，失败有界退避；服务端的账号限制、群权限和文件授权仍按操作校验。认证缓存不得跨账号、跨环境复用，不得接受未验证身份或长期忽略撤销。
- **减少空刷新与重复请求。** 私信、群聊、列表和线程共用有界增量同步，优先采用适合实际部署的长轮询或推送；连接、心跳、函数运行时间和扇出也计入比较，不能假定 WebSocket 免费。重复打开当前页面不重建同步通道；隐藏页面停止非必要同步，无变化时采用有上限的退避，重连按游标补取。主动交流的实时体验仍须满足既定目标，不能通过频繁要求用户手动刷新节约点数。
- **后台任务按需运行。** 清理、摘要、索引、日报和同步采用事件触发、批处理或符合业务时效的调度，禁止无任务时持续高频扫描数据库。连接池、健康检查和定时任务均纳入数据库活跃成本；对于按活跃时间段计费的数据库，验收空闲时是否仍被这些操作持续唤醒。失败重试有次数、时长、并发和费用上限，不能形成重试风暴。
- **减少存储与下载浪费。** 头像和正文图片在保证可读性的前提下端侧压缩、去除元数据，文件按大小预检；资源列表只取摘要和必要缩略图，不自动下载完整 PDF、原图或附件。文件与接收记录按账号、权限、内容哈希及版本去重，同一授权传输可恢复时不重复完整传输。评估受控对象存储直传／下载及缓存，避免无必要地由后端中转大文件；缓存和短时授权不能绕过退群、撤回、封禁或私人资源权限。
- **复用已完成的处理。** 搜索、列表和历史使用分页与索引，避免全量扫描和无意义查询；摘要、预览、审核、索引按内容版本及授权范围复用，不能为每个访问者重新生成。AI、审核、日志、监控和遥测本身也核算调用、Token、处理量、存储和流量；只采集必要信息，设置采样及保留期限，普通操作不附带额外付费处理。

- **费用控制可观察、可停止。** 按环境、功能和计费项记录聚合计数、传输字节、估算点数和余额预测；不记录密钥、验证码或私人正文。实际账单与本地估算分开标识并对账，防止统计延迟造成超支；沿用 80% 告警、90% 停止新增可变费用任务规则。预算拦截须保留草稿和可恢复状态，不显示虚假成功，不把不可恢复的成本转嫁为丢失用户数据。

### 11.1.1 对话与群管理的开源实现基线（2026-10-25）

按用户要求，阶段 4 的私信和阶段 5 的群管理优先采用成熟开源平台已验证的模型，不另造一套消息／群管理逻辑。以下是本项目采用的映射规则，功能实现和验收均按此检查；引用的机制不代表已经部署这些产品或兼容其全部协议。

- **会话、同步与重试以 Matrix 为基线。** 会话使用稳定 ID，消息使用服务端 ID 和客户端重试 ID。首次只读取一段历史，此后使用游标增量同步，重复事件按消息 ID 合并，断线继续补取，向前翻页独立处理。重复打开当前会话不重建编辑器、清空记录或重置阅读位置。对应 [Matrix 同步与消息 API](https://spec.matrix.org/latest/client-server-api/#syncing)。当前本地消息使用前台 5 秒轮询触发增量读取，尚未实现 Matrix 的长轮询接口；群聊阶段优先共用同一同步通道，不能另建一套全量刷新机制。
- **列表归属与会话归属分开。** 参考 [Rocket.Chat 会话订阅](https://developer.rocket.chat/apidocs/subscriptions-api)，成员对会话的隐藏、草稿和个人偏好各归本人。当前「删除会话」仅从自己的列表移除，不删除对方记录或公共会话；新消息可重新出现，不能通过反复打开新会话绕过交流限制。
- **群讨论采用群内线程。** 按 [Rocket.Chat Threads](https://docs.rocket.chat/docs/threads) 的根消息与线程关系组织讨论。共学问题是一条可置顶的群消息，回复关联其根消息；「进入讨论」在当前群会话打开该线程，保留原话题与回复上下文，不另建重复聊天房间。置顶入口只属于交流区域，不出现在资源、成员等无关页；话题关闭后保留可读记录。
- **群权限采用房间角色与操作权限。** 按 [Rocket.Chat 房间角色](https://docs.rocket.chat/room-roles) 区分群主、群管理员和普通成员，非成员没有群内写入权限。群角色只在本群生效，不能赋予平台管理员权限；服务端核验成员身份和操作权限，隐藏按钮不作为权限保障。移除成员、群禁言、置顶和群设置分别判权。
- **群生命周期采用已有管理流程。** 参照 [Rocket.Chat 团队管理](https://docs.rocket.chat/docs/manage-teams) 的成员管理与所有权交接，群主离开前必须完成转让，或执行有明确记录的归档流程。申请、邀请、加入、退出和封禁是独立状态；角色变更和退群后，下一次消息／附件请求即重新检查权限。
- **求助采纳采用主题与答案关系。** 参考 [Discourse Solved](https://meta.discourse.org/t/discourse-solved/30155)，采纳指向具体答复，由具备权限的提问者或管理人员执行，保留原问题和讨论；采纳不会改写作者资源，资源更新仍由作者操作。

- **群任务参考 Plane 的工作项生命周期。** 使用稳定任务 ID、可选说明／截止日期、结束与重新开放、移除与恢复、版本冲突检查和活动记录，依据 [创建与管理工作项](https://docs.plane.so/work-items/create-and-manage-work-items) 与 [工作项详情](https://docs.plane.so/work-items/work-item-details)。本项目面向共学，采用成员主动参与、各自记录进度的方式；群管理者维护共享任务，不能代成员设置完成或公开暂停设置。页面保留列表形式和默认三项，不引入项目管理看板、优先级字段或强制指派。未引入 Plane 服务或复制其代码。

本项目保留已明确的产品约束：关注不等于私信授权；陌生人可先发一条介绍，接受后连续交流。默认无红点、数字角标、声音或系统推送；参与线程不自动开启提醒。Enter 发送、Shift+Enter 换行、中文输入法选字不发送、发送后保留编辑焦点属于统一输入规范。以上差异在策划中明确，不声称是上游平台的默认设置。

后续直接复用开源组件或源码时记录上游项目、版本和原许可证；共学业务只扩展学习任务、资源授权与监督关系，基础会话、线程、角色、权限和成员生命周期沿用本节模型。群管理开工前先对照上述来源确认权限和状态转换，验收覆盖越权、退群、群主转让、并发操作和重试。

### 11.1.2 同步与资源消耗整改（2026-10-25）

- 复用社区 API、权限和阶段 3 已完成的账号待同步／桌面接收通道，将原生手机的收藏／导入操作接入同一协议，完成账号偏好及专注状态协同；不另建一套资源格式或导入器。
- 验证安全凭据存储、登录恢复、弱网与重连、输入法遮挡、应用前后台和系统通知设置。

**做到什么程度**

交付可安装的两端测试包，在真实 iOS 和 Android 设备各完成关键链路；不以移动网页或模拟器截图代替原生手机验收。未拿到签名或真机条件时保留阻塞状态。

**验收标准**

- 手机完整走通资源发现、提问回答、入群参与任务、私信、投诉与查看结果，主要按钮不被键盘或安全区域遮挡。
- 手机保存到桌面的任务可在桌面找到；首次接收目标与自动接收授权未确认前不写入私人库，已授权任务可静默接收，重复操作不重复导入。计划仍在实际启用时排期，不因手机操作绕过类型导入及状态初始化规则。
- 弱网、断网、切后台、进程重启和会话过期不清空已保存草稿，不显示虚假提交成功，重试不重复。
- 新安装默认不请求通知权限，无系统推送、声振和图标角标；用户主动开启时才申请对应权限。
- 桌面进入专注后手机也暂停普通提醒，退出不补发；注销和退出清理相应会话权限，不影响本地私人学习数据。
- iOS、Android 和桌面使用同一版本的资源、隐私设置及治理结果，不依赖某个客户端自行过滤权限。

**交付物**：两端测试安装包、真机验收记录、多端协同演示、弱网与通知权限报告。

### 11.10 阶段 8：阿里云联调、容量验证与完整发布

**做什么**

- 在符合条件的真实 ECS、域名、HTTPS 和 OSS 环境部署网站、API、任务与后台，完成数据库初始化、权限、备份和监控。
- 验证真实注册验证渠道、外部来源、投稿审核和附件授权；若以后确认启用 AI，再验证对应服务。核算全部已启用能力的实际费用，不为可选日报提前开启收费任务。
- 将阶段 3 的网页／视频链接、资料文件及单篇笔记在线分享在真实 ECS／OSS 上复验，核对权限、容量、流量、资料／链接离线任务和失败恢复，并检查历史快照及其记录保留；本地通过不代替正式云端验收。
- 执行整体验收、压力测试、备份恢复、版本回滚和安全事件演练，准备真实署名的初始资源与运营规则。
- 完成网站、桌面入口和两端原生应用发布检查及必须的主体、备案、隐私和分发手续核对。

**做到什么程度**

受控公网环境完成真实端到端验收，记录容量与费用结论，部署可恢复、后台可运营、投诉可处理。完成发布前门槛后开放完整首发，再执行首周观察并关闭本阶段，不把部署成功或 HTTP 200 直接视为上线通过。

**验收标准**

- 真实域名下完成注册登录、资源发布导入、问答、共学、消息、资讯收录、用户投稿／管理员审核／官方发布和举报申诉，云端重启后数据与权限正确。可选 AI 摘要／日报只有确认启用后才加入对应验收。
- 使用至少一万账号、一万资源、一万问题和十万消息的隔离测试数据，建立 100 个真实 WebSocket 连接；以每秒 20 次 HTTP 请求、读写约 8:2 的混合负载持续测试 30 分钟，不对生产私人数据压测。
- 初始性能目标：不含公网链路及第三方服务耗时的服务端读取 P95 不超过 1 秒、写入 P95 不超过 1.5 秒；稳定测试网络下消息送达 P95 不超过 2 秒；非预期服务错误率低于 1%，已确认写入或消息丢失及重复业务记录为零。限额拦截单独统计，不掩盖为服务成功。
- 真实域名、数据库、附件和管理接口的访问范围正确；不存在未登录绕过下载、跨群访问、越权管理或默认公开私人状态。
- 完成异机备份与恢复、发布回滚和管理员恢复演练。初始恢复目标：数据库备份恢复点不超过 24 小时，恢复操作开始后 4 小时内恢复核心业务；操作目标不表示个人运营提供全天候值守承诺。
- 实测与费用测算满足批准的预算及开放容量；不满足时保留上线阻塞，修正配置、容量或预算安排，不将目标改写为已通过。
- 完成 11.15 的资源点验收：以实际地域、套餐和部署路线对账，分别报告空闲基础消耗、正常活跃消耗、文件分发和失败重试消耗；未解决的重复上游认证、持续空轮询及空闲数据库唤醒不得直接带入正式环境。月度预算投影包含计费延迟余量，并验证告警和停止新增费用任务的行为。
- 没有未解决的私人数据泄露、越权、已确认数据丢失、核心功能不可用、无法恢复或普通提醒绕过专注等阻塞问题；其他已知问题明确影响、替代方式与处理安排，不影响必需链路。
- 上线后首个 7 天进行运行观察：服务异常、工单、队列、备份及费用按日核对；不为提高活跃度恢复红点或扩大推送。观察结束形成稳定性复盘，异常按既有回滚和隔离流程处理。

**交付物**：部署与版本清单、公网验收报告、压测及费用报告、恢复回滚记录、发布检查清单、运营交接与首周观察报告。

### 11.11 全阶段通用：体验验收

- 每个页面主要任务和操作清晰，次要信息易找，没有重复模块、卡片墙和自动填入的无关内容。
- 市场默认三条资源，其他页面也按当前任务收敛首屏，不仅对市场执行信息精简。
- 已登录用户求助为「输入 → 发布」，收藏与任务完成一步完成，已有资源分享只进入一个编辑面板。
- 无强制冗余字段，自动分类失败可发布，失败保留草稿，重试不重复生成记录。
- 无多层抽屉堆叠，关闭后恢复位置和焦点，键盘、触屏和鼠标可完成主要操作，重要功能不依赖悬停。

### 11.12 全阶段通用：注意力保护验收

- 全站默认无红点、数字角标、闪烁、跳动、声振、普通推送和强制通知权限请求，覆盖网页标题及应用图标。
- 普通 @、回复、群公告和日报不自动升级为强提醒，开启提醒必须由接收者主动选择，群主无法代开。
- 专注期间多设备均暂停普通提醒，专注结束不集中补发或弹出汇总；用户主动设置的学习计时提醒仍按约定运行。
- 阅读历史不被新消息自动滚动或重排，普通操作反馈局部呈现，保存失败清楚可见。
- 不设置清空未读任务、未读排行榜或诱导回访的积压数量，关闭推荐与提醒后设置持续生效。

### 11.13 全阶段通用：学习、权限与治理验收

- 导出包不含私人状态、密钥、登录信息、本地路径或未选择的关联内容，群内与指定学友权限贯穿搜索、预览及下载。
- 导入不覆盖已有学习记录，计划日期和内部链接正确重建，来源版本可追溯，重复与失败可恢复。
- 正文、主资源与补充附件角色明确；各类型实际落到相应本地库，笔记包可逐篇使用，知识点未评估不计作 0 分或已学习，计划在启用时排期，资料下载成功与索引可用分开核验。

- 资讯与投稿的来源标识、版本审核、公开范围、撤回／下架及恢复可验证；自动收录不自动发布。以后如启用日报，再验证去重、AI 标识、纠错、失败回退和预算熔断。
- 举报 → 处置 → 反馈 → 申诉 → 改判恢复形成闭环，普通用户及群管理员无法越权，重大处罚有人工依据和审计。

### 11.15 全阶段通用：资源点与成本验收

- 每项相关变更附简短成本说明：触发条件、一次操作的上游调用数、同步频率、数据库活跃方式、传输字节、去重／复用／重试策略，以及变更前后结果；没有云端费用影响时注明依据。计费估算不能代替真实账单，模拟上游计数不能标为已发生的云端用量。

- 真实云联调使用有上限的最小样本，检查实际抵扣明细、认证请求增长和数据库活跃时段；计费有延迟时等待该周期统计完整再对账，不反复执行大流量测试催出账单。按目标日活、同时在线时长、下载文件大小与次数、存储留存量投影月度消耗，并标明假设，不直接将资源点换算成支持人数。
