# 个性化项目教材改造计划

更新日期：2026-10-06

## 核心目标与实施范围

将 Agent 从推荐资料与补全单个概念，扩展为能够为一个明确的学习项目生成完整、可直接学习、可追溯来源的教材。教材以本地物料为主、网络补缺为辅，根据可信用户画像、相关个人认知、掌握度和当前根项目下的学习记录组织内容，重点解决认知遗漏、概念混淆和适用条件误判，并衔接项目学习路径。

教材写入目标项目笔记，用户进入心流页面即可阅读、提问、复述和复盘。同一项目默认只生成一次完整教材，跨天继续学习不产生新教材。这里的“当日生成”是计划触发时机，不是按日期创建教材的存储规则。

### 必须保留的产品边界

1. 复习通过现有复习入口进行。Agent 可根据掌握度、遗忘风险和上次学习的未解决问题，在对话中建议先复习；用户可以接受或跳过。教材不插入上一课的复习模块，也不强制用户先完成复习。
2. 用户批准为指定项目生成并写入教材后，流程才进入生成和发布。授权应明确目标项目、操作类型、本地资料范围和是否允许联网；不因开启 Agent 自动模式而跳过授权。
3. 同一项目有教材时默认继续阅读。只有用户明确要求重写或末尾补充，才执行对应操作；到期、跨天、画像变化和新增资料都不自动触发重写。
4. 项目正文以教材为主，原有计划任务和用户手写内容不被覆盖。每完成一次心流复盘，向笔记写入一个独立的可折叠学习记录框，框内同时显示本次复述文本和原有论证结构图 block。保留 block 的显示、点击编辑和保存回写能力，不移除现有进入论证图的入口。标题默认使用本次学习时间，并允许用户编辑修改。
5. 保留已跑通的资源推荐四标签页、查询组装、自动推荐配额、人工无限额添加和偏好累积逻辑。教材搜集不能偷偷追加项目资源或复用资源草案作为教材草案。
6. 概念补全保持独立。知识点标题就是知识点本身，继续使用原标题及别名，不进行项目标题式语义清洗；教材生成不自动覆盖知识点正文。
7. 复用现有 MathLive、KaTeX、RAG、画像信任门控、认知查询、学习记录和复习调度，不另建平行系统。
8. 生成、阅读和查看答案都不等于用户已经掌握知识，不因此增加掌握度样本、更新认知观点或勾选计划完成。

### 第一版完成的定义

第一版不是一份资源清单，也不是每天一份泛化摘要。它须完成从用户授权、定位项目、读取本地证据、设计针对性教学内容、生成多格式教材、原子写入，到心流阅读与跨天继续学习的闭环；支持缺口联网补充、明确重写和末尾追加，并通过数据保全与来源分离验收。

暂不纳入：整个根项目批量生成教材、自动改写学习计划、任意代码执行、通用网页爬虫平台、付费页面绕过、所有音视频自动解析，以及对全部笔记页面的整体重构。

## 现有能力与关键缺口

### 可直接复用

- `src/components/MdxNoteEditor.tsx`：标题、列表、引用、代码块、表格、图片及自定义公式编辑。
- `src/modules/derivationCanvas/components/MathField.tsx`：MathLive 编辑与 KaTeX 静态阅读的现成分工。MathLive 也提供静态转换和只读公式能力，但不必为普通教材公式全部切换渲染引擎。[MathLive 官方说明](https://mathlive.io/mathfield/guides/static/)
- `src/electron/ragIndex.ts`：BM25 与向量混合检索，知识层启用后的原文、实体、论证检索和关系扩展，章节与原文定位。
- `src/services/documentRagClient.ts`、`src/services/argumentDoc/evidenceSources.ts`：检索候选后重新读取命中片段，再形成引用的路径。
- `src/services/agent/tools/dataTools.ts`：用户画像、掌握度、复习队列、知识点参考正文及导入资料查询。
- `src/services/agent/tools/planTools.ts`：项目层级、关联知识点、计划与任务范围查询。
- `src/services/cognition/`、`src/electron/cognitionMaterials.ts`：个人观点、复述和已发布用户论证的专用检索通道。
- `src/services/memory/episodeStore.ts`：学习记录及既有持久化策略。
- `src/electron/resourceBrowser.ts`：公开网页读取所需的隔离 Electron 浏览器基础。
- `src/services/agent/toolRegistry.ts`、`approvalBinding.ts`：工具权限、审批和参数绑定机制。

### 必须先解决的冲突

- `FlowMode.tsx` 当前退出路径把复述全文写入 `note.content`。新增教材后必须先保存本次会话数据，再在复盘保存时追加或更新对应学习记录框，不能继续覆盖正文。
- `App.tsx` 当前保存新论证图会向正文直接追加 `<ArgumentBlock ... />`。须改为在本次学习记录框内绑定并显示该 block，而不是取消 block 或移除入口；图文档继续保存在既有 `argumentDocs` 中。
- `ragSourcePolicy.ts` 当前从项目正文推导复述。新增教材若不更新来源分类，会被误当成用户观点，形成“模型生成教材被视为用户认知”的反馈污染。
- `userStateService.ts` 使用字段白名单拆分笔记内容和个人状态；新字段须进入正确的序列化、迁移、导入导出路径，否则重启后可能丢失。
- 心流正文目前主要使用 ReactMarkdown 与 GFM，未统一接通编辑器的全部内容能力。

### 读取能力缺口

当前文档索引主要覆盖 TXT、Markdown、文字 PDF、DOCX、PPTX；扫描 PDF 缺 OCR，Office 与 PDF 的图片、表格和公式未形成可引用的完整素材。检索输出主要为摘要，预览也有条目和长度限制；缺少限定文档范围的章节深读接口。PDF Python 路径还依赖系统环境，需要明确桌面部署与降级策略。

这些缺口应补在现有 RAG 上游和读取接口，不通过替换现有检索框架解决。

## 数据与持久化设计

以下类型与模块名称是实施建议，新增接口不视为当前已存在的功能。

### 项目正文与教材元数据

保留 `NoteItem.content` 作为可编辑正文的唯一当前内容源。教材占一个可稳定识别的受管区域，原有任务锚点、日期、手写内容和每次复盘的学习记录框引用保持独立。写入只替换或追加教材区域，不整份替换笔记。

新增 `TextbookManifest`，建议记录：

- `schemaVersion`、稳定 `textbookId`、`projectNoteId`、`rootProjectId`；
- 当前修订 ID、教材区域标识与内容哈希、生成和更新时刻；
- 学习目标、章节锚点、章节与任务或知识点的对应关系；
- 来源引用、素材引用、待核实提示，以及画像和认知上下文的最小版本指纹；
- 教材状态及生成任务引用，不用日期充当教材身份。

结构化内容块用于生成、验证和渲染，发布时序列化到正文。解析缓存以正文哈希为键，避免另一份教材正文与编辑器内容同时成为真源。版本历史保存不可变快照，不参与当前内容的双向覆盖。

### 每次复盘的折叠学习记录

新增 `LearningReviewRecord`，按稳定学习会话 ID 保存一条记录，至少包含：记录 ID、项目 ID、教材修订 ID、学习开始结束时间、标题及是否由用户修改、复述原文、用户编辑后的文本、总结、已有学习记录引用，以及本次论证图的 `argumentDocIds`。原始转写与分析副本保持区分，不因分析失败丢失用户内容；实际图文档继续使用既有 `NoteItem.argumentDocs`，不另存一份平行图数据。

每完成一次心流复盘，正文插入一个受控的 `LearningReviewBlock` 引用，而不是把所有会话汇总到一个框。展开后依次显示本次复述文本和原有 `ArgumentBlock`，收起后只显示标题及必要的时间信息。第二次复盘生成第二个框，即使发生在同一天，也不能按日期合并成一个框。折叠状态只影响展示，不改变记录内容、论证图准入状态或认知检索。

标题默认由真实学习时间生成，例如“2026-10-06 20:10–20:45”。用户可重命名标题并修改复述文本；用户已修改的标题不能在后续保存结构图时被时间标题覆盖。底层开始结束时间保持原始记录，不随标题修改改变。图继续通过框内 block 打开原编辑器，保存修改后更新同一记录中的原图，不新增复盘框。

外层折叠组件负责记录身份、标题、展开与文本展示，内层复用既有结构图渲染、图 ID 查找及编辑回调。编辑器须支持外层受控块的导入导出，不能因包裹 block 而出现解析失败、丢失嵌套图引用或点击回调失效。记录 ID 与图 ID 的关系必须可持久化、可定位，不能仅存在于页面状态。

心流复述输入框只加载明确的复述数据，不以教材正文作为旧复述前缀；分析只读取本次会话的明确输入，不再通过正文前缀截取来猜测增量。复述与个人认知仍由各自来源通道读取，不因同处折叠框就把教材与复述混合送入分析。

阅读进度单独保存教材修订 ID、章节或块锚点、滚动位置和最近阅读时间。展开状态与阅读进度属于个人状态。普通教材分享不默认带出个人复述，完整个人备份保留记录及图引用；既有 `argumentDocs` 的存储、发布与分享边界不因包裹组件被静默改变。

### 心流复盘的保存顺序

1. 用户在心流页完成复述与复盘，先暂存本次会话原文和总结；不能用这一步覆盖教材或整份笔记。
2. 沿用现有流程进入复盘分析，生成本次论证结构图并展示分析结果。
3. 用户点击分析结果页的保存退出后，按项目 ID 和会话 ID 一起写入复述、图关联及学习记录框，再返回项目笔记。记录框和图引用必须同时可用，不能出现文本已保存但图入口丢失的半完成状态。
4. 首次保存追加一个框；同一复盘重复点击保存、分析重试或图编辑器回传，只更新同一记录，不追加重复框。新的心流复盘使用新的会话 ID，追加新的框。
5. 若关闭分析或分析失败，保留复述和会话数据并标记实际状态，不编造图；重试成功后将真实图补入同一记录。取消分析不得删除已经暂存的用户文本。

论证图是否发布进入 RAG 仍遵循原有质量与用户确认规则，保存到折叠框不等于自动通过论证质量门控。教材重写、末尾补充或恢复旧教材版本不得移除这些记录框和图入口。

### 物料与来源

新增 `MaterialReference` 与 `MaterialAsset`，至少包含：

- 文档 ID 或规范化来源 URL、来源类型、标题、采集或解析版本和内容哈希；
- 页码、章节、块 ID、表格或插图位置及必要的边界框；
- 引用原文及截断标记，图片图注和邻近上下文；
- 图片、表格、公式、代码等素材类型，稳定素材 ID、本地缓存引用与质量状态；
- 原始素材、识别结果和模型说明的区分，使用限制及已知来源信息。

图片、表格和识别公式保存为可定位的素材，不将大量 Base64 写进教材。内部引用使用受控素材 ID，不把用户绝对路径交给 LLM。公式识别低置信度时保留原图；插图的模型描述不能冒充原作者图注。

### 生成任务与版本

新增 `TextbookGenerationJob`，绑定项目、操作、授权、本地资料范围、联网许可、基础教材哈希、阶段检查点和幂等键。三个操作为 `create`、`rewrite`、`append`：

- `create`：没有教材才允许；存在教材直接返回继续学习入口。
- `rewrite`：明确授权后替换教材区域，保留旧版，个人记录不删除。
- `append`：只在教材区域末尾增加补充章节，保留已有正文、修订历史和锚点。

同一项目同时只允许一个修改教材的任务。重复点击、工具重试和重启恢复不能重复发布。续跑任务不能自动继承过期写入授权。

## 用户交互与授权流程

1. Agent 解析当天计划或用户请求，按稳定项目 ID 确认目标；同名项目或多个候选无法确定时再询问，不仅凭标题写入。
2. 读取该项目教材状态。存在教材时推荐继续阅读，展示上次位置和可选的重写、末尾补充入口，不重新生成。
3. 从当前根项目下真实学习记录中选择最近一次相关学习，结合现有掌握度和复习队列建议复习。用户可进入已有复习页，也可直接准备教材。
4. 首次生成的授权说明写明：目标项目、操作、预计教材范围、本地优先、联网开关、教材写入及旧内容保留方式。来源向云端模型传递遵循现有模型配置和明确的数据许可；“本地物料”不代表“生成模型也在本地”。
5. 用户已明确批准“生成并写入此项目”时，只对同一任务、同一范围进行发布，不强制第二次重复确认。目标、操作、读取权限或用户教材内容发生实质变化时，原授权失效。
6. 对话中显示资料检索、章节读取、教材组织、格式验证和写入等阶段进度。提供取消和失败重试，不把每次后台查询映射为用户面前的浏览器刷新。
7. 发布成功后展示章节概览和“进入心流学习”。只有持久化成功才报告教材已写入；生成完成但写入冲突时不能宣称完成。

生成过程允许用户继续阅读旧教材。新的半成品保存在任务草稿中，不流式覆盖笔记。用户取消、模型错误或联网失败均不改变已发布教材。

## 个性化教学内容设计

### 学习上下文

新增只读 `LearningContextPacket`，复用现有查询，组织以下信息：

- 项目与根项目身份、真实学习任务、明确关联知识点及别名；
- 达到信任门槛的用户画像和学习偏好，当前任务允许的时间或难度；
- 相关个人观点、原话证据、认知状态和出处；
- 当前根项目下最近一次相关学习记录、未解决问题和已经表达过的理解；
- 教材状态及已读进度、参考资料范围。

最近学习按真实发生时间筛选，不以笔记修改时间代替。新记录补充根项目身份快照；旧记录根据可验证的项目关系保守映射，无法确定归属时不跨项目套用。学习偏好复用现有资源反馈，不新建另一套偏好分数。

### 从认知证据到教学安排

新增 `TeachingBlueprint`，每个教学重点记录：认知证据、问题分类、可观察学习目标、支撑资料、采用的解释或练习方式及对应教材章节。

明确区分“已表达的观点”“尚未表达”“待验证的可能误解”“与材料存在冲突”。未检索到观点不等于用户不懂；一次复述遗漏不等于稳定缺陷；对既有观点的纠正必须有可检查的材料依据，并标注适用范围。

例如，用户表达“选项越多必然越差”时，先查资料是否讨论适用条件、研究分歧和边界，再决定是否加入条件对照、反例和判断练习。不能先按常识判错，再找材料装饰结论。

画像主要决定解释粒度、抽象与实例顺序、支架和呈现方式；不会改变事实、删掉必要边界或把偏好固化成标签。无可信画像时采用中性教学设计；偏好视频的用户仍有可独立阅读的完整教材，可附视频入口和阅读指引。

### 教材章节

根据任务选择内容，不强制每份教材使用全部格式。基本结构为：

1. 学习目标与本主题在项目路径中的位置。
2. 必需前置概念和核心定义。
3. 机制、步骤或推导，以及适用条件。
4. 示例、对比和反例，针对有证据的混淆安排讲解。
5. 与任务一致的案例或实践题，答案和解释可折叠。
6. 自我检验、关键结论、未核实内容及来源。

“承上启下”体现为概念连接和学习路径，不复制上一课的复习内容。全教材可按章节分配建议用时，但不因当天剩余时间少就把完整教材压缩成日摘要。现有场景训练可作为可选入口，生成教材本身不自动启动训练或复习。

## 本地物料搜集与网络补缺

### 复用 RAG 的搜集路径

1. 建立目标项目资料清单，优先使用用户指定教材、项目已绑定且可读取的文档，其次使用其他获准本地资料和知识点参考正文。
2. 按教学目标设计少量短查询，使用知识点原标题及别名，分别查定义、机制、条件、案例和争议；不拼接整个长项目标题。
3. 调用现有混合检索及已启用的知识层。保留已有全局配额与排序基线，不为教材直接改大所有查询的返回数量。
4. 用文档 ID、片段 ID 和章节路径读取完整上下文，收集关联素材。先解决“找到以后读不完整”，而不是只扩大搜索次数。
5. 形成 `MaterialPacket`，按章节组织证据和素材，后续生成阶段复用，不为每个段落重复联网或检索。

DeepTutor 的教材流程先形成资料探索报告，后续章节设计与内容块复用该报告中的检索结果；本项目借鉴这种阶段分离，不照搬其并发数量。[SourceExplorer 实现](https://github.com/HKUDS/DeepTutor/blob/main/deeptutor/book/agents/source_explorer.py)

### 新增受控深读接口

建议在现有 `ragDocs` 接口旁新增：文档目录、按章节或页码分页读取、读取邻近块、按 ID 读取素材。教材检索包装层增加允许文档 ID 范围、来源状态和读取预算；普通 `search_documents` 的默认行为保持兼容。

读取结果显式返回截断、游标、解析失败与质量状态。章节整读有长度和页数预算，不把整本书无界限塞进 LLM。读取权限绑定资料 ID，Agent 不获得任意磁盘路径读取或任意 CLI 执行能力。

解析完成与索引完成分离：文档已有可读原文但向量化失败时，允许在授权范围内直接读指定章节，不能把失败状态误报为无资料。目录、图片图注和表格说明可建立搜索文本，但原始素材保留在素材目录中。

### 文档解析增强

保留 TXT、Markdown 和普通文档的快速解析，复杂 PDF 和扫描件走独立文档 worker。优先评估 Docling 的结构解析、OCR、图片和表格导出；代码、公式及图片理解按需启用，并记录识别质量。Docling 支持预下载模型与本地运行，额外增强模型会增加处理成本。[离线选项](https://docling-project.github.io/docling/usage/advanced_options/)、[素材导出](https://docling-project.github.io/docling/_generated/examples/export_figures/)、[公式与图片增强](https://docling-project.github.io/docling/usage/enrichments/)

引入前使用真实中文资料评测，并验证 Windows 安装包内的运行时、模型、字体、取消、超时和内存占用。若复杂解析效果或部署成本不达标，首轮增强采用现有解析器加局部 OCR、原图提取；不因选型未完成而重写 RAG。

新增格式按需求排序：扫描 PDF 和图片、Office 图表与图片、EPUB 和表格文件。CSV、Markdown 与代码使用结构化解析以保留缩进、表头和公式。旧 Office 转换、音视频字幕与批量转写作为后续扩展，不绑在第一轮闭环上。

### 仅针对缺口联网

物料覆盖检查逐项标记充分、部分、缺失或冲突，不设置机械的本地占比。若本地证据已满足目标，不调用网络；若禁止联网，展示缺口、允许缩小范围或等待补资料，不伪装完整。

网页读取使用独立教材 reader：Node HTTP 获取、Readability 提取与 Turndown 转换，保留代码、表格、图片引用和来源信息；对转换遗漏的公式及复杂表格保留原始定位与质量提示。动态页面仅在必要时复用隔离 Electron 浏览器；下载的 PDF 和 Office 转交同一文档解析通道。[Readability](https://github.com/mozilla/readability)、[Turndown](https://github.com/mixmark-io/turndown)

reader 有查询和读取预算、超时、大小、重定向及内网地址限制。页面脚本、资料里的提示词和 HTML 都是不可信输入；不读取持久登录 Cookie、不绕过验证码或付费访问，也不执行资料中的操作指令。搜索摘要不能冒充已读正文，候选 URL 不能猜测生成。联网物料缓存至教材任务的受控目录，不自动成为项目资源推荐。

## 多格式教材的编辑与阅读

建立共享教材内容解析和组件注册层，服务项目编辑器与心流阅读。答疑消息等其他页面可逐步复用，但不以全站渲染重构阻塞本功能。

- 文字、标题、列表、表格和图片：复用现有 Markdown 与 MDXEditor 能力，补图片来源、说明、替代文本和素材链接。
- 公式：沿用 KaTeX 静态阅读、MathLive 按需编辑；新增共享 `FormulaBlock`，统一多行公式、宏和错误回退。MathLive 只读能力用于需要公式选择或交互的单独场景，不给每个普通公式挂输入组件。
- Mermaid：新增图块，支持流程图、时序图与基础 mindmap，先校验再显示，保留源码和错误回退。基础思维导图由 Mermaid 提供，Markmap 暂不作为必需依赖。[Mermaid mindmap](https://mermaid.js.org/syntax/mindmap.html)
- 统计图表：新增 ECharts 的受限 JSON 图块，按需引入图表类型；现有 `function-plot` 继续用于函数曲线。图块不能接收模型输出的可执行回调。真实数据绑定来源，模拟数据明确标为教学示例。[ECharts 按需加载](https://echarts.apache.org/handbook/en/basics/import/)
- 代码：复用现有代码编辑能力，补语言标识、复制和阅读高亮；高亮实现优先检查现有能力，需要时再评估 Shiki。保留缩进，默认不执行代码。
- 注释和来源：区分代码内注释、教学提示块、引用脚注及用户个人批注。脚注阅读复用 GFM，补编辑器导入导出与定位；个人批注不混入教材事实。
- 折叠块：受控的提示、答案，以及每次复盘的学习记录组件。学习记录框内显示本次复述和原结构图 block，并提供可编辑标题；不允许任意 HTML、脚本或任意 MDX 组件执行。

图块内容须经历生成、格式校验、保存、编辑、再次打开、心流阅读的往返测试。编辑器修改后仍保留来源身份和教材区域边界；未知块显示可恢复源码，不静默删除。用户论证图位于对应学习记录框中，教材概念示意图位于教材区域，两者保持不同来源类型和编辑语义。

MathLive、KaTeX、Markdown、图片与公式字体继续离线可用。新增 Mermaid 与 ECharts 按需加载，版本选择以当前 Electron 和构建环境的兼容测试为准，不直接无条件安装最新版本。Readability 不是安全净化器，网页转出的内容仍需进入受限内容块和安全渲染路径。

## 教材生成与发布编排

新增应用内部 Skill `personalized-textbook`，复用现有 Agent 工具注册与权限架构；它不是为开发工具安装一个外部教学插件。

### 生成阶段

1. 定位项目、检查教材状态并验证授权。
2. 构建学习上下文，区分个人认知与外部参考证据。
3. 检索和深读本地资料，形成物料包与覆盖检查。
4. 获准且确有缺口时补充网络证据。
5. 生成教学蓝图，再按章节生成受限结构内容块。
6. 验证学习目标覆盖、引文存在、引用语义、数据来源、格式和安全性。
7. 只修复未通过的章节，设置有限次数；无法通过时保留草稿并报告原因。
8. 在主进程复核目标、基础版本和授权后原子写入，生成发布回执。

任务检查点保存已经取得的物料、章节状态和内容哈希，避免失败后全部重搜。已发布教材在新版本生成期间始终可读。模型生成完不等于通过验证，图片或公式识别完成不等于准确。

### 写入与冲突处理

- 写入目标必须为稳定项目 ID，操作必须与批准的任务一致；不依赖模型最后回答里的项目名称。
- `create` 发布前再次检查教材是否已存在；有则返回现有版本，不能重复创建。
- `rewrite` 与 `append` 校验教材区域的基础哈希；用户修改过该区域时中止提交，保留双方内容并请求重新确认，不自动覆盖。
- 生成期间只新增复述、修改阅读位置或更新资源时，提交从最新笔记合并无关字段，不能回写旧的整个 NoteItem。
- 笔记、教材元数据和版本快照通过原子写入或可恢复的发布事务保持一致。素材先写受控暂存目录，发布回执成功后变为该版本引用的素材；失败不清理用户原资料。
- 恢复旧教材版本只改变教材区域，不回滚新的复述、计划、画像、资源或论证图。
- 成功回答依据发布回执和持久化状态，不依据生成模型的自我声明。

### 工具与运行时接入

建议新增受控工具：查询教材状态、读取教材上下文、搜集和深读教材物料、开始教材任务、查询或取消任务，以及提交教材。搜索与读取为只读权限，写入为明确授权权限；联网与写入许可不能混为一个无限制通行证。

接入范围包括 `skillRegistry`、`bootstrap`、角色工具上限、意图路由、审批绑定、运行恢复、阶段展示和最终回答门控。现有审批草案类型仅有 plan 与 resource，须新增教材类型或等价的教材任务授权，不借用其中任意一种。

“继续”“确认”“取消”等短输入必须绑定当前正确的教材任务；已有计划或资源草案时不能误提交它们。扩展 `activeDraft` 与任务路由时保留既有草案并显式处理冲突，不以开启教材功能清空旧草案。

## 测试与验收

### 必须通过的产品场景

1. 本地资料已覆盖学习目标：完整生成，联网调用为零，来源可打开定位。
2. 本地缺少必要证据：只搜该缺口；不允许联网时说明限制而不伪装完整。
3. 用户原话与材料冲突：教材有带依据的条件说明、对照或练习，而非只有“你可能理解错了”的标签。
4. 无画像、无认知观点或无学习记录：正常使用中性教学设计，不编造用户特征或上次经历。
5. 同一根项目最近学习与其他根项目不同：衔接和复习推荐不串入其他项目记录。
6. 已有教材跨天未学完：复用同一教材与修订，恢复位置，不自动创建新内容；超期仅提示计划状态，不自动重写。
7. 心流退出和分析失败：教材、任务、复述及已保存记录均保留，未把全文教材当作用户语音分析；分析失败或重试不丢文本、不编造图、不重复追加框。
8. 首次生成、重写和补充重复点击或重试：每次授权对应的有效操作只发布一次。
9. 生成时用户修改教材：拒绝覆盖并保留草稿；仅新增复述等无关变化时可以安全合并。
10. 重写、追加和恢复版本：旧教材可恢复，复述和论证图不被回滚，追加不改变已有章节内容。
11. 所有支持格式：编辑保存后再打开，公式、图片、表格、Mermaid、图表、代码、注释与折叠块正常。
12. 来源被删除、更新或无法访问：对应引用提示状态，不把原引用静默改绑到另一份来源。
13. 恶意资料与页面：脚本、提示词注入、内网 URL、路径越界、超大文件和异常压缩包不触发越权行为。
14. 生成教材不增加掌握度样本、不自动发布用户观点、不勾选任务、不追加项目资源。
15. 旧笔记迁移重复执行、导入导出、个人备份恢复和重启：内容不丢失，私有复述不默认随教材分享。
16. 完成一次心流复盘并保存退出：新增一个折叠框，包含本次复述和原结构图 block；默认标题为学习时间，可重命名，保存重启及图编辑回传后保留自定义标题；再次复盘新增另一框，同次复盘重试只更新原框。
17. 折叠框展开后的图入口：原图显示、点击编辑、修改保存及既有质量发布流程均可用；折叠、教材重写与历史版本恢复不导致图入口消失。

### 针对性教学评价

固定一组可追溯资料与学习者样例，至少包含：有条件误判、概念混淆、只有复述遗漏、观点待核实、新用户，以及不同呈现偏好。每个样例核对学习目标覆盖、事实和引文一致性、认知判断证据、条件与反例、解释支架、练习适配和来源可定位。

确定性检查验证引用 ID、结构、安全、版本和幂等；语义评测检查引文是否支持结论、是否误判用户以及是否遗漏条件。模型自评只能辅助，不能替代固定样例和人工验收。生成教材引入新的观察材料前，不改变现有画像信任与掌握度证据门槛。

## 依赖与范围决策

- 必须复用：MathLive、KaTeX、MDXEditor、ReactMarkdown、GFM、现有 RAG 与认知通道。
- 拟新增：Mermaid、ECharts，以及网页 reader 所需的 Readability、DOM 实现和 Turndown 相关依赖；实现前核对现有依赖树与兼容版本。
- 按实际接入选择：`remark-math` 等公式语法解析；`rehype-katex` 只是一种阅读接线方案，不是必需的新公式引擎；代码高亮不足时再选择 Shiki。
- 需评测后决定：Docling 或轻量 OCR 增强、额外公式识别模型、旧 Office 转换工具及其 Windows 打包方式。
- 后置：Markmap、批量音视频转写、视频关键帧识别、交互实验生成、教材 PDF 导出和专用图像生成服务。

核心实现原则是先复用现有系统，补全来源明确的物料读取与针对性教学编排，再增加必要呈现能力。完整功能的判断以学习闭环、数据保全和教材质量为准，不以安装了多少插件为准。
