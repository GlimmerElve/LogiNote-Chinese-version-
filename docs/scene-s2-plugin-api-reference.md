# S2 交互包接口参考：v1 核心与 v2 包内物料

本文保留原开发指南的详细契约，供按字段、限额和兼容规则查阅。首次开发请先按[开发指南：从源码到可复用场景](scene-s2-plugin-developer-guide.md)完成示例、实现、安装与验收；本参考的章节顺序不是开发步骤。核心接入与视图接口于 2026-10-28 对照当前代码核对。

目标：开发者能够依据明确的协议，独立交付组件、业务逻辑、Agent 说明和界面；符合已有接入范围的新包，不需要修改 S2 业务代码。S2 不理解包的业务含义，不预设提示词测试流程。

本文将“当前可用的契约”“开发者应履行的约定”和“尚未实现的能力”分开。后续目标不是可以直接写入当前清单的字段。当前支持 S2；S1/S4 尚未接入此包协议。代码类型与读取器是当前可执行契约的依据，历史实施记录不替代本指南。

## 1. 先判断你的包能否使用当前接口

当前可以独立接入：

- 纯本地 `transform` / `validator`，以及声明了有界结构的语义数据类型。
- 严格符合 `model-session@1` 的模型能力，由宿主管理当前模型、执行入口及程序限额。
- 包内的 React 设置视图、节点内嵌视图、完整能力节点视图、本地双击交互、端口位置与显示策略、帮助说明和交互草稿。
- 通过已安装的共享能力读取用户本局选择的文件、图片及逐项允许的项目知识笔记。
- v2 包声明并读取所属包的固定文本、JSON、PNG/JPEG/WebP 物料，由包视图在 S2 中展示。

当前不能通过动态安装接口新增任意执行类 renderer/human、文件写入、网络或系统执行器。包的自定义视图与执行图中的 renderer 能力是不同概念：视图可提供业务可视化，但不能据此注册新的宿主执行种类。

不需要独立物料时继续使用 v1。需要时使用 [v2 包内物料协议](scene-s2-package-materials-v2.md)，原 v1 不增加必填字段。可选宿主依赖与声明式降级仍待实现；用户会话选图/选文件与包内物料是两种独立来源。

包是可信本地代码，在终端渲染环境内执行；当前没有不可信包沙箱。不要把命名空间或组件范围校验描述为恶意代码隔离。

## 2. 三层协议分别解决什么问题

S2 底座负责通用画布、配置和持久化、组件注册、端口及数据校验、调度、取消、结果和会话授权。交互包负责业务组件、组合规则、本地逻辑、业务校验、专用视图及 Agent 使用说明。提示词、数学、图表等业务含义不进入底座接口；新增业务优先通过现有契约表达。

1. 包接入契约：包身份、精确版本、S2 接口要求、所需宿主服务、加载入口与生命周期。
2. 组件与数据契约：能力的输入/输出端口、语义类型、字段结构、产物来源、完整性和错误。
3. 场景配置契约：用户或搭建 Agent 生成的内容块、执行节点、绑定、连线、布局和实例约束。

场景配置只引用能力与数据，不携带包代码、凭据或运行授权。当前每个场景绑定一个主交互包，并可使用底座共享能力；不做跨业务包任意拼装推理。包内组合的业务正确性由包开发者负责，宿主继续核对真实类型和执行结果。

### 2.1 按职责组织源码，再通过入口装配

源码按职责拆分，分发时合并为 main.js；两者不矛盾。开发者应先分清以下部分：

- **包身份**：manifest。供终端发现、核对版本和安装要求。它不是组件代码，也不承载 Agent 提示词。
- **公开搭建接口**：authoring 声明逻辑组件、可调参数、可接端口及本地映射。用户菜单和搭建 Agent 共用；空目录明确没有公开组件。
- **Agent 说明**：可选 describe 返回 ScenePackDescription，分发副本为归一化 agent.json。可补用途、业务组合和交互建议；不必为纯手动包手写完整手册，也不能据说明开放内部能力。
- **能力插件**：capabilities 中的 S2PluginManifest 声明，以及 executeLocal 的对应实现。声明告诉底座完整内部运行能力、端口及类型；搭建 Agent 仅看公开目录投影。实现处理一次调用的真实完整输入，生成产物。不能只写说明而没有实现。
- **运行程序**：validate 与 createRuntime 返回的 SceneInteractionRuntime。编写包的业务约束、运行编排、操作分发、取消和释放。运行器通过 host 请求画布调度；节点间类型化传输、授权和结果发布由底座完成。
- **画布交互与视图**：可选 canvas 声明内容字段的编辑位置和添加菜单分类；ScenePackCapabilityViews、ScenePackViewContext 提供设置区或节点内视图及端口展示策略。使用受控回调提交修改，不直接替换终端内部状态。help 是用户可见标签和解释，不能代替 Agent 完整说明。
- **场景配置**：用户或 Agent 生成同一种 S2PublicCanvas 公共配置；底座本地编译为完整 ScenePackConfig。保存精确包版本、公开值与连线、布局，不保存凭据或临时资源权限。示例配置应独立保存，方便检查和复用。
- **物料**：v2 的 materials 清单及同名目录存放固定资源；运行程序和视图按所属包 ID 读取。它不是 Agent 提示词、用户会话文件授权或场景配置。首版支持文本/JSON/三种静态图片；PDF、字体等类型未开放。

[数值缩放示例](../examples/scene-packs/number-scale/README.md)采用 entry.ts 只装配、plugins/scale.ts 实现能力、runtime.ts 管理业务及运行、views.ts 管理展示的结构。scene-pack.json 的 manifest/authoring 分区分别提供身份与机器公开目录；本例省略 Agent 说明，由终端生成最小归一化说明。旧包仍可提供 description。它是开发目录约定，不是要求终端直接解释这些 TypeScript 文件。

### 2.2 接口如何变成可用画布

1. 终端发现 manifest，选择包后调用同步 activate，检查接口与说明，再注册能力和视图；加载本身不运行场景。
2. 用户和搭建 Agent 使用同一个 authoring 公开目录和配置接口，本地程序映射为 ScenePackConfig。纯手动搭建不要求先调用 Agent。
3. S2 校验配置，将内容块、执行节点、真实端口和布局显示到画布，按包的 canvas 声明提供编辑入口和分类菜单。没有声明或专用视图时沿用通用编辑方式。
4. 插件包选择提供执行流程时，用户通过包内入口、明确执行请求或已配置的场景触发条件发起执行，终端才校验配置并创建/复用运行器。运行器调用 host.run，底座按执行图解析输入并调用 executeLocal 或受控宿主桥。仅编辑包跳过这一步，添加、删除、改值、接线和保存直接生效。
5. 视图修改通过回调返回文档，终端校验并重绘。编辑、拖动和查看说明不会自动触发执行，也不授予模型或资源权限。

开发端重启时可刷新由构建播种且未被本地修改的包，来源由安装根目录 `.seed-receipt.json` 的完整文件指纹确认。用户修改、无记录的安装包和已删除包均不自动覆盖或复活。需明确替换时使用 `npm run replace:scene-pack -- --root <绝对安装根目录> --seed <绝对构建根目录> --id <包ID> --version <精确版本>`，随后重启。只重新构建源码不会改变无记录的旧安装副本；渲染器也不会在活动会话中热换代码。`npm run check:scene-pack-seed-refresh` 覆盖此边界及失败回滚。

### 2.2.1 用户导入与免重启更新

桌面端“场景模拟 → 通用画布 → S2 交互包”提供“导入 / 更新”。选择下载的 ZIP 并确认来源可信后，安装至交互包目录，刷新列表，可直接用于新场景；无需重启。ZIP 可直接包含构建文件，也可包在一个外层目录内；必须包含 manifest.json、main.js、styles.css、agent.json，v2 同时携带声明的完整物料。不会执行 npm 安装或自动下载缺失内容。

发布端可使用 `npm run package:scene-pack -- <构建后的包目录> <输出.zip>`。ZIP 上限16MiB、256个文件、展开总量32MiB、单文件2MiB；各固定文件及物料仍遵循原协议更小的上限。路径、CRC、身份、物料哈希通过后才原子发布；主进程安装时不执行包代码。原生确认明确提醒：S2 是可信主窗口代码，不是 H5P 沙箱，也没有代码签名审核。

热更新采用精确版本并存，不是覆盖运行中的函数：新版需使用新的包版本号。同版本相同文件重复导入为幂等操作；同版本不同内容拒绝覆盖，旧版始终保留。已保存场景继续引用原精确版本，进度、布局及运行中调用不迁移、不取消。新建场景可立即选择新版；旧场景要采用新版需另建或明确迁移（本轮没有自动迁移入口）。能力接口变化时也必须升级其能力版本；兼容的相同能力接口可由所选包自己的本地适配器分发，新旧调用各自固定实现。加载失败可重试，不再要求重启。包 CSS 选择器按 data-scene-pack 精确版本作用域隔离；可信包仍不得直接修改宿主 DOM、注入全局资源或绕开接口，这不是恶意代码安全沙箱。

样式加载前使用 CSS AST 校验：选择器包在精确版本的 `@scope` 内，`@keyframes` / `@-webkit-keyframes` 及 CSS 中的 animation、animation-name（含前缀、局部变量及 var 回退）统一改为包版本命名空间。同名新动画不会替换旧版动画；普通文案和 URL 不改写。支持 media、supports、container、starting-style、scope 分组；charset 被移除。font-face、property、counter-style、layer、import 等可能产生全局影响的规则会明确拒绝，不静默注入。包应通过 CSS 类切换动画，不要在 JavaScript 中直接设置未改写的原始动画名称。样式验证在执行 activate、注册能力之前完成，失败不改变已加载版本。

宿主公共组件的精确身份在初始化时固定，不根据交互包声明推断归属。重复声明完全相同的公共组件不会将其私有化或替换宿主处理器；声明冲突仍拒绝。加载/撤回其他包不会改变基础画布的公共能力目录、调用范围或本局已有授权；新包自有能力也不会因此获得公共权限。

首次复制内置包时，单个包失败只保留本次诊断和可用的健康包，不写入全部初始化完成标记，也不缓存为最终成功；刷新或下次启动可重试。重试仍合并并发初始化，已落盘版本不会重新覆盖。受管收据证明某精确版本曾成功安装，其后缺失按用户主动移除处理，即使其他包尚未完成首次复制也不自动补装。成功恢复后清除旧故障提示。旧版软件若已经错误写入完成标记，则不能安全判断缺包是失败还是用户删除，仍需用户显式导入相同版本 ZIP；不会通过删除旧标记或全量重装猜测修复。

`.seed-receipt.json` 的读取失败、损坏或不可信状态不会降级成空记录，而是停止自动安装/覆盖并明确报错，恢复原记录后可重试。首次初始化已存在、但没有受管收据的迁入/预置精确版本，会在任何自动复制之前原子写入独立的 `.seed-exclusions.json`；只记录排除，不冒认所有权，其后被用户删除也不补装。排除记录读写失败同样停止自动初始化，不擅自修复或清空记录。迁移应完整复制交互包目录并保留这两个状态文件；确实损坏的状态文件需从有效备份恢复，不能以“刷新”为由重建成空状态。

`npm run check:scene-pack-install` 验证导入、旧数据保留、版本缓存、同名动画和公共组件归属；`npm run check:scene-pack-update-native` 使用隔离 Electron、生产 preload/IPC/UI、合成 ZIP 和原生弹窗替身，验证运行中旧调用、新实现、同名动画及公共组件隔离。不会读取真实学习库、调用模型或覆盖安装产物。上段 replace:scene-pack 是开发维护命令，仍然会直接替换同版磁盘文件并要求重启，不是此用户更新入口。

### 2.3 统一的机器公开组件目录

新包在入口返回 `authoring: ScenePackAuthoringCatalog`，它是用户添加菜单与搭建 Agent 共用的唯一搭建目录。`capabilities` 仍完整保留包内所有执行能力、函数、类型和依赖；不因某能力未公开就删除其运行实现。`describe()` 是可选的 Agent 辅助说明，不能扩大机器公开目录。

```ts
authoring: {
  version: 1,
  components: [{
    id: 'scale', label: '数值缩放', purpose: '将数值乘以倍数',
    group: { id: 'processing', label: '处理' },
    implementation: { kind: 'capability', pluginId: 'my-tools', pluginVersion: '1.0.0', capabilityId: 'scale' },
    inputs: ['amount', 'factor', 'label'], outputs: ['product', 'text'], parameters: ['amount', 'factor', 'label'],
    defaults: { amount: 4, factor: 2.5 }
  }]
}
```

把示例能力换成包实际声明的精确能力。`id` 是公开组件类型 ID；`implementation` 只由本地解释，不是搭建 Agent 要生成的内容。`inputs` 是允许接线的真实输入端口，`outputs` 是公开输出，`parameters` 是可改的字面量输入。`defaults` 可预设真实输入，包括未公开为可调参数的固定值；未公开的固定值不能由用户或 Agent 改写。端口类型、参数 schema、标签和必填规则由底座从已安装的精确能力契约解析，不再维护第二套 schema。

原生文字同样可公开：`implementation: {kind: 'content', blockType: {id: 'note', label: '内容', fields: [{id: 'content', label: '内容', kind: 'multiline'}]}}`，其 `inputs` 为 `[]`，`outputs/parameters` 使用实际字段 ID，例如 `['content']`。同一逻辑分组可有多种具体类型；提示词包的文字、文件、图片三种资料类型归入同一个“待测资料块”分组。

`components: []` 是有效且明确闭合的目录：没有公开可修改组件，不能回退完整运行目录。没有公开组件时可使用包已有界面及内部运行流程，不要求 Agent 选择内部能力或编写 builder/assistant/operations 手册。读取目录失败是加载错误，不能当作空目录或全量开放。

最多64个公开类型，每个 inputs/outputs/parameters 最多16项；默认值最多16项、16 KiB，完整目录最多256 KiB。拒绝未知字段、访问器、非稠密数组、重复 ID、非精确版本、错误端口和循环数据。入口规范化与安装时还会分别核对包内和实际共享能力；运行代码不会在这些检查中被探测调用。

### 2.4 用户与 Agent 共用公开配置及本地修改边界

公开搭建配置使用组件类型、实例和公开端口，不写插件实现 ID。以数值缩放示例为例：

```json
{
  "version": 1,
  "nodes": [
    {"id":"caption", "componentId":"caption", "position":{"x":0,"y":0}, "values":{"content":"结果"}},
    {"id":"scale", "componentId":"scale", "position":{"x":350,"y":0}, "values":{"amount":4,"factor":2.5}},
    {"id":"show", "componentId":"result", "position":{"x":700,"y":0}}
  ],
  "connections": [
    {"source":{"nodeId":"caption","portId":"content"},"target":{"nodeId":"scale","portId":"label"}},
    {"source":{"nodeId":"scale","portId":"text"},"target":{"nodeId":"show","portId":"text"}}
  ]
}
```

用户添加、改值和接线与 Agent 生成/修改使用相同的目录、参数及端口校验。底座本地编译到完整 `ScenePackConfig`，负责类型化数据传输和运行；Agent 不实现传输代码。原生工作区、子图导入、批量操作、包视图回调及历史恢复也不能绕过最终修改校验。只隐藏菜单或过滤 Agent 提示词不能形成边界。

包可用 `authoring.internal: {blockTypes, document}` 提供可信完整原生内部基线。它属于安装包，不能由用户场景 JSON 重新指定。内部实例按实际 ID 及基线保持；即使与某个公开组件使用相同 blockType/capability，也不能编辑、移动、删除或改接内部连接。用户自报 `public/componentId/readOnly` 不会解锁内部实例。把始终固定的内部过程封装在运行代码或该内部区，公开块之间的业务连线仍由用户或 Agent 设计。

Agent 首次只读 `id/label/purpose`，再按需读取选中类型的参数形状与公开端口。`group` 留给本地菜单分组，不进入索引、组件详情或设计审查请求；搭建上下文也不发送 implementation、内部图或完整执行清单。`describe()` 可补用途和业务建议，但不决定开放范围。互动 Agent 可依据相关任务、实际输入、真实结果与预期做指导或比较，不必获取内部实现图。

### 2.5 底座统一生成精简的 Agent 视图

底座从同一份完整公开契约生成 Agent 视图，按固定字段规则处理，不调用模型摘要，也不执行包的运行程序。所有声明 `authoring` 的包共用这一流程；开发者继续维护公开目录、真实字段和能力契约，不需要另写一份“精简版协议”或修改底座业务代码。完整契约仍留在本地，用于用户界面、公开配置编译、修改边界和运行校验。省略整个 `authoring` 的旧包继续走明确的旧协议适配，本流程不隐式迁移旧包。

Agent 的组件详情保留 `id/label/purpose`，以及始终存在的 `parameters/inputs/outputs` 三个数组，空数组也保留：

- `parameters` 列出的 ID 才能写入实例的 `values`。保留用途、取值规则、必填规则、默认值和可留空规则；`false`、`0`、`null`、空字符串默认值不能按真假省略。能力参数使用完整 `schema`；原生内容参数使用 `field` 的实际字段规则，涵盖列表数量、表单子字段、表格列类型及可空性等，不再同时重复近似的通用 schema。类型本身的独立含义通过 `typeMeaning` 保留，参数的重复类型引用留在本地。
- `inputs/outputs` 只声明可连接的端口，不会因出现在这里而开放字面量编辑。保留端口含义、`required`、`multiple`，类型引用写成精确的 `id@version`；相同结构的不同语义类型不会合并。端口为空与参数是否可编辑是两件独立的事。
- 参数或端口的 `label` 与自身 `id` 完全相同时，可省略这份重复标签；统一说明约定缺省标签就是 ID。组件名称和用途仍保留，方便独立请求理解当前组件。

首轮只发完整的轻量索引。搭建轮按本地选中集合携带已读详情；允许补读时，选择索引只包含尚未读取的组件，没有补读机会时不再发送索引。已读 ID 台账、剩余调用次数及读取预算在本地管理，Agent 只需知道本轮能否补读。每次搭建、修复和显式审查请求仍携带该轮所需的原任务、目标、当前公开画布及已读接口；不假定模型自动记住上一请求。

精简只删除搭建无关信息与重复表达，不扩大公开字段权限，也不改变本地校验。开发者应在字段、类型和端口声明中准确表达用途与限制；底座不会从执行代码或自然语言说明猜测并生成新的限制。

旧包**省略整个 authoring 字段**时走明确的旧协议适配，保留原 native 配置、说明读取及 canvas.addMenu 行为；这与显式 `authoring.components: []` 不同。旧 `describe().components[].capabilities` 只是说明层推荐能力，不是新机器公开边界。开发新包应声明 authoring；不要依赖缺字段来开放内部实现，也不要把新公共接口测试放到旧兼容 fixture 中。

### 2.6 组件身份、错误修复和可选审查

公开配置的 `componentId` 会由本地编译器写入内容节点和执行节点，并随保存、导入导出、复制及历史恢复保留。`label` 仅用于显示，改名不会换组件。开发者仍只维护 authoring 目录，无需另一份身份映射；这个可选元数据不进入能力执行协议。终端按精确包版本核对组件、真实实现、公开参数和端口，不能凭自报 componentId 解锁未公开或内部实例。已有身份的只读内容实例也不能更换或删除身份。

旧节点缺少身份时，仅在实现和公开约束唯一对应，或默认标签能唯一对应一个候选时兼容识别；本地准备公开会话时补齐身份。无法唯一确认时报 `PUBLIC_COMPONENT_AMBIGUOUS` 并保留原数据，不再默认选择第一个候选。已丢失的身份不能从自定义名称自动恢复。

可修复的配置错误由本地生成 `repair.issue:{code,path,reason}`，路径使用 `/canvas/nodes/...` 或 `/canvas/connections/...` 等公开位置。该次修复请求同时携带有界完整的 `repair.candidate` 公开画布，保留正确文字、节点、位置和连接；未知元数据和未公开参数值不进入候选。修复仍返回完整公开配置并重新校验，不通过则不提交。内部基线、安装或体积超限等无法由搭建 Agent 修复的问题直接停止。正常请求不添加修复上下文；JSON 语法修复继续使用原有的完整 previousOutput。

`designS2Canvas` 默认仍为选择组件、生成配置两轮；仅调用方明确传 `review:true` 时增加一轮设计审查。审查检查目标表达及参数、连接用途，不运行场景。一次审查驳回后可重新生成并复查，所有补读和修复都计入原调用预算：默认最多四次，开启审查最多六次。界面不会因此增加确认弹窗。

`npm run check:scene-s2-authoring-fixes` 通过真实搭建入口和独立通用测试包检查身份往返、旧数据歧义、公开修复候选、可选审查及失败原子性；不调用真实模型或用户资料。

## 3. 交付文件与加载入口

安装目录：`<终端用户数据目录>/scene-interaction-packs/<包ID>/<精确版本>/`。

```text
my-package/1.0.0/
  manifest.json
  main.js
  agent.json
  styles.css
  package.json     可选，构建工具可生成 ESM 标记
  materials/       v2 按清单声明的物料文件
```

Electron 必须能读到前四个文件，`styles.css` 可以为空。`main.js` 必须是导出 `activate(services)` 的单文件浏览器 ESM；入口应同步返回包对象。当前加载器不等待异步 activate。

包的运行依赖应编入自身产物，不在入口保留指向终端源码、Node.js、外部 React 或其他相对模块的运行时导入。React 使用 `services.ui.react` 注入的宿主实例；不要再打包第二份 React。TypeScript 的类型引用可在构建时消除。

提示词参考包的 React 转接文件目前只转接 `createElement / Fragment / useState / useRef / useEffect`；这不是完整 React SDK。开发者若复用其构建方式，需要明确处理额外 Hooks 和自动 JSX runtime，不能直接假设转接文件已经导出了全部 React API。

`agent.json` 应与归一化的 `describe()` 同源生成。显式 authoring 的开发者可省略 describe，构建器据机器目录生成最小说明，不要求手写完整 Agent 手册。当前 Electron 对此文件只做 JSON 语法检查；旧兼容搭建流程按需读取加载后的 `describe()`，新公开搭建流程只读取 `authoring` 的公开投影，辅助说明不会自动全文注入。修改 agent.json 不单独覆盖运行接口。Web 预览由宿主提供独立资源索引，不能据此要求每个包自己实现发现服务。

两端文件限额尚未统一。计划同时用于 Electron 和 Web 的包，采用共同下限：manifest 不超过 8 KiB，主代码不超过 512 KiB，CSS 不超过 64 KiB；桌面端 agent.json 不超过 256 KiB。Web 当前不读取 agent.json。这里是跨端交付建议，不代表两端已经使用统一限额实现。

桌面端已提供 ZIP“导入 / 更新”和精确新版本的免重启加载，见2.2.1节。新版与旧版并存，正在运行的场景不热换实现，已有场景仍引用原精确版本；没有在线市场、自动版本迁移或完整的图形化移除管理。直接手工复制版本目录、移除目录或使用开发维护命令替换同版文件时，需重启以重新发现，不能与用户 ZIP 更新混为一谈。

## 4. 清单：必需字段与版本规则

```json
{
  "protocolVersion": 1,
  "id": "my-package",
  "version": "1.0.0",
  "name": "我的场景交互包",
  "paradigm": "S2",
  "paradigmApiVersion": 1,
  "requiredServices": ["execution"]
}
```

v1 读取器要求恰好这七个字段，拒绝未知字段及不受支持的版本。不要向 v1 擅自添加 `assets`、`materials`、`optionalServices` 或版本范围。v2 恰好多一个 materials 字段，完整规则见独立物料协议；paradigmApiVersion 仍为 1。

- `protocolVersion`：1 为原核心包，2 为带物料声明的包；表示包接入格式。
- `paradigmApiVersion`：当前为 1，表示 S2 接口版本；与包自己的版本分开。
- `id`：小写字母开头，仅包含小写字母、数字和连字符，最多 64 字符。
- `version`：严格的三段数字精确版本，不接受 `latest`、范围或预发布后缀。
- `requiredServices`：当前只接受 `execution`、`model`、`resources`，按需列出，不代表已经获得运行授权。

“包要求宿主提供什么”与“包提供哪些组件和操作”分开声明。完整执行实现放在包级 `capabilities`，公开搭建范围放在 `authoring.components`，可选辅助说明放在 `describe()`；不能把组件名称填入 `requiredServices`。

`requiredServices` 字段不可省略，可以是空数组。当前 `execution/resources` 声明尚未接入完整的宿主可用性协商，`resources` 也不向 activate 注入独立资源服务对象；不能将这些声明解释为资源提供器注册或任意文件读取授权。

## 5. 包对象：核心必需与选配

开发者的 `activate(services)` 返回 `SceneInteractionPackDefinition`；终端校验后得到有归一化 describe 的 `SceneInteractionPack`。必需运行成员为：

- `manifest`：与分发清单一致的身份和接口声明。
- `authoring`：新包声明机器公开组件目录，可为空；旧包省略时使用明确兼容路径。显式声明后 `describe()` 可省略；若提供，仍按完整说明格式校验。
- `capabilities`：包提供的精确版本能力声明数组。
- `validate(config)`：返回 `{path, message}` 问题列表，空列表表示包级业务校验没有发现问题。
- `executeLocal(call, inputs, signal)`：处理已声明的本地能力，返回严格的 `S2PluginOutcome`。
- `createRuntime(config, host)`：返回 `updateConfig / dispatch / run / dispose`。

`views`、`help` 和包级 `canvas` 声明为选配。不提供专用设置视图时，可使用已有的通用参数编辑方式；不声明 `canvas` 时保留终端原有画布行为。

即使一个包不需要本地执行，当前接口仍要求 executeLocal 存在；未支持的调用应明确拒绝。不要把全部函数改成可选来减少代码。后续可以提供公共辅助实现，减少标准运行器和校验的重复代码；当前尚无独立发布的默认运行器 SDK。

统一校验入口为 [sceneInteractionPackProtocol.ts](../src/services/scene/sceneInteractionPackProtocol.ts)。加载、注册和能力安装会在发布前检查必需函数、能力清单、authoring 及可选 describe 的结构，以及 views/help/canvas 元数据。说明在注册时固定为已校验快照，describe 每次返回新数据，不能靠后续修改原对象改变已注册说明。实际创建运行器时检查四个方法；实际 run 返回时检查任务 ID 和 completion，保留原完成 Promise，不等待任务来判断接口是否有效。

校验失败抛出 `ScenePackProtocolError`，包含稳定的 code、path 和可读 message，例如 `/describe/components/0/configuration`。这些检查不会探测执行 runtime、dispatch 或 executeLocal。完整业务正确性仍由包开发者负责，依赖/类型/实现绑定及执行产物继续由 S2 安装器和执行宿主核对。

## 6. 运行与数据传输

新增本地能力只能是无权限的纯 transform/validator；宿主会验证其能力清单与数据类型、依赖和实现绑定。

自定义 `dataTypes[].id` 必须属于声明该类型的插件命名空间，即以 `插件ID.` 开头。例如插件 `text-echo-demo-logic` 可以声明 `text-echo-demo-logic.text`；不能只按包 ID 或公开组件 ID 命名。端口类型引用使用同一个 ID 和精确版本；归属不符会在激活验包时以 `PACK_CONTRACT_CAPABILITY` 拒绝。

`executeLocal` 应使用宿主提供的完整 inputs，不修改输入，不读取终端内部状态，不自行发起模型/文件/网络调用。产物必须包含声明的类型、完整性、当前调用的 scene/run/node/revision/invocation 来源及实际载荷。不能仅返回业务对象冒充完整产物。具体结构以 `S2PluginOutcome`、`S2Artifact` 为准。

inputs 是按端口 ID 索引的已解析值数组，类型为 `Record<string, S2Json[]>`。成功产物 ID 必须唯一；失败返回空 outputs 及错误信息。数据 schema 使用 S2 当前支持的有界方言，不能假定支持完整 JSON Schema。reference 载荷不提供上传或任意句柄创建；v2 包物料通过独立 context.materials 读取，不能冒充用户文件或大文件引用。

同一语义类型 ID 和版本应有一致的结构契约；相同 JSON 形状并不自动兼容。类型转换用显式能力，不猜测或隐式转换。

模型组件需同时声明 model 宿主服务，并严格符合 `model-session@1`：prompt/input/image/maxOutputTokens/temperature/thinkingMode 输入及 text 输出，连同副作用、重试和超时约定。业务组件 ID 可自定，不能改变模型桥的 ABI。提示词包的用户测试入口读取点击时的当前输入和参数，次数、长度及超时由程序处理，不再要求准备预算或逐次核对发送。

包内运行器可为一次明确测试补上直连的只读结果展示节点。底座保留一次同步调度的动作授权；扩展仅限无权限、无输出、无副作用且全部输入来自原执行图的 renderer，不允许夹带其他模型、工具、转换、条件或新上游。其他目标变化仍走原执行校验和授权，不因包内排版或结果展示自动增加模型调用。

正式运行入口会在创建/运行包运行器前，对当前配置快照做 S2 结构检查及包的 validate，检查返回的问题列表，非空则阻止本次运行。校验不会自动修复场景，也不会阻止用户保存未完成草稿。直接使用 createRuntime 的开发者仍应在运行器内读取当前配置并校验；更新配置先完整检查，再提交变更。

宿主提供配置快照、结构校验、受控配置写入、图运行、取消、结果读取和关闭服务。当前画布主要向包提供运行服务，配置写入回调是否开放取决于接入入口；不能假设每个入口都允许 updateConfig 修改整个场景。

具体到正式画布运行入口，`enqueueSceneInteractionWorkflow` 当前未提供 applyConfig 回调，因此 `host.applyConfig` 会拒绝写入。画布编辑应通过视图的 `onDocumentChange / onInputChange` 提交。终端也不会在每次画布编辑后自动调用 runtime.updateConfig；运行器应在每次 run 时读取 `host.readConfig()`，校验本次实际配置，避免使用初始化闭包中的旧配置。

取消及 dispose 应停止本包工作、移除监听并释放临时状态，不恢复已消耗预算或旧授权，不发布结束后的迟到结果。副作用不随画布撤销而撤销。

### 6.1 两种交互 Agent 响应共用公开动作接口

具有 `authoring` 目录的包使用统一交互协议 v1。未提供目录的存量包保留原解释及画布修改适配；旧式运行或插件请求会明确提示使用包内入口，不留下没有操作入口的待确认项。用户发送文本时，以 `origin: 'user'` 和原消息作为 `task` 调用助手。自动响应使用 `origin: 'event'`，只匹配场景显式配置的规则；打开、编辑、渲染或单纯测试成功均不会凭空增加助手调用。普通结构解释一次请求即可完成；允许两批必要补读及一次格式/公开动作修复，总计最多四次模型请求，不自动重试执行失败。

场景定义的可选 `interaction` 配置由搭建 Agent 随 `canvas / instructions` 返回，或随工作区保存。它属于场景设计，示例中的节点 ID 必须是本场景已有的公开执行节点：

```json
{"version":1,"triggers":[{
  "id":"explainTest",
  "on":{"event":"s2.node.succeeded","nodeId":"test"},
  "task":"对照本次真实输入和返回解释结果，不改写内容。",
  "scope":{"actions":["reply"],"nodeIds":["test","result"]}
}]}
```

`scope.actions` 为 `reply / edit / execute`，省略时仅允许回复；`nodeIds` 省略表示当前场景全部公开节点，显式 `[]` 表示没有节点，不能当作省略。自动响应不能扩大这个范围。底座内置 `s2.node.succeeded / s2.node.failed`，只由真实执行记录产生；终端保留精确调用身份，避免把另一次测试的输入或结果用作本次证据。原始内部诊断不会直接塞入模型上下文，未公开的失败原因明确标为不可用。

包需要业务事件时，在入口返回独立的可选分区，并由运行程序调用 `host.emitEvent(nodeId, eventId, data)`：

```ts
interaction: { version: 1, events: [{
  id: 'my-pack.answerReady', purpose: '业务回答准备完成',
  dataSchema: { kind: 'object', fields: { summary: { kind: 'string', maxLength: 500 } }, required: ['summary'] }
}] }
// 运行程序，参数 nodeId 为当前场景公开实例。
host.emitEvent?.(nodeId, 'my-pack.answerReady', { summary: '本次业务结果摘要' });
```

事件 ID 必须使用当前包 ID 的命名空间，不能伪造 `s2.*`；声明非空业务事件目录的包必须同时提供 `authoring`。底座检查公开来源、事件声明和数据结构，排队、去重并阻止同一因果链重复触发；场景变化、因果链取消或结束后丢弃旧任务。事件数据由包负责选择必要业务内容，不能借事件载荷复制整个运行目录或无关物料。每包最多16类事件、每场景最多16条规则，单次事件数据最多32 KiB。

模型只返回 `reply`、`actions` 或 `read`。`reply` 是对话文本，不能替代真实执行状态。交互 Agent 首轮对所有包统一使用渐进式披露：`componentIndex` 只含 `id / label / purpose`；画布只给实例、位置、连线和参数值的 ID/长度索引；实际正文、已有结果、自动事件输入和业务事件载荷均不自动发送。选中节点及历史消息不能解锁接口。包用途超过160字符时只提供包名称及长度索引，完整用途随业务说明读取。场景策略和少量近期对话保留。

读取粒度由任务决定：解释结构通常无需接口正文；修改一个值只需该参数的完整规则，接线只需来源输出和目标输入的完整规则；默认添加不带配置的公开块只需类型索引。字段 ID 不明确时，先读成员索引，再选择所需字段。只有检查/配置整套组件或确实需要其全部接口时才读 `componentIds`；业务组合说明也按需读取，开发者无需维护第二套短说明：

```json
{"read":{"interfaces":[{"componentId":"model-test","parameters":["temperature"]}]}}
```

`interfaces:[{componentId}]` 仅返回该组件的 `interfaceIndex`，包含 parameters/inputs/outputs 的 ID 与标签，不能用于写值或接线。带选择器时，底座在 `interfaces` 返回 `representation:'selected-interface'` 及所选字段的完整规则；未列出的详情是未读，不能理解成不存在。完整读取成功才放入 `components`。原生 field/schema 的全部限制、默认值、精确端口类型及多路/必填规则保持原样；不摘要或截断限制。只要成功读取字段或端口，就附统一 `componentRules`。`parameters` 可写入 `values`，`inputs / outputs` 仅用于连线，空端口数组不关闭参数编辑。

读取实例正文可用 `values:[{nodeId,parameterIds:[id]}]` 精确选择参数，`nodeIds` 仍兼容完整节点读取；结果及真实事件输入按 `resultIds` 读取，`eventData:true` 读取范围内业务事件载荷，`packageInstructions:true` 读取完整业务说明。读取值、正文、业务说明或成员索引均不会解锁参数/端口规则。后续 `actions` 使用同一公开搭建接口，例如：

```json
{"reply":"按你的要求调整文字并测试。","actions":[
  {"type":"setValues","nodeId":"prompt","values":{"content":"调整后的提示词"}},
  {"type":"run","targetNodeIds":["test","result"]}
]}
```

公开动作支持 `addNode / setValues / removeNode / connect / disconnect / run / cancel`。`addNode.node` 使用公开节点结构；连线使用真实公开 `nodeId / portId`；`cancel.runId` 只能引用范围内当前运行。新增时填写的参数、`setValues` 的每个参数，以及连接来源输出口/目标输入口，都必须在本次请求中成功读取对应完整规则，不能用同组件其他已读字段替代。公开默认块可直接按索引新增，本地编译器填入包默认值。未公开字段、内部节点、只读原文以及超限值仍在本地拒绝。删除节点、运行既有图和取消不增加接口读取前置步骤。一次最多12项动作、每次运行最多8个目标；完整预检后连续编辑一次提交，再按顺序运行。失败停止后续动作，已完成的执行及结果保留，不回滚真实副作用。

`read` 的完整/局部组件合计最多8类，完整/局部实例合计最多4个，结果最多3项；每类参数/端口选择最多16项。单批披露共用12000字符额度，累计两批最多24000字符，包含成员索引、完整字段限制、统一规则、实例正文、结果及业务说明。放不下的整项标为 `unavailable`，不解锁接口；较大组件完整读取失败后仍提供成员索引，可在下一批只读所需字段。单个字段本身仍超额时明确不可用，不以残缺限制操作。重复成功读取且没有新内容会被拒绝。补读及修复保留原任务、范围、近期对话和已提供资料；空的可选字段省略。

结构解释可一轮完成；已知字段 ID 的修改通常为一次局部补读后执行，不明确时为成员索引、所需字段、执行三轮。运行代码、完整能力清单、私有绑定、授权凭据、缓存和调度细节继续留在本地。所有包经过同一个底座投影，包格式及既有完整说明无需修改。

包负责业务事件、业务策略、组件参数和视图；场景负责触发条件、任务及作用范围；底座负责调用模型、公开投影、解析、校验和执行。此路径不新增通用确认面板，也不自动授予文件或模型权限，包内直接操作仍可独立使用。保存/导出会清理已删除节点的触发引用；当前编辑历史保留原规则以支持撤销恢复。

对应类型为 `src/types/sceneS2Interaction.ts`；Protocol 解析协议，Disclosure 管理分层读取、额度及逐字段/端口已读状态，Interaction 组织模型调用，Events 分发触发任务，Actions 校验并执行公开操作，Metadata 处理保存快照。运行 `npm run check:scene-s2-interaction` 检查这些边界及提示词包的合成流程。

运行 `npm run inspect:scene-s2-interaction-context` 可重现同五块提示词场景的字符测量；源码 fixture 保存真实改造前请求，`output/scene-s2-interaction-context-inspection/` 输出冻结前值、当前原文和逐轮对比，`progressive-v1/` 保留中间阶段572系统字符+1865输入字符的证据。旧修改请求只按冻结原请求替换同一 task 重建，未执行旧引擎；字符统计均为实际紧凑 JSON 的 `string.length`，不是 token 或真实模型质量验证。

### 6.2 最小常驻提示与按需动作格式

系统提示由底座按每轮实际状态生成，不再发送固定完整方法清单。保留任务/策略/scope、当前可用的输出字段、正文与字段规则的区别、逐参数/端口已读边界和简短事实判断原则。当前值和真实记录优先，名称不证明实际界面，配置不证明现实事件；只解释时不操作。自由文本是否符合事实不能完全由本地格式校验替代，因此保留这些原则并合并举例。

`InteractionPrompt` 依据可信的公开投影、scope 和本轮已读状态裁剪说明：没有结果索引就不提供 resultIds，没有范围内自定义事件载荷就不提供 eventData，已读说明/正文不重复介绍，读取额度耗尽时去掉 read 输出和写法。首轮以 interfaces 局部规则和 values 局部正文为主；发现成员索引后才介绍 componentIds 整套接口，在读过局部值且还有未读值时才介绍 nodeIds 整块内容。局部方式仍可继续读取，不要求升级整项。

仅回复范围不提供 actions；限定既有节点时不提供新增；存在可删除节点、已有连线、可执行节点或当前可取消运行时才提供对应写法。可新增范围内，读取到执行组件后仍可同批新增并执行。连线说明只针对范围内实际或允许新增的同类型公开端口组合。裁剪不靠用户消息关键词猜意图，也不把被删说明搬进输入。所有包复用这套本地投影，开发者继续声明完整公开参数及限制，无需另写精简协议。

数量和调度规则留在本地，包括每次动作/目标数量、补读批数、调用次数、正文额度、类型和只读校验、执行顺序及取消归属。系统只显示当前剩余读取机会；超限时由本地返回具体额度供修正，不每轮讲述完整执行程序。

删除节点、断开画布已有公开连线和新增默认块可在当前范围内直接请求，保留一步操作能力。`setValues`、带 values 的 `addNode` 及新建 connect 的嵌套写法在成功读取相关参数或端口规则后，才放进 `context.actionGuide`：参数规则附写值格式，端口规则附接线格式，且继续按 scope 裁剪；guide 已提供的新增写法不在系统中重复。删除现有连线不引入新字段或数据，无需为断线重复读取端口，但本地仍核对真实连接存在、公开范围及只读约束。概览、正文、结果和业务说明读取不解锁编辑字段。动作格式不增加权限，其字符计入补读额度和测量；语法修复引用当轮已有写法，不重发无关动作，也不解锁字段。

字段的完整 field/schema、默认值、必填/多路、精确类型及统一字段说明保持原样，未通过语义摘要来压缩。系统预算回归检查同五块示例首轮不超过700字符，仅用于开发检测重复增长；不在运行时截断提示词，也不发送该测试预算给 Agent。

交互 Agent 理解的是当前公开配置，不是屏幕截图或完整操作录像。节点索引列出的字符数不等于正文，具体内容通过 `read.values` 或 `read.nodeIds` 按需读取；手动修改后，下一轮以当前文档及补读值为准。`goal` 是声明目标，历史是过去表达；`id / label` 是标识或可选名称，不能覆盖当前参数与连线。完整节点视图由本地包绘制，label 不保证是屏幕上的实际文字，因此不据旧标签声称“界面显示错误”或增加同步名称流程。没有提供运行、保存或界面操作证据时，助手应说明无法确认，不能由结果缺失推断从未运行，也不能由配置存在推断已经保存。事故树等条件关系不构成现实事件已经发生的证据；用户仅请求解释或检查时不擅自修改或执行。

### 6.3 是否提供执行流程由本地插件包决定

入口可返回 `execution: 'none' | 'on-demand'`。`none` 表示仅编辑/建模，不提供用户或 Agent 的执行流程；`on-demand` 表示按需执行，省略时保持旧包行为。它是可信本地包的顶层策略，不是场景、manifest 或 Agent 可写字段。使用示例构建工具时可在 `scene-pack.json` 同名顶层字段声明，并在 activate 返回同值。`requiredServices` 只描述底座依赖，不能据此强制添加运行入口。

```ts
return { manifest, authoring, execution: 'none', capabilities, validate, createRuntime, executeLocal, views };
```

底座将仅编辑包的执行摘要交给搭建/交互 Agent，并去掉交互范围中的 execute；本地动作预检即使收到 run/cancel 也拒绝整批，不允许编辑后偷偷追加执行。包视图的 execution.enabled 为 false，公共工作流入口及 host.run 同样拒绝，不能只靠隐藏按钮或提示词限制。旧包及显式 on-demand 包仍使用必要的类型校验、调度、结果及取消服务。

所有包的普通编辑指令默认只编辑画布。用户说“添加事件”“删除该节点”“连接到这个门”“只断开这条线”即可，不需要补充“不运行”。on-demand 也不意味着每次编辑后必须执行；运行只由包内业务入口、明确的执行任务或配置好的场景触发决定。底座不再在通用画布标题或添加菜单附加“编辑后再运行”提示。必要的确认仍按实际操作契约处理，不把普通图编辑变成执行确认流程。

事故树最简包声明 none：结构关系已经由当前事件参数和连线表达，无需运行生成或确认。编辑与保存不创建运行器、不调用 executeLocal；不完整结构可以提示但仍允许草稿保存。包保留当前协议要求的运行接口形状，其运行方法明确拒绝启动。低层纯能力及序列化测试可单独验证类型传输，但不代表向用户开放了运行步骤。若以后增加概率计算等业务，应由包明确提供相应执行策略、业务实现与入口。

提示词包显式声明 `execution: 'on-demand'`。编辑提示词、修改结构和连线只更新配置；用户点击测试节点内的“测试”，包通过 `context.execution.run` 请求测试节点及关联结果节点，底座收集上游提示词/资料、校验并执行，必要的模型授权沿用既有规则。Agent 收到“修改提示词”只改值，收到明确的“用当前提示词测试资料”才可在范围内请求执行。测试结果在包设计的结果节点展示，不增加底座统一运行按钮或先启动试验的步骤。

## 7. 界面、物料与扩展的边界

`views` 按 `pluginId/capabilityId` 提供 settings、inline、node、本地 onDoubleClick 和可选 policy。policy 控制真实端口的显示、位置、标签、入口操作及节点内结果展示，不创造未声明的执行端口。

settings/inline/node 是可调用视图，onDoubleClick 是本地用户手势回调，policy 是返回 ScenePackViewPolicy 的函数。底座会在实际使用 policy 时检查端口、动作和返回结构；非法策略不生效，并在节点显示带 code/path 的错误，沿用通用端口展示。回调不会为校验而被执行。

视图应通过提交回调修改配置，通过 guard 与输入来源标识处理旧回调；包不能绕过原子校验、公开边界、只读或授权。`editable` 表示当前实例可编辑，独立于 `active` 生命周期：内部只读视图仍可保持活动并读取包物料，不能提交修改。临时 state 按包/场景/节点隔离，不保存为模板。显示名称、说明、端口别名及固定字面量的展示策略可通过 help 提供。

### 7.1 由包声明编辑入口与添加菜单

在 `activate()` 返回的包对象上提供可选 `canvas: ScenePackCanvasPolicy`；它属于界面声明，不放入 manifest、Agent 说明或场景 JSON。例如：

```ts
canvas: {
  contentEditing: 'double-click',
  openSettingsOnSelect: false,
  contentSettings: 'hide',
  addMenu: {
    contentLabel: '内容',
    groups: [
      { id: 'processing', label: '处理组件', capabilities: [
        { pluginId: 'my-tools', pluginVersion: '1.0.0', capabilityId: 'process', defaults: { value: 2 } },
      ] },
      { id: 'results', label: '结果展示', capabilities: [
        { pluginId: 'structured-view', pluginVersion: '1.0.0', capabilityId: 'text' },
      ] },
    ],
    otherCapabilities: 'show',
  },
}
```

把示例 `my-tools/process` 替换为包内实际声明的能力；也可引用终端实际提供的共享能力。`contentEditing` 可为 `panel`（设置区编辑）、`inline`（节点内编辑）或 `double-click`（双击节点进入编辑）；它针对通用内容字段，不依赖角色、任务等业务名称。`openSettingsOnSelect` 决定选中节点时是否自动打开设置区，`contentSettings` 用 `show/hide` 决定是否显示内容设置区。未声明的部分沿用终端原有行为；但设置 `contentSettings: 'hide'` 时，必须同时显式声明 `contentEditing: 'inline'` 或 `'double-click'`。隐藏设置区又选择 `panel` 或省略编辑位置会丢失编辑入口，包校验会在 `/canvas/contentEditing` 拒绝该组合。

运行、状态、停止和结果展示入口由插件包设计。底座不再提供顶部通用运行按钮、运行核对面板、组合/批量运行入口或 Agent 请求的通用执行确认按钮；包的用户操作通过 `context.execution.run(targets)` / `cancel()` 调用宿主服务，不因缺少包内按钮而回退通用运行面板。场景只需编辑建模时可以没有执行按钮；需要主动执行的包必须在交付验收中验证自己的入口、运行反馈及必要的停止交互。底座仍保留调度、类型与输入校验、取消、结果、错误、资料范围及实际人工输入/模型请求确认。

旧 `executionUi: 'panel' | 'inline'` 字段仅为读取存量包元数据而保留，已经弃用；省略或填写任一值都不恢复通用运行面板，新包不再声明。过去依赖面板的包必须增加自己的视图入口。样例 number-scale 提供“计算”按钮，material-study 提供“计算均分”按钮；两者通过宿主服务运行当前节点及其已连接下游。提示词包继续使用自己的“测试/停止”与结果块。

底座不再要求先点击“开始试验”。包内执行、首次选择资料、发送用户消息均可直接使用，相应操作按需建立本局运行会话；打开、渲染、选中或编辑画布不创建会话、不请求模型。资料选择仍只授权和绑定，读取与执行继续经过各自校验；结束、离开或切换场景后旧操作失效。

底座也不提供“结束试验”按钮，不以本局正在运行锁定 S2 的返回或页面切换。用户返回、切换场景或画布卸载时，由本地生命周期自动取消未完成的执行和助手请求、关闭运行器及本局授权、释放临时资源并作废旧回调。晚到结果不能覆盖当前场景，重新进入按新的本局处理；包无需另加“先结束再退出”的流程。单个任务的停止按钮仍可由包按需设计。自动清理不代表自动保存模板或未提交草稿。

未显式指定 `openSettingsOnSelect` 时，具有 node、inline 或 settings 自定义视图的能力节点默认只选中，不自动打开通用设置区；节点内编辑的普通内容块也只选中。其余节点保留默认设置入口。包可显式覆盖该策略，用户也可通过“节点设置”手动打开，或由包调用 `focusSettings()`／`navigate()` 定位具体设置。

助手常驻画布右侧，没有全局开启／关闭、允许编辑或允许执行开关。具有公开目录的包按第6.1节处理用户消息和已配置的自动事件；未提供目录的存量包保留原适配。正在进行的单次请求可以停止；这只取消该请求及其尚未完成的执行，不关闭助手或影响后续对话。编辑和渲染不会触发模型请求。

块与连线的选中、删除和操作历史由底座统一处理，包无需另写删除面板或撤销按钮。选中后用 `Delete`／`Backspace` 删除，`Ctrl/Cmd+Z` 撤销，`Ctrl/Cmd+Shift+Z` 或 Windows `Ctrl+Y` 重做；编辑输入框、文本域及富文本时交给原生文字操作。删除会清理关联连线并一次记录历史，仍受固定只读内容约束。

`addMenu.contentLabel` 命名内容分组，终端在其中列出当前场景真实的 `blockTypes`。`groups` 对可组合执行能力分类，使用精确的插件 ID、版本和能力 ID，不能填内容块类型或 editor 能力。同一能力只能归入一个组；最多8组、合计64项引用，组名与标签不超过120字。未列能力默认仍显示，只有 `otherCapabilities: 'hide'` 才隐藏其添加入口。

能力引用可带可选 `defaults`：以真实输入端口 ID 为键、原生 JSON 为值，添加节点时统一变成 `literal` 绑定。上例要求 `process` 实际声明 `value` 输入；提示词包用相同接口预设组装标题和分隔符。每项最多16个输入、完整 JSON 16 KiB；拒绝访问器、稀疏数组、循环和超限数据。能力引用不另接受 `bindings` 字段，`defaults` 内形似字段引用的 JSON 也只作为字面量数据；添加时仍完整校验类型、文档及本局能力范围。未声明 `defaults` 时沿用原空配置；精确能力身份及去重规则不包含预设值。

这些设置只组织界面：新 authoring 包的可添加类型由统一公开目录决定，canvas.addMenu 仅作为旧协议菜单适配；隐藏菜单项不构成权限边界，不删除已有节点，也不授予模型、文件或插件执行权限。节点配置、只读与运行授权仍由底座核对。包声明会按普通对象、稠密数组、精确能力引用及32 KiB总量校验，不执行声明中的代码；未知字段、访问器及重复项均拒绝。实现见 [scenePackCanvasPolicy.ts](../src/services/scene/scenePackCanvasPolicy.ts)。

提示词包的当前选择是 `double-click / false / hide`：内容块双击后在节点内编辑，普通文字失焦或按相应提交快捷键后经校验更新，Escape 取消本次编辑；普通单击只选中，不弹出属性面板。添加菜单只提供“内容块、提示词组装块、提示词测试块、结果展示块、待测资料块”五类。组装块默认角色、任务、输出要求三个入口，来源通过画布连线或字段绑定表达；结构小编辑区只改标题与分隔符。模型参数常驻测试节点，点击“测试”即发送当前提示词、资料及参数，节点内显示短状态并可停止，不打开预算、运行队列或发送确认面板。原文只在结果块展示。这是包的界面选择，其他包仍可使用 `panel`。

待测资料的文字、文件和图片是同一逻辑类的不同输入方式。手填文字复用 `text/content` 块，`label` 为“待测资料”，字段连接测试 `input`；只有需要文件或图片时才选择现有 `local-material/read-text` 或 `read-image`，通过 `resourceInput` 承接宿主原生选择控件，不另外创建业务块类型或授权流程。

旧 `bind/render` 只兼容存量场景，不进新菜单或主动搭建。旧 `render` 若引用内容块作为模板，包内 `TemplateControls.tsx` 只提供定位原块的入口，正文统一在原块编辑；字面量模板仍可在旧节点内编辑。

普通内容字段修改只更新本地文档、撤销记录和控件事件，不合成为用户聊天消息，也不自动请求 Agent 或运行节点。结构化字段仍保留必要的草稿、校验和提交；真实聊天与人工输入步骤使用各自的交互流程。

选中节点与连线的 Delete/Backspace、Ctrl/Cmd+Z 撤销及 Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做由底座处理；文本编辑焦点保留原生输入快捷键。包无需再实现一套删除或历史按钮。

### 7.2 节点显示与用户操作的通用接缝

`ScenePackViewPolicy.inputLabels` 可按真实输入端口 ID 提供本次显示标签，最多16项，每项1至120字；它不重命名端口或改变绑定。`showResult`、`showStatus` 是可选布尔值：完整 node 视图默认自行展示结果和普通运行状态，不附加宿主重复区；普通卡片默认使用原展示，显式值优先。`showResult: false` 隐藏该节点的宿主结果预览和全文按钮，输出、已记录产物及诊断读取保持原规则。错误、等待、取消和结果过期等必要反馈仍保留，开发诊断可显式查看。提示词包在组装、测试和资料节点隐藏重复结果，只由结果块展示。这些字段同样适用于第三方包，不需要底座判断提示词组件 ID。

`genericSettings` 控制宿主业务参数编辑区：存在完整 node 或 settings 视图时默认不重复生成；其他情况保留默认参数区。包可显式设为 true，组合自有说明、按钮和宿主参数编辑器；设为 false 则由包负责提供需要的编辑入口。这些界面字段只在本地 policy 中声明，不进入 Agent 协议。

`context.results` 提供当前节点脱离宿主状态的快照 `{ status, stale, artifacts }`，供完整视图绘制结果。产物只属于该节点，过期时 artifacts 为空，不能把历史结果作为当前成功结果。该快照不暴露 Host 或执行权限。

节点视图的 `ScenePackViewContext.execution` 提供可选的 `running / status / error / cancel()` 以及 `enabled / run(targetNodeIds?)`。包按状态显示短反馈、禁用重复运行，用户主动点击时调用 `guard()` 后运行或停止；不要在渲染或自动 effect 中执行。宿主检查当前场景、文档、目标、重复运行和程序限额。提示词测试按钮就是本次请求的用户动作，Agent 仍通过终端用户入口发起运行，场景 JSON 不新增授权字段。

可选 `resourceInput` 是宿主已经绑定当前节点、本局资源范围和生命周期的原生控件，支持文本文件、图片与项目笔记。包在 node/inline 视图内直接嵌入收到的 React 节点，并在 policy 显式返回 `resourceInputInView: true`，宿主才停止重复呈现；省略或 `false` 时在原节点保留原生控件。标记本身不能代替实际视图，也不授予资源权限。项目笔记选择在同一次用户操作中完成本局允许与节点绑定，不要求先到全局面板授权、再回节点选用；绑定失败撤回本次新建授权，不读取正文。

槽位承接原有文件/图片选择与撤回，不是新的读取 API。原生控件使用冻结的资源专用门面与脱离画布的只读文档快照，只开放资源摘要、选择/撤回及图片预览，不暴露完整 Host、正文读取、模型确认或执行方法。缺少槽位时，包不能据此生成路径、资源句柄或另开一套授权控件。`execution` 和 `resourceInput` 均由通用视图上下文提供，不要求底座为业务包增加分支。

### 7.3 完整节点、本地双击及上下连接

这些接口只属于可信本地包的运行代码。由包的同步 activate 返回，不放入 manifest、authoring、describe/agent.json 或场景配置。搭建与互动 Agent 只读取公开业务参数、真实输入输出及连接语义，不读取、选择或生成节点视图、CSS、端口位置或双击处理代码。用户或 Agent 修改公开的事件类型、门类型等业务值后，包内程序可据此改变外观；这不开放样式配置权。

本节扩展的是能力节点视图，不注册新的执行类 renderer。普通内容块仍由底座内容字段视图呈现；希望使用完整自定义视图的事件块与逻辑门可各自声明为能力组件，仍须有真实的类型、输入输出及本地实现。

需要执行的插件包自行提供“分析”等业务入口，视图在用户点击后通过 `context.execution.run(targets)` 调用宿主服务，无需额外界面开关。仅编辑包声明 `execution: 'none'`，不要求提供运行入口。底座已移除默认“运行与发送前核对”面板，旧 executionUi 值也不会使它重新出现。添加、接线、编辑内容或双击切换属性均不启动执行。

每项独立遵循“有效包内自定义优先，未定义的部分使用默认实现”：

- `node(context)` 绘制完整节点主体，优先于该节点原有卡片和 inline 视图。宿主外壳不增加默认标题、矩形边框、固定宽度或字段列表，包自行绘制符号、正文和业务控件。未提供 node 时保持旧卡片和 inline 行为；settings 不受影响。宿主继续管理选中、拖动、删除、真实连接点、必要的运行/等待/错误提示及结果读取。
- `onDoubleClick(context)` 接管节点非输入控件区域的双击。它独立于 node，可以只自定义双击、保留默认卡片。双击按钮、输入框、选择框、可编辑文字或连接点不会触发该回调；包视图中需要这些控件时仍应使用 nodrag/nopan 等交互标记。包也可在自绘控件内处理自己的事件，并停止冒泡，避免重复处理。未提供回调时保留原双击行为。提供回调后宿主阻止该手势继续触发默认画布缩放。
- `policy.inputAnchors/outputAnchors` 按实际端口 ID 设置 `{side, offset?}`。side 是 top/right/bottom/left，offset 是沿该边从左到右或从上到下的0至1有限数，省略为0.5。每个方向最多16项；未知端口、额外字段、非法方向或偏移均拒绝。原卡片中未设置位置的端口仍在原左右行内；完整 node 中未设置位置的端口按左输入、右输出均匀排列。包需要同侧多个点时自行指定不同 offset。

示例仅展示接口；使用时必须把能力键和端口名替换为包中真实声明：

```ts
// services 来自 activate；GateNodeView 由本地包实现，并使用宿主 React。
views: {
  'my-tools/gate': {
    node: GateNodeView,
    onDoubleClick(context) {
      const binding = context.node.bindings.gateType;
      if (binding?.kind !== 'literal') throw new Error('门类型必须是可编辑的本地参数');
      const source = services.editor.parameterSource(context.document, context.node.id, 'gateType');
      context.onInputChange('gateType', {
        kind: 'literal', value: binding.value === 'AND' ? 'OR' : 'AND'
      }, source.key);
    },
    policy: () => ({
      showResult: false,
      inputAnchors: {
        first: { side: 'bottom', offset: 0.25 },
        second: { side: 'bottom', offset: 0.75 }
      },
      outputAnchors: { condition: { side: 'top' } }
    })
  }
}
```

gateType 在能力中声明为真实输入参数，并在 authoring.parameters 中公开；first/second/condition 在相应真实输入输出与公开端口中声明。业务值通过原 onInputChange 或 onDocumentChange 提交，继续经过当前身份、公开边界、只读、来源版本、schema 和原子修改检查，保存并进入撤销重做。双击回调会先执行 guard，并检查 active/editable；结束、删除、修订变化、切换场景或只读内部实例均不能用旧回调修改。双击本身不调度图、不发送模型请求；包开发者不得把属性切换实现为自动执行。

连接点由宿主生成，ID 继续使用 `in:<真实输入ID>` / `out:<真实输出ID>`；上下摆放只改变几何位置，不改变连线方向、类型或授权。包不能通过绘图创建新的数据端口。原有 authoring 公开范围继续过滤可连接端口。宿主在端口位置、可见性或节点尺寸变化时刷新连接点边界，既有连线继续连接原端口；正常的节点移动仍由画布处理。

完整视图异常时，当前节点显示 PACK_NODE_VIEW_ERROR 并回退默认卡片及默认结果展示，其他节点保持可用；业务配置变化后可重新尝试该视图。双击处理异常通过 PACK_NODE_INTERACTION_ERROR 明确反馈。policy 错误按原 code/path 显示并使用默认布局。缺少自定义与无效自定义不能混为静默回退。等待/失败/取消/过期等必要反馈、条件及已有诊断入口仍由宿主保留；普通状态和结果展示遵循本地 policy。

原有 v1/v2 包未声明这些可选视图字段时行为不变。这不是物料协议版本升级，不向旧 manifest 追加字段。旧宿主不认识新的视图字段时会按严格契约拒绝；依赖这些能力的包需使用支持本节接口的宿主，不能声称旧宿主会自动降级。需要兼容旧宿主的独立构建应仅使用原有接口。

验证：`npm run check:scene-s2-node-views` 检查本地接口、端口边界、过期/只读手势、Agent 投影与样式注入拒绝；`npm run check:scene-s2-node-views-browser` 在实际 S2 画布中检查完整/默认优先级、双击及控件隔离、上下连线、尺寸刷新、撤销重做、实际执行结果和异常恢复。浏览器使用纯本地合成能力，不读真实资料、不调用模型。

事故树包的多事件输入直接复用通用多来源端口：逻辑门保留 `left / right` 两个真实端口和原底部锚点，两者声明 `multiple: true, required: false`，都可以接入多条 `fault-tree-logic.event@1` 来源。端口数不是输入事件数量；可全部接到同一点，运行时合并两个端口的事件列表。包检查合计2～32个不同事件，拒绝同一事件跨端口重复计入；AND 组合全部事件，OR 组合至少一个事件，输出仍为一个连接上级事件的 `condition`。端口可选是为了允许单点接入，不能据此省略整个门的业务完整性检查。S2 每端口最多32来源、整个执行画布最多40节点/80连线的校验继续生效。

用户直接拖动事件输出到已有来源的门接入点即可追加连线；Agent 使用相同公开 `addNode / connect / disconnect / setValues`，无需创建动态端口或修改本地视图配置。Agent 读取的端口规则保留 `multiple`、类型和业务限制，先读取所需字段/端口再操作。`inputEventIds` 为长度2～32的数组，禁止继续按二元 tuple 解读。输入集合、门类型和所有连线通过普通场景快照保存；未完成草稿可保存，明确执行时仍做完整业务校验。保留原端口 ID 使旧双输入场景在更新包后直接复用；发布新包时仍按精确版本安装规则管理发行版本。

对应实例及测试见 `examples/scene-packs/fault-tree/`：保留原双输入示例，新增 `sample.multi-input.s2-workspace.json`；单元/宿主测试覆盖3、5、32输入、嵌套门、重复与超限，浏览器测试实际添加事件、拖到已占用接入点、切换 AND/OR、保存并重开。显式真实模型验收还检查对话新增事件并接入已有或门/与门、保留原线和新浏览器会话恢复。

#### 主题与基础控件

底座负责解析应用的浅色、深色及跟随系统设置，并在主题根节点统一提供 `color-scheme` 与 `--ln-*` 语义颜色。原生下拉菜单、滚动条和画布缩放按钮随应用的实际主题变化；插件包不要再独立监听系统偏好或增加主题开关。

包内样式使用 `--ln-bg-surface / --ln-bg-subtle`、`--ln-text-primary / --ln-text-secondary`、`--ln-border / --ln-border-subtle`、`--ln-accent` 等变量，SVG 可使用 `currentColor`。底座通用按钮、表单和焦点样式使用低优先级选择器，仅作为默认实现；包内明确声明的样式优先，不应为覆盖默认样式而堆叠 `!important`。未自定义的控件仍继承底座默认样式。主题和外观属于本地运行程序，不增加 Agent 参数或公共搭建字段。

### 7.4 物料及其他界面扩展

v2 使用 materials 声明和包作用域的 list/read/openUrl 接口。终端检查实际文件、大小、摘要及媒体类型，包负责内容解析和视图；不能用终端绝对路径、用户本局资源 ID 或任意 URL 冒充可迁移的物料引用。作用域在运行、视图结束或撤回时释放，Blob URL 不保存入场景。

物料服务只接受所属包声明的 ID，两个包相同 ID 可以对应不同内容。包若主动将物料发布为通用画布内容或 artifact，之后按通用数据规则处理；当前没有物料内容的保密 ACL，不能从服务范围推导出恶意代码隔离。

业务参数应放入已有、明确声明的字段或端口数据结构中；组件、类型和操作使用包自己的身份/名称空间约定。不要往顶层清单或场景对象添加未知字段并期待底座忽略。现有表达能力不足时，应先版本化扩展契约。

`dispatch` 可以实现包自己的操作名，但当前聊天 Agent 没有统一的任意包操作调用路由。describe 中列出操作或 defaultAllowedOperations，不等于已注册 Agent 工具，也不是执行授权。当前搭建与互动主要使用场景配置、受控画布命令和执行图。

### 7.5 保存场景与下次复用

统一入口为画布上方工具栏的“保存场景”，与“添加”并列，直接点击保存；“更多”中不再重复提供保存入口。保存不要求开始或结束试验；它保存用户已应用的场景配置，供“场景模拟 → 复用已有场景”直接打开。每次保存新增一个 sceneId，记录 sourceSceneId，原场景不被覆盖。没有新增命名、确认或执行流程。

保存内容包括块正文、事件/门类型等业务属性、参数与字段引用、真实端口连线、位置、分组、组合及蓝图库，以及场景目标、指令和插件包的精确 ID/版本。包代码、CSS 和手势实现继续来自已安装的本地包，不写入场景或交给 Agent 生成。需要对应版本的包已经安装，才能恢复相应组件。

保存基于经过校验的当前文档的独立快照。`local-material@1.0.0/read-text`、`read-image` 和 `project-notes@1.0.0/read-text` 的 resource 字面量选择不进入保存文件；其他节点输入中的 `core.image@1` 字面量句柄也清除。保留这些节点和其余参数、字段引用及连线，以待新本局重新提供资料。不会按字符串前缀猜测业务意义或删除正文，也不会清理包内声明的可迁移物料引用。自定义数据类型不能靠把宿主临时句柄包装成普通业务值获得持久性。

清理只作用于保存快照，不修改当前画布、撤回当前资料、改变额度或触发执行。保存不包含未提交草稿、聊天、运行结果、等待、文件/图片内容和本局资源或模型授权。正文已经由用户明确填写到普通内容字段时，它属于场景配置，仍会保存。

重新打开时创建新的运行生命周期，不发送模型请求或读取资料正文；旧版场景中遗留的上述临时字面量也只在内存中清理，不自动覆盖原保存文件。界面提示未选择的资料入口需要重新选择；文件和图片节点显示本地选择控件，项目笔记只列本次所选项目允许范围内的元数据，须重新允许和选用。选择后沿原连线使用包内入口即可继续操作，不需重新搭建画布。

底座先写入 `scene-skills/scenes/<sceneId>.json`，再更新 `scene-skills/manifest.json` 场景库索引。保存失败明确显示错误，不伪报成功。验收见 `scripts/check-scene-s2-scene-save.tsx`：覆盖当前资料不受影响、三类资料清理、普通值及布局保留、新旧场景恢复、重新选择后的实际数据链路和保存失败/重复点击。

### 7.6 “更多”的边界与节点内待处理交互

“更多”只提供底座的通用搭建、配置迁移和诊断入口：复制所选、分组、组合/蓝图库管理、工作区与子图导入导出，以及开发诊断。删除、移动、连线增删和组折叠使用画布已有操作，不再附加批量删除、固定方向平移、重复的勾选节点与连线操作列表。复制保留一个入口，因为当前没有另一个通用复制入口。保存场景继续直接位于画布上方工具栏。

“更多”不再放置业务目标/评价标准、互动分工、能力范围勾选、AI 重设计初稿、全局资料选择、人工填写或模型发送确认面板。这些业务内容和操作由包通过本地视图、场景配置及明确的用户对话提供。包可读取 context.definition 中的已声明目标和规则自行展示；隐藏界面不取消能力目录、只读边界、输入类型、权限、预算、版本、来源、取消或生命周期校验。原执行调度和资料/模型服务保持有效，不恢复通用运行面板。

“添加”仍按所选包的真实公开目录或原协议可组合能力目录提供组件；本局尚未建立时，明确添加组件经原校验写入配置范围，不要求另到“更多”勾选一次能力。运行中的本局仍使用既定范围，菜单不扩大授权。

`context.interactionInput` 是当前节点实际处于等待时的原生人工输入/模型请求控件，没有等待时为空。包可在 node/inline 视图中嵌入，并返回 `policy: () => ({ interactionInputInView: true })`。没有实际 node/inline 视图时，单独的标记不能隐藏兜底；未接管时由底座在同一个画布节点显示一次，用户无需前往“更多”再处理。完整节点视图出错时恢复原生待处理控件，避免等待失去提交入口。

```tsx
node: context => <section>
  <MyBusinessControls {...context} />
  {context.resourceInput}
  {context.interactionInput}
</section>,
policy: () => ({ resourceInputInView: true, interactionInputInView: true })
```

示例只表示本地插槽布局，MyBusinessControls 由包实现，不能把插槽或回调写入场景 JSON。原生提交/拒绝/取消仍绑定当前节点、当前等待与文档版本，过期操作不能提交到后续等待或新场景。现有包的“测试”点击已完整表达本次请求时，继续走原用户动作执行路径；不因本节接口增加一次通用确认。交互槽位只在存在真实待处理项时提供，不自动运行、读取资料或请求模型。

本局授权摘要、撤回授权、调用/模型记录和技术详情仅在显式开发诊断中查看；诊断不提供另一套业务资料选择或执行入口，也不自动批准请求、重置用量或修改配置。错误恢复优先定位原节点的原生或包内控件；查看模型授权问题才进入诊断。资料与交互插槽及其 policy 均只开放给可信本地插件包，不进入 manifest、Agent 说明或公共搭建配置。

验证：`npm run check:scene-s2-pack-ui` 包含“更多”的可见范围、项目笔记选择与保存复用、节点内待确认模型请求及过期/重复/拒绝/结束校验；`npm run check:scene-s2-node-views-browser` 验证真实画布中的包内人工输入、原生兜底、渲染错误恢复和单次提交。测试使用合成资料/请求，不访问真实模型。

## 8. 写给搭建 Agent 的说明

开发者应明确说明每个组件的用途、真实 ID、所需字段/端口、默认值、可配置项、错误和已支持的组合。示例必须使用真实组件和数据契约，不能包含虚构执行结果或预先授予的权限。

Agent 根据用户目标选择组件、安排布局、预填内容和设置通用实例约束；无需包枚举所有教学目标。例如同一种文字块可分别保存固定角色、可编辑任务和固定输出要求，通过实例 readOnly 表达差异，不新增三种专用块。

Agent 不应重写内部资源路径、组件实现或数据传输代码，也不能为了满足需求临时猜测安装、降级或授权。包说明不完整时应明确缺口。

## 9. 兼容行为：当前与目标

当前已有精确版本、接口版本、组件契约、类型、依赖、包范围和运行校验；缺包/版本不符保留原场景并拒绝进入，安装同版本后可以恢复。显式基础 S2 只使用底座共享能力，不继承之前加载的业务组件。

当前尚无统一的“可运行 / 可降级运行 / 不可运行”检查结果，也没有 optional 宿主依赖与显式替代方案的标准声明。当前错误来自读取、安装和运行阶段，不应伪称已完成统一兼容协商。

后续目标为：必需能力不满足则明确拒绝；可选能力不满足时，仅在包声明了已实现的替代方案后降级，并向用户及 Agent 返回限制。没有替代方案就标记功能不可用。业务意义与包间任意组合不纳入兼容推理。

这些新增声明应通过明确的协议演进引入。旧 v1 包按既有规则读取，不靠无限容忍未知字段或忽略必需能力来兼容。

演进规则：不给已分发 v1 包追加必填字段，也不改变已有 ABI 的语义；新增必需清单字段或执行语义变化应使用新的协议版本。当前终端同时读取 v1/v2；旧宿主对 v2 清楚拒绝。v2 缺文件、完整性错误或物料服务不可用时拒绝加载，不静默降级。

## 10. 开发步骤与验收

1. 从一个非提示词的小包开始，确定组件、数据类型和运行能力是否属于当前开放范围。
2. 实现同步 activate、完整核心接口和 Agent 说明；需要界面再提供 views/help。
3. 使用自有构建或仓库的源码约定构建工具，生成单文件 ESM 和其余分发文件。`build:scene-pack` 仍专门构建提示词包；`build:scene-pack-example` 构建分层最小示例，构建工具的 --source 可指定同约定的新包目录。
4. 在目标版本底座中检查清单、注册与实例配置，再验证本地执行和实际产物。使用 `npm run package:scene-pack -- <id/version目录> <新输出.zip>` 打包，通过桌面“S2 交互包 → 导入 / 更新”确认可信来源后即装即用，无需重启。首次开发也可手工复制整个版本目录到终端交互包目录，再重启发现；不要覆盖已发布版本。
5. 保存、导出、重新打开及复制到第二个隔离终端，核对精确引用和图配置；删除包应提示缺失而不改场景。
6. 验证错误输入、停止、旧回调、只读、关闭及重复运行。模型能力额外验证无用户动作时零发送、点击只请求一次且采用当前输入，以及次数、长度和超时限制。
7. 不修改底座业务代码、不引入提示词包依赖即可完成接入，才算通用接入通过。借助测试专用预安装包通过旧回归，不等于无包底座验收。

仓库内已有构建和通用验包命令，尚未独立发布 npm SDK 或脚手架。按最小示例约定开发时：

```powershell
npm run build:scene-pack-example
npm run validate:scene-pack -- --dir output/scene-pack-examples/number-scale/1.0.0
npm run check:scene-pack-example
```

构建其他同约定源码：`node scripts/build-scene-pack-example.mjs --source <源码目录> --out <安装包根目录>`。不要直接修改已发布版本的契约。

`--out` 是开发构建输出根目录，不要指向终端实际安装目录。重复构建同一开发版本时，工具先生成干净的完整临时版本，再切换目录；旧清单曾声明、而本次已移除的物料不会残留进新 ZIP。写入或发布失败会恢复完整旧产物；若恢复本身也失败，会保留完整备份并输出其路径，不删除最后一份旧产物。已有目标含未知文件/目录、不同身份或链接时拒绝替换，开发者应核对或选择新输出目录，不能用清空整个输出根目录解决。上述开发迭代不改变终端安装器的同版本不可变规则。

ZIP 打包读取期间保留入口文件句柄并核对版本目录／文件身份，避免并发重构建生成“旧代码＋新样式／物料”的混合包。若同一路径在读取中被切换，命令以 `PACK_BUILD_CHANGED` 中止，不生成 ZIP；等待构建完成后重试即可。Windows 也可能因该句柄直接阻止并发构建的目录替换（`PACK_BUILD_BUSY`），此时旧产物保留，等待打包结束后重试构建。通用示例和内置提示词包都复用完整目录发布，不再原地逐文件覆盖。即使文件内容先改再改回，也不会把它误认为同一目录快照。完整读取后只对内存快照验包和压缩，后续重构建不影响该快照；不增加持久锁或改变安装端的同版本不可变规则。文件系统不提供稳定文件 ID 时会拒绝打包，不能绕过此检查。不要在打包期间手动原地编辑构建文件。

ZIP 输出先写入目标同目录中独占创建的 `.scene-pack-zip-<随机ID>.tmp`，完整写入、同步并关闭句柄后，通过硬链接原子发布到正式文件名；不使用会覆盖目标的 rename/copy 降级。已有目标（包括其他进程刚发布的文件）始终保留，失败只尝试清理本次创建的临时文件。写入／同步／关闭／发布失败不会留下残缺的正式 ZIP，可直接重试。发布前进程异常退出可能留下临时文件，但不占用正式输出名，也不阻止重试；发布后异常退出时正式 ZIP 已完整。清理失败会报告临时路径，不删除正式文件或其他进程的临时文件。不支持硬链接的文件系统会以 `PACK_ZIP_PUBLISH_UNSUPPORTED` 拒绝发布，请改用支持硬链接的本地目录。此机制不是断电持久性保证；以前已存在的残缺 ZIP 不会自动删除，核对后移走／改名或选择新输出名。

`npm run check:scene-pack-development` 在隔离临时目录串联真实示例源码构建两个版本、CLI 验包、CLI ZIP 打包、生产安装器/存储、免重启刷新与加载、实际本地图执行及旧场景保留。它同时验证构建器只放行已审查的共享纯协议文件，拒绝未审查的服务端/存储依赖；不是按整个目录放行。构建不执行包入口，验包会执行可信包的激活代码，二者不要混淆。真实桌面更新另运行 `npm run check:scene-pack-update-native`，覆盖生产 preload/IPC/UI、旧调用继续、新版实现、动画和公共能力隔离；使用隔离 Electron 与合成数据，不覆盖正式安装产物，不调用真实模型。

示例默认输出到独立的 output/scene-pack-examples，不进入终端默认包种子或正式应用分发目录。将其安装到终端是开发者明确执行的独立步骤。

验包工具检查固定四文件、共同限额、目录身份、入口、Agent 说明一致性及真实能力安装契约；错误输出包含代码和路径。CSS 使用生产 `scenePackStyles` 解析器静态检查，不注入样式；ZIP 打包及桌面导入预检也执行同一规则，禁止的全局规则或无效 CSS 在安装写盘前拒绝。验包会执行可信包的 activate/describe，不创建运行器、不运行场景、不改输入目录。`--scene <文件>` 选项接受 `{definition, document}` 格式的 ScenePackConfig，复用正式打开场景时的公开目录校验/兼容归一化，检查公开组件、参数、端口、只读约束及业务规则；内部基线取自包的 authoring.internal，不接受调用方通过同时改写 initial/document 伪造。旧协议省略 authoring 的包继续使用显式旧适配。工作区封装文件应走应用导入或示例验收，不能直接冒充该格式。验包通过不能替代实际运行和生命周期验收。

`npm run check:scene-pack-release-guards` 针对上述发布边界做离线反例回归，包括公开/内部/只读配置拒绝、CSS 在激活和写盘前拒绝、撤回物料不进入重建 ZIP、写入/发布失败回滚与恢复失败备份保留、同目标并发及未知文件/链接保护；还覆盖真实打包 CLI 与跨进程重构建交错、内容改回的 ABA 情况、失败无 ZIP 与稳定重试、回滚及不同目标互不影响、旧安装版本与已有 ZIP 不变。该专项也包含在 `check:scene-pack-development` 中。

该专项同时验证 ZIP 输出的部分写入、同步、关闭、发布故障与同路径重试，不支持的文件系统拒绝、清理失败告警、发布前后进程退出、两个真实 CLI 争用同一文件名，以及已有文件／遗留临时文件不被误删；生成的完整 ZIP 会交给生产安装器验证。

`npm run check:scene-pack-contract` 运行直接契约和生产接入边界检查；`npm run check:scene-pack` 合并物料、核心契约、最小示例及既有包回归。新示例和契约检查均在未预装提示词包的进程中运行。真实物料视图另由 `npm run check:scene-pack-material-browser` 在无头浏览器验收。

包声明的画布交互由 `npm run check:scene-s2-pack-ui` 验证默认兼容、编辑位置、分类添加和本局权限。`npm run check:scene-s2-prompt-inline-browser` 使用真实组件和隔离的无头浏览器检查提示词包的双击编辑、节点内设置、分类菜单及原内容定位；模型响应使用合成数据。

提示词包的真实模型验收可显式执行 `npm run check:scene-pack-prompt-live -- --execute`。它读取当前终端实际安装的 `prompt-lab/0.1.0` 和模型配置，使用合成城市资料，分别计数助手请求与提示词测试请求：直接编辑零调用，Agent 修改只发助手请求，按钮或明确让 Agent 测试才发测试请求，结果展示完整真实返回。提示词包运行器统一补上测试节点直连的文字结果块，两种入口采用相同策略，不扩展到其他模型节点。保存写入独立验收目录，关闭浏览器上下文后从磁盘重开，检查配置、连线及再次测试；旧结果和运行会话不作为场景配置保存。报告位于 `output/prompt-pack-live/<时间>/report.json`，不写用户场景库。该验收使用生产加载器、画布、交互协议、模型会话、模型请求及场景存储，替换 Electron IPC 为隔离桥接，不等同于完整桌面外壳验收；命令会真实消耗当前配置模型的调用额度。

## 11. 当前未提供的扩展

当前可使用本仓库构建/验包/打包工具、ZIP 导入、精确新版本并存与加载、公开搭建及 v2 物料服务。以下项目不属于当前可声明的接口：

- 独立发布的开发 SDK、脚手架或通用默认运行器。
- 完整的必需/可选宿主能力协商、统一降级结果和声明式替代实现。
- 自动场景版本迁移、在线市场，以及完整的图形化包管理。
- Agent 自动调用任意包 dispatch 方法，或临时生成本地执行/视图实现。
- 不可信代码沙箱，以及包自行扩展的任意网络、文件写入或系统执行器。

需要超出当前契约的宿主能力时，先扩展并验证宿主接口，再发布依赖该接口的包；不能通过未知 manifest 字段、自然语言说明或忽略校验来补足。

“符合已有契约的新业务包，无需修改 S2 业务代码即可接入”是兼容性验收标准；业务包数量和玩法数量不是该标准。开发顺序及交付检查回到[主指南](scene-s2-plugin-developer-guide.md)。
