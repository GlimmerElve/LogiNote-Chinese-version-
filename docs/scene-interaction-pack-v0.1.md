# S2 交互包 v0.1 实施说明

开发者按 [S2 交互包开发指南](scene-s2-plugin-developer-guide.md)完成示例、实现、安装和保存复用验收；字段、限额与兼容路径查 [接口参考](scene-s2-plugin-api-reference.md)。本文保留分阶段实施和验收记录。各轮中的界面描述和截图记录当时行为，旧内容属性区、组装设置区及预算批准/逐次发送核对步骤已由下述当前交互替代，不作为新包必须实现的功能。

S2 是终端内置的通用画布范式。交互包向它提供业务组件、包内规则和 Agent 使用说明。协议不要求内容必须是提示词，也不要求存在模型节点。本版沿用已有 S2 配置、端口、产物和调度协议，不让搭建 Agent 编写数据传输代码或判断包内组件是否兼容。

## 已实现的边界

终端负责画布编辑、配置解析、类型与端口校验、调度、产物、缓存、取消、修订和过期结果隔离；模型连接、执行限额及资源访问由终端处理。保存场景也沿用原路径。

交互包负责说明组件的用途、用法和业务组合，提供确定性的本地处理、包级校验、运行器、画布交互声明及专用编辑视图。提示词包拥有组装规则、节点内组装和模型参数视图及搭建策略。文本内容块及原文展示仍可使用 S2 通用能力。

协议源文件为 `src/types/sceneInteractionPack.ts`。接口中没有角色、任务、提示词模板、实验评分等专属字段：

- `manifest`：包的精确身份、所需范式及宿主接口版本、所需服务。
- `authoring`：版本化的机器公开组件目录；用户菜单与搭建 Agent 共用。可为空，不能用空目录回退全量运行能力。
- `describe()`：可选 Agent 辅助说明；显式 authoring 的开发者可省略，终端生成最小归一化说明。旧包省略 authoring 时保留原说明契约。
- `validate(config)`：包的业务校验。终端继续校验 S2 格式、类型、端口和图结构。
- `createRuntime(config, host)`：接收本场景的有限宿主服务，返回 `updateConfig / dispatch / run / dispose`。
- `capabilities / executeLocal()`：声明并处理精确版本的本地能力。包内开发者保证组合正确；宿主在运行时继续检查输入、输出及错误。
- `views`：按 `pluginId/capabilityId` 注册 `settings / inline` 通用视图槽位；视图接收配置快照、当前节点、活动状态和提交回调。提交仍经过当前场景、文档、历史版本及结束状态检查。
- `canvas`：可选声明内容字段的编辑位置、选中时是否打开设置区、内容设置区显隐、添加菜单分类及 `executionUi: 'panel' | 'inline'`；未声明时保留原有通用行为，不授予执行权限。

`dispatch` 的操作名和附加参数由包扩展，终端不枚举业务操作。当前画布的执行入口已接入包的 `run`，结束、换场景和卸载视图时调用包的 `dispose`。自定义 `dispatch` 可由宿主调用；本版尚未给聊天 Agent 新增任意包操作的通用工具路由。

## 统一公开搭建接口

包的完整 capabilities、处理函数和运行依赖留在本地。authoring.components 列出允许搭建的逻辑类型，每条声明 id/label/purpose、可选 group、本地 implementation 映射、inputs/outputs/parameters 及可选 defaults。参数 schema 和端口类型从真实原生内容字段或精确能力契约解析，不让 Agent 重新实现类型或传输。

用户与搭建 Agent 共用 S2PublicCanvas：nodes 使用 componentId、实例 ID、位置及公开 values，connections 使用实例和公开端口。底座编译为完整运行配置；菜单隐藏、Agent 说明和用户自报的 public/componentId/readOnly 均不能授予修改权。Agent 不读取 implementation 或内部图。

`authoring.internal: {blockTypes, document}` 是包提供的可信原生内部基线。内部实例即使使用已公开的同种能力，也不能编辑、移动、删除或改接；最终本地校验覆盖字段修改、包视图回调、Agent 命令、批量操作、历史恢复和整图/子图导入。完整运行实现与公开编辑范围分开，未公开不影响内部运行。

`components: []` 是有效闭合状态，直接使用包已有界面，不强制组件选读或内部装配。只在整个 authoring 字段省略时采用明确旧协议适配，绝不把显式空目录解释为全公开。独立 number-scale 示例已提供机器目录并省略 describe，以验证开发者不必先编写完整 Agent 手册。

## 当前提示词包的编辑入口

编辑方式由包声明。提示词包使用 `contentEditing: 'double-click'`、`openSettingsOnSelect: false`、`contentSettings: 'hide'`：双击内容块进入节点内编辑，普通文字失焦或通过快捷键提交，Escape 取消；普通单击只选中，不弹出属性面板。S2 仍保留其他包可选择的 `panel` 编辑方式；隐藏内容设置区时必须显式使用 `inline` 或 `double-click`。

当前只有五种逻辑块：内容、组装、测试、结果、待测资料。组装块默认提供角色、任务、输出要求三个入口，来源通过连线或字段绑定表达，结构小编辑区只改标题和分隔符，不再提供另一份来源选择或正文表单。模型参数常驻测试节点，点击“测试”即用当前提示词、资料及参数发送本次请求；节点内显示短状态并可停止，不弹出预算、运行队列或发送核对面板。次数、长度和超时由程序处理，不切换模型、不自动重试。返回原文只在结果块展示。

提示词包通过通用 `executionUi: 'inline'` 选择节点内运行界面，视图使用 `execution` 的运行、状态、错误与停止接口；底座按用户动作执行当前请求，不按提示词业务 ID 分流。

待测资料可直接填写文字，或按需选用文件、图片：手填使用同型 `text/content` 块并标为“待测资料”，文件与图片复用现有读取能力和宿主原生控件，均属同一逻辑类。Agent 需要运行时仍交给终端的用户动作入口，场景 JSON 不保存发送授权。

添加菜单与新搭建只使用这五类，旧 `bind/render` 仅兼容存量场景，不进入新菜单或主动生成。实际能力继续按精确引用和当前场景范围校验；普通内容修改只更新本地画布、撤销及控件事件，不合成聊天消息或自动调用 Agent。底座的通用结构化字段、人工输入和真实聊天协议继续保留。完整声明见开发指南“由包声明编辑入口与添加菜单”。

## 分发目录与加载

构建提示词包：

```powershell
npm run build:scene-pack
```

产物位于 `output/scene-interaction-packs/prompt-lab/0.1.0/`，可将该版本目录复制给其他具有 S2 接口 v1 的终端。目录固定包含：

```text
manifest.json   包身份、范式与服务要求
agent.json      给搭建 Agent 及开发者阅读的组件和使用说明
main.js         单文件 ESM；导出 activate(services)
styles.css      包的视图样式；可以为空
package.json    本包构建时附带的 ESM 标记
```

提示词包的本地构建审计会拒绝打入包目录以外的运行时代码。第五轮迁入完整编辑界面时记录为 17 个源码模块、`main.js` 约 118 KB；体积是当轮构建记录，React 使用终端注入的同一实例。

安装位置是 `app.getPath('userData')/scene-interaction-packs/<id>/<version>/`。主进程仅从这个根目录读取固定资产并检查路径、清单身份和大小，不执行包代码；渲染进程在创建画布宿主前加载入口、校验契约、注册能力和样式。这里只支持可信本地代码，执行入口与终端渲染器处于同一环境，不是隔离沙箱。

开发端启动会用 `.seed-receipt.json` 中的完整文件指纹识别受管默认包：只有安装副本仍与上次构建一致时，才替换为本次构建。用户修改过、没有来源记录或已删除的包不会被自动覆盖或重新安装。旧的无记录副本须显式运行 `npm run replace:scene-pack -- --root <绝对安装根目录> --seed <绝对构建根目录> --id <包ID> --version <精确版本>`；命令仅替换指定包，完整暂存验证后提交并写入指纹，更新后重启以清空渲染器中的已激活模块。不会操作笔记、场景、其他包或会话授权。

安装、删除或更新后重启终端。首次启动从随应用分发的目录播种默认包，随后写入初始化标记；删除包后不会在下次启动偷偷装回。缺包或版本不符时明确报错，保留原场景配置，装回相同版本后再打开。首版不包含热插拔、在线市场、版本范围推断或跨包兼容分析。

新增包可以注册自己的纯本地 transform/validator、数据类型、通用视图和操作；模型、文件等有副作用能力使用已有宿主桥接。首版没有开放自定义文件权限、任意网络或新的副作用执行器。

## Agent、配置与运行

搭建先理解用户原始需求，再展示所选包及能力的用途索引，由 Agent 按需选择完整组件说明和精确接口后生成配置。包提供业务搭建及修复策略，终端提供通用 S2 协议规则；读取流程见下述第九轮。未选包时使用通用画布策略，不自动套提示词实验流程。

用户和搭建 Agent 使用同一份 S2 `canvasWorkspace`，其中包含内容节点、执行节点、绑定和连线。场景外层保存包的精确引用：

```json
{
  "interactionPack": { "id": "prompt-lab", "version": "0.1.0" },
  "canvasWorkspace": {
    "version": 1,
    "goal": "按需练习提示词工程",
    "initial": {
      "nodes": [],
      "edges": [],
      "execution": { "version": 1, "nodes": [], "links": [] }
    }
  }
}
```

上面仅展示字段位置，不是可独立运行的完整场景；完整画布还需 `instructions / blockTypes / plugins` 以及实际节点绑定。提示词包说明和验收夹具中提供真实组件例子。

正式搭建面板的 S2 新场景可选择基础画布或已安装交互包，选择进入 `SceneInitialRequest.interactionPack`；显式 `null` 表示纯 S2，并保存为 `SceneSpec.interactionPack: null`，重新打开仍保持纯画布。已有场景复用自己的精确引用，不显示覆盖选项。历史场景及旧入口没有这个字段时，由入口兼容层默认选择提示词包；通用执行接口本身不推断默认业务包。

实际运行路径：入口加载包 → 校验/创建 S2 场景 → 用户点击测试 → 包运行器 → 终端调度 DAG → 包内本地处理或宿主模型/资源桥接 → 宿主校验并发布产物 → 结果展示。次数、长度、超时和停止由程序处理，关闭助手不阻断这条路径。

## 本轮拆分位置

- `src/interaction-packs/prompt-lab/`：文本组装实现、组装/提示词控制、专用 React 视图、能力声明、Agent 说明、包运行器和分发入口。
- `src/services/scene/sceneInteractionPackRegistry.ts`：通用包协议与精确版本注册；`sceneInteractionPackLoader.ts`：通用入口加载。
- `src/services/scene/scenePackEditorServices.ts`、`sceneInteractionHostServices.ts`：通用编辑及运行服务。
- `src/components/scene/ScenePackView.tsx`：通用视图槽位；`SceneS2PackBoundary.tsx`：加载完成后才创建画布。
- `src/electron/sceneInteractionPackStore.ts`、`main.ts`、`preload.ts`、`preload.d.ts`：目录读取及 IPC。
- `scripts/build-scene-interaction-pack.mjs`、`electron-builder.yml`：独立构建和发布资源接入。

最初迁移阶段保留了旧路径转发、静态注册和画布内旧 UI 分支；第五轮已将这些实现依赖移除，详见下文。旧能力 ID 与保存格式继续有效，历史包引用由入口兼容识别，实际能力必须从安装的包加载。

## 验收证据与实际限制

以下及后续分轮记录保留当时的模型预算与发送确认验收事实；当前提示词入口已改为用户点击测试即发送，旧步骤不再作为使用要求。

`npm run check:scene-pack` 包括两组独立验收：

1. 提示词包实际构建、目录读取和生产加载器激活、样式只加载一次、打包后编辑器渲染、真实宿主的组装→模型确认→原文结果链路，以及配置快照、错误、取消、结束、精确版本及删除后不重装。
2. 独立计算包仅依赖公共类型，单模块构建后经相同目录和生产加载器接入。在提示词包不可用时，注册新的数值能力、自定义设置视图和 `explainFormula` 操作；搭建阶段读取该包说明；真实 S2 宿主执行 `2 + 3 → 5`，不提供模型服务；未绑定业务包的 S2 也能执行。

现有 `check:scene-s2-experiment`、`check:scene-s2-registration`、`check:scene-s2-browser`、设计回归及生产构建已通过。新增协议、入口、加载器、独立包、存储及验收脚本的依赖闭包类型检查无诊断。浏览器命令在本仓库是离线协议与模块隔离验收，不能当成真实浏览器实点证据。

首轮未进行原生客户端验收；下述第二轮补充了隔离 Electron 功能客户端的真实界面验证。完整安装版应用及真实模型效果仍未验收。

## 第二轮：原生 Electron 功能客户端验收（2026-10-25）

新增 `npm run check:scene-pack-native`，使用 Electron 35.7.5、生产 preload、同一个生产交互包 IPC 注册函数、生产加载器及 S2 画布组件。只有四个模型相关依赖使用离线替身；场景通过真实 `sceneSkillStore` 和隔离测试 IPC 落盘。不会读取正式笔记或模型配置，HTTP/HTTPS/WebSocket 请求被阻断。

该命令只运行测试页，不接入正式产品菜单。测试页顶部“打包提示词、旧提示词、基础 S2、独立计算包”四个按钮是验收入口，不是产品功能入口。默认自动退出；显式追加 `--inspect` 才保留可见检查窗口，检查结束后应关闭。

本次五组真实 Electron 验收通过：

1. 安装后加载独立 ESM、样式、组装设置及模型参数视图；实际修改组装前缀、应用到文档，把输出参数改为 512，再经预算批准和逐次发送确认得到一条合成原文返回。确认前发送次数为零。
2. 移除提示词包并重启，显示缺包提示、不自动重装；所有已保存场景文件的字节指纹保持不变，独立计算包仍执行 `2 + 3 → 5`。
3. 精确版本清单与目录不符时拒绝打开，已保存场景字节不变。
4. 重装后重启，原提示词场景图保持一致；磁盘上没有包引用的旧场景仍能经兼容入口打开。纯 S2 保存后重新打开仍为 `interactionPack: null`。
5. 将包目录和合成场景复制到第二个独立终端数据目录，在没有默认播种来源的情况下重新打开，图配置一致，不恢复旧模型授权或触发新调用。

最新报告和截图索引：`output/scene-pack-client-acceptance/latest.json`，其中 `runRoot` 指向本次完整证据。截图包括组装设置、实际合成结果、缺包、版本错误、重装及第二终端恢复。测试数据均为合成内容；两个目录模拟独立终端，不代表已在另一台实体设备或完整安装版应用中验收。

运行环境需要 `in-process-gpu` 避免 GPU 子进程依赖错误，测试窗口关闭后台节流并等待两帧后截图；这些设置只位于测试客户端。受限执行环境可能阻断 Chromium 子进程或文件导航，需在允许启动原生子进程的环境运行。宿主仍会记录 DirectComposition 接口警告；浏览器偶发的已知 ResizeObserver 通知单独记入报告，其他应用异常和 React 错误仍使验收失败。

本轮同时修复了两个边界：持久化包引用的 `false / 0 / ""` 不再绕过精确引用校验；选包后的搭建及 UI 目录仅展示本包和终端共享能力，本地执行适配器在发布输出前拒绝其他包的能力。未选包的 S2 行为不变。`check:scene-pack` 与提示词实验回归通过，相关依赖闭包类型检查无诊断，前端及 Electron 构建通过。

第二轮结束时尚保留的范围：旧路径转发和旧 UI 兼容分支未全面清理；当时工作区导出未携带包引用，该项在下述第三轮解决。聊天 Agent 的任意自定义包操作路由未开放；模型/资源仍由原有宿主授权机制控制。未发送真实模型请求，也不以合成返回证明提示词效果。

## 第三轮：正式入口与便携工作区闭环（2026-10-25）

正式入口为“学习 → 场景模拟 → 选择场景来源 → 通用画布（试验）”。新建、自定义及 Agent 搭建均可在第二步选择一个已安装 S2 交互包，或选择基础画布。确认页显示所选名称和精确版本。已保存场景按自己的引用打开，不允许在复用向导中悄悄换包。S1/S4 的请求结构与原流程保持不变。

`listSceneInteractionPacks()` 只读取清单，不导入包代码；初次发现使用缓存，明确刷新使用 `{ refresh: true }`。元数据加载期间阻止误入，读取失败仍可选择基础画布。实际执行入口依然由 `SceneS2PackBoundary` 在创建宿主前加载。已加载代码的同版本替换仍需重启，不把刷新列表作为热更新。

用户界面的工作区导出现在使用版本 2，同时携带 `definition` 与 `interactionPack`。后者只能是精确 `{id,version}` 或显式 `null`，不接受代码、授权或运行凭据。原有两参数程序 API 仍输出版本 1，旧文件继续可读。导入版本 1 时保留当前选择；导入版本 2 时采用文件中的精确引用或 `null`。

导入先执行有大小限制的元数据预检，加载所需精确包后再解析能力图；因此新终端无需预先打开过该包的场景。缺包、错误文件及包范围不符不替换原画布。等待期间若编辑、撤销、换文件、换场景、停止或卸载，过期结果不能覆盖当前预览，也不创建运行宿主或模型会话。

## 第四轮：通用内容块的实例只读约束（2026-10-25）

S2 内容块实例新增可选 `readOnly?: boolean`。省略或 `false` 继续可编辑，`true` 固定该实例全部 `values`、块类型和只读状态。它属于通用 S2 配置；不新增角色、任务或输出专用组件，也不是整个交互包的开关。

例如搭建 Agent 可以使用同一种 `text` 块生成以下三个实例，按普通字段绑定交给组装步骤：

```json
[
  { "id": "role", "type": "text", "label": "角色", "readOnly": true, "position": { "x": 0, "y": 0 }, "values": { "content": "你是一名清晰表达的讲解者。" } },
  { "id": "task", "type": "text", "label": "任务说明", "position": { "x": 0, "y": 180 }, "values": { "content": "解释什么是函数。" } },
  { "id": "output", "type": "text", "label": "输出要求", "readOnly": true, "position": { "x": 0, "y": 360 }, "values": { "content": "输出摘要和例子。" } }
]
```

这里只展示节点片段。块类型、字段声明、能力与执行连接仍按原有完整协议提供。搭建 Agent 根据用户的固定内容要求预填并设置标记；没有明确要求时不擅自锁定。各包自己的装配、定向修复和 JSON 修复策略都会附加终端的通用约束；互动 Agent 的完整画布、预算索引和宿主事实同样携带只读状态。

终端在预览和运行期间校验用户输入、互动 Agent 命令、批量操作、整份文档替换、撤销重做以及包的配置写入。修改批次先完整校验，再更新文档和历史；任一固定块遭到修改、解锁、改型或删除时，整批不提交。当前场景的固定内容基线独立于可替换配置保存，导入和重新设计不能通过更换 `definition.initial` 重设原块。成功导入或重新设计引入的新固定块也成为该场景的固定内容。

固定块仍可选取文字、改显示名称、移动、读取、接线、组装和运行。复制保留 `readOnly`，派生副本在保留时同样不能修改内容；删除副本或撤销复制可用，原固定块仍不能删除。重新保存为独立新模板后，其中的只读块作为新场景的原固定内容。修改固定原文应创建新的场景设计；本版不提供运行时解锁入口。

界面显示“只读 · 场景固定内容”，普通文本框使用真实 `readOnly` 属性，复杂字段显示原内容预览。提示词包的排版辅助入口若引用固定字段，也拒绝反写来源；固定字段继续参与原有数据链路。JSON 格式解析器只负责字段格式，作者创建独立场景仍可生成不同的初始内容；当前场景的执行约束由编辑和宿主写入边界负责。

`npm run check:scene-s2-readonly` 覆盖协议、真实宿主、搭建与互动 Agent 合成协议、包内字段引用和实际组件回调。验收包括混合命令原子拒绝、删除后同 ID 重加、伪造解锁和配置基线、产物/等待/预算保持、同型固定角色及输出与可编辑任务、正常组装→逐次确认→合成结果、复制与历史、工作区与模板保存重开、跨场景重置及旧数据兼容。所有模型响应均为合成响应，不代表真实模型遵循率或提示词效果。

能力选择使用当前画布做结构校验，原始固定锚点由终端单独持有，并传给命令、Agent 校验、导出与执行宿主。它不属于 Agent 输出或可导入的授权字段。复制只读块后改变能力范围，再撤销复制，不会产生已不存在的“固定副本”；删除执行消费者后仍可取消对应能力。包收到的是与当前文档一致的配置快照，不能通过更新配置绕开宿主的原始锚点。原始宿主写入也拒绝重复内容 ID，防止校验和实际读字段命中不同的块。

完整正式应用验收新增独立的只读场景，已通过真实 DOM 的 `readOnly`/可选取状态、任务输入与撤销重做、生产 IPC 保存、正式场景库重开，以及非法导入拒绝后的原文和历史保持。证据在 `output/scene-pack-app-acceptance/latest.json`；截图 `installed/04-formal-readonly-content.png` 显示正式应用中的三个通用文字块。测试没有改默认场景数据，没有四个测试入口按钮，窗口隐藏并自动退出。受限环境第一次运行无法完成文件导航，允许原生测试进程后在独立数据目录通过；不代表完整安装器或真实模型效果验收。

## 第五轮：底座与提示词包实现解耦（2026-10-25）

## 第九轮：由搭建 Agent 选择读取说明（2026-10-26）

默认搭建改为渐进式披露。需求理解后先提供包用途、组件 ID/名称/用途、章节和当前范围全部能力的用途索引，不带配置、示例、端口、值结构或包规则正文。Agent 返回 `read` 清单，宿主只返回所选组件原文、章节及精确能力接口，再提供画布声明供配置生成。`builder` 章节必须先读；组件 ID 与能力引用保持独立，不按关键词或组件名猜测对应关系。
