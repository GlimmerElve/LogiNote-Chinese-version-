# LogiNote 移动端产品方案

阶段：第一阶段，产品方案、同步架构与可操作原型。本文定义移动端的功能、交互与验收边界；跨设备同步协议以同目录同步架构文档为准。原型使用独立演示数据，不连接真实桌面资料库、账号、聊天服务或学习结果。

上架相关入口、隐私/AI 同意、账号删除、UGC 治理、支付及工具链要求参见 [上架准备与官方依据](./store-readiness.md)（查证日期 2026-10-30）；这些要求纳入后续正式移动端交付与验收。

## 1. 产品定位

移动端服务于通勤、等待、休息等碎片时间，帮助用户查阅自己的知识、表达当前理解、完成短测和协调接下来的学习。桌面端服务于深度整理、长内容创作和复杂分析。两端使用相同的用户身份、资料身份与业务规则，但各自提供适合设备的页面。

移动端的主要闭环：滑到一张想看的内容卡片，阅读后点“复述”，在原地弹出的气泡里说出或写下自己的理解，再保存。简测、聊天和计划仍可独立进入，不要求先完成一套流程。

两端分工：

- 桌面端：长富文本编辑、资料导入与组织、复杂论证和知识图谱编辑、场景模拟、完整学习流程、复杂计划编排与批量管理。
- 移动端：推荐与搜索、阅读、短文本复述和认知记录、定向简测、学友与共学群聊天、计划生成和轻量调整、最新资讯。
- 共享结果：资料与来源身份、阅读位置、用户明确保存的个人表达、简测活动与经同一规则评定的学习状态、已确认计划、社交消息。
- 手机不提供长富文本或场景模拟入口。需要桌面处理的内容显示可阅读摘要和“在桌面继续”的提示；交接使用对象 ID 和定位信息，不传本机文件路径。

## 2. 导航与通用布局

底部固定五个入口：**发现、练习、记录、消息、计划**。资讯位于发现页内部，“我”、账号、设备和同步设置从顶部头像进入。五个入口始终保留文字标签，避免只靠图标识别。

延续 LogiNote 现有的 iOS 风格：浅色背景、清晰层次、圆角容器和克制的强调色。发现页优先一次展示一张卡片，减少同时出现的入口和说明。复述使用原地气泡，不把短记录变成独立的复杂表单。正文遵循系统字号；按钮和输入框采用适合触控的尺寸，键盘出现时仍可完成保存。正式移动端仍需验证深色模式。

全局规则：

- 保留当前卡片、阅读位置和搜索词；关闭复述气泡或阅读详情后继续原内容。
- 每条内容标注来源类型，例如“我的资料”“自己的复述”“社区资源”“资讯”。它们不混为同一种事实依据。
- 同步状态使用可理解文字：已保存在此设备、等待同步、正在同步、同步失败、需要处理冲突。只有收到服务端回执后才显示已同步。
- 空状态提供可以执行的下一步；不以演示内容冒充用户已有数据。
- 打开详情、阅读和切换入口不触发内容分析、公开发布或个人认知写入。

## 3. 发现：自己的资料优先

发现页以内容卡片为中心，默认呈现来自本人资料的推荐。一次显示一张主要卡片，左右滑动切换，也提供可点击的上一张/下一张操作。搜索、本人资料与资讯保留轻量入口，不在首屏堆叠多个推荐列表和筛选区。

### 我的资料

卡片显示标题、短内容、资料来源和必要的阅读信息；需要长内容时再展开详情。继续阅读、与当前计划相关的资料和待复习内容都可以成为下一张卡片。推荐理由保持简短且可核对，不凭空推断用户兴趣或宣称推荐算法已经验证理解程度。

搜索优先检索本人有权访问的同步资料。结果展示标题、命中片段、所属项目、来源及更新时间；点击进入只读详情。输入期间保留已有结果，提供加载、无结果和读取失败状态。离线时明确标注“仅搜索已下载内容”，不把离线未命中解释为资料库中不存在。

卡片上的“复述”是主要轻操作：点击后在当前页面弹出带轻微出现动画的输入气泡，自动关联当前资料；关闭后仍停留在原卡片，不跳转到记录表单。阅读详情同样可唤起气泡。收藏、适用知识点的简测和查看完整来源作为次要操作，不因收藏或阅读自动形成个人认知。富文本只读渲染，禁止执行资料中的指令或不安全嵌入。

### 资讯

按用户主动关注的方向呈现资讯，展示原始来源、来源发布日期和采集/更新时间。详情可打开原文、收藏、隐藏不感兴趣内容、纠错或基于资讯记录自己的想法。资讯属于外部材料，不自动写入私人知识库或认知库。

“最新”依赖服务端实际更新与来源时间。没有接入实时资讯时显示明确空状态或“演示资讯”，不得以固定示例声称实时。

### 可写边界

移动端可以写入收藏、阅读位置、下载选择和独立摘录。正文修改、批量组织和图谱编辑留在桌面。阅读位置同步应独立于正文，避免阅读操作使正文版本发生冲突。

## 4. 练习：短测与可追溯反馈

练习首页展示可简测知识点、待确认项目和未完成的简测。用户可搜索知识点后开始，或从资料详情、记录和计划进入。知识点必须满足现有简测规则，不将普通项目或任意资讯直接伪装成可评测知识点。

复用桌面现有简测业务标准：三题组成一张卡，保留题目来源、检验项、作答、辅助情况和评价证据。手机改变呈现方式，不改变确认掌握的条件。每次展示一道题，允许暂存后离开；提交前可检查作答，提交中防止重复操作。

结果区先展示本次结论、仍需确认的内容和下一步，再按需展开解析与引用。区分答题完成、本地保存完成和云端同步完成。用户使用提示或查看资料的情况按现有规则记录，不包装成独立检验通过。

### 可写边界

- 写入作答草稿和独立简测活动；成绩、掌握度和复习排期必须由与桌面一致的评价及持久化流程产生。
- 原型可演示选项、提交和反馈页面，但不调用真实出题服务、不评价真实能力、不更新掌握度。
- 离线作答仅适用于已经下载且允许离线使用的题卡；先保存作答。没有有效评价条件时显示“待联网评价”，不在客户端自判正式掌握度。
- 同一活动使用稳定 ID。超时重试查询或重放原活动，不创建另一份成绩。

## 5. 记录：保留用户自己的表达

记录入口保留自己的最近记录和独立短记录；从发现发起的复述直接在原页面气泡中完成，无需先进入记录页、选择分类或填写来源表单。来源自动关联当前卡片，记录入口可用于之后回看。

复述气泡只保留**编辑框、“按住说话”、保存和关闭图标**。不显示气泡标题、来源文字、语音/打字模式按钮、字数和说明提示；关联来源在内部保存。用户无需先选择类型或模式。输入和未提交草稿需要保留；保存失败时不清空内容，保存成功后给出简短反馈并继续阅读。动画尊重系统“减少动态效果”设置，弹层支持焦点管理、返回关闭和小屏键盘。

语音使用“按住说话”：长按期间反馈语音状态，松手结束，上滑后松手取消；结束后的识别文字可编辑，确认保存。打开气泡不自动聚焦编辑框；用户直接点击编辑框，由手机系统管理默认键盘，不需要另外点击“打字”。系统键盘听写可以作为用户输入法自有能力，但不能代替应用长按语音按钮。正式语音能力需接原生录音/识别适配，按需处理权限、服务披露和取消。第一阶段只演示长按状态，不实际录音、不调用浏览器 SpeechRecognition、不连接桌面 Python 服务，也不以固定文字冒充识别结果。具体资料与 skill 查证见 [移动交互依据](./mobile-interaction-reference.md)。

### 个人认知语义

- 个人认知来自用户明确保存的表达和明确选择的立场；阅读、收藏、搜索、导入资料和他人聊天均不等于用户认同。
- 原始用户表达、引用材料、AI 建议、结构分析与学习评价分别保留身份和来源。AI 可以提出整理建议，但不能替用户形成认同。
- “记录一个疑问”不自动成为信念；“记录复述”也不自动证明表述正确或知识已掌握。
- 对已有认知的修订展示旧内容、新内容和修订原因。只关联来源不改写原来源；同步冲突时保留两个表达供用户处理。
- 正式接入应使用现有认知来源与变更语义，不通过创建普通资料笔记间接推断个人认知。

### 可写边界

可以保存、修改或撤回本人短记录，关联资料，明确立场和补充条件。长篇富文本、复杂论证节点/边编辑和批量语义整理交给桌面。原型记录留在独立演示空间，不进入真实认知库。

## 6. 消息：人与人的交流

消息首页分为学友会话与共学群；每个会话可查看历史、发送文本、使用已有服务支持的附件、管理草稿。请求会话、拒绝、屏蔽和不可发送状态沿用社区权限规则。离线消息先保存在发送队列，展示待发送或失败；只有服务回执后显示已发送。

正式聊天复用现有社区账号、私信、群聊与服务接口，不另建移动端假账号或独立聊天室。私聊、群聊及公共内容各自遵循其可见范围。自己的资料只有经用户选择并预览后才作为消息附件或摘要分享。

**AI 助手与社交会话是不同对象。** AI 入口明确标识“AI 助手”，可以协助查找资料、整理草稿或生成计划建议；不会出现在学友列表中冒充真人，也不能未经确认向他人发送内容。人与人的聊天内容不自动进入私人认知或训练成绩。

第一阶段原型使用固定演示会话；发送动作仅增加演示消息并明确标识本机演示。实际账号、跨用户投递、推送与消息同步须在正式服务接入阶段验收。

## 7. 计划：查看、生成与轻量调整

计划首页默认展示今日，支持本周和项目筛选。每项任务显示所属项目、时间、预计时长、状态和下一步；点击后可查看来源资料、开始简测或记录完成情况。复杂甘特图和大规模拖拽不进入手机首页。

生成计划时询问目标、截止日期、可用时间和可用资料。生成结果先是草案，预览展示阶段、任务、时长和与已有安排的冲突。用户可以修改草案，最后点击“确认加入计划”才创建正式计划。未确认的结果保留为草稿，不占用正式排期。

调整计划从具体问题开始，例如今天没时间、修改日期或减少本周任务。先展示受影响的任务、调整前后日期、负荷与原因，再确认保存。一次改期不能隐式删除原笔记、完成其他任务或改变知识掌握度。目标计划已在别处变化时，重新载入并重新预览，不悄悄覆盖。

### 可写边界

- 手机支持本人任务完成、明确的日期/优先级调整、生成与确认草案；写入采用稳定任务和计划 ID。
- 计划完成沿用现有业务语义，区分任务完成与学习检验通过。
- AI 生成与 AI 调整都需要草案预览及明确确认；失败后保留输入和草案。
- 原型仅调整演示计划，确认按钮清楚说明保存至演示空间。

## 8. 头像入口：我、设备与同步

头像入口提供账号信息、当前资料库、设备列表、同步状态、离线下载、主题字号和帮助。共享或切换设备之前，应让用户能确认当前账号与资料库，防止误认为所有库都自动互通。

同步详情显示上次成功时间、本机待上传数量、待下载情况和失败原因；提供重试及查看冲突。账号切换后隔离缓存与待发送操作，禁止旧账号活动写入新账号。退出登录和设备撤销行为的具体保留/清除规则由同步架构和账号策略定义，并在操作前说明实际影响。

## 9. 空、离线、失败和冲突体验

- **首次使用或尚无同步资料**：说明从桌面选择资料并连接账号的下一步；提供独立且明确标识的演示入口，不把欢迎内容当作已同步私人数据。
- **未连接服务**：允许查看已有离线内容及本机草稿，显示未配置状态；不呈现“同步成功”或伪造账号身份。
- **离线**：保留阅读、短记录、已下载内容搜索和允许的本地作答；网络依赖操作说明原因。用户输入先落本机，再提示等待同步。
- **同步失败**：本机内容继续可见，保留相同操作 ID 重试，按对象展示失败。阅读请求失败不能导致整个本地库被清空。
- **数据已过期**：标注可确认的更新时间，允许继续阅读；对需新版本才能执行的写操作，先刷新并保留草稿。
- **冲突**：不以最后一次写入覆盖长内容、个人表达或计划草案。显示涉及对象、两份内容和更新时间，允许保留两份或选择版本；需要重新确认的计划操作重新预览。
- **提交结果未知**：显示“正在确认保存结果”，先查询原操作回执；不因超时立即创建新记录。
- **权限变化或账号失效**：暂停相关上传与消息发送，保留属于该身份的草稿，重新登录并确认资料库后恢复。

## 10. Android 与 iOS

两端共用信息架构、数据协议和业务标准；系统行为通过平台适配层处理。

- 安全区：底部导航避开手势区，顶部避开状态栏与刘海；横屏和平板保留可读行宽。
- 返回：Android 系统返回先关闭弹层、再返回详情来源；iOS 页面返回手势保留相同未保存内容保护。草稿成功保存后才能离开仍在提交的页面。
- 键盘：适配输入法组合输入、键盘抬升和发送/换行操作；输入中不移动用户光标或丢失草稿。
- 权限：原型长按仅演示状态，不采音、不申请录音权限。正式版录音、通知、相机等只在用户触发相应功能时请求；拒绝后保留文本输入和文件选择等替代路径。
- 文件与分享：使用各系统支持的文档选择和分享入口，分享前预览范围；不暴露桌面绝对路径。
- 后台：应用返回前台后刷新身份、增量同步和发送回执；不依赖应用持续在后台运行才能保存内容。
- 无障碍：支持系统字体缩放、屏幕阅读器、明确焦点与减少动态效果；深色模式和错误提示不能只靠颜色表达。

首阶段原型验证移动浏览器中的布局与交互；这不等同于完成 Android/iOS 安装包、系统后台任务、推送、权限和商店发布。

## 11. 现有代码的复用点与缺口

路径相对项目根目录。接入前仍需按当时实现核对接口。

- `src/main.tsx`、`src/App.tsx`：现有桌面主入口与主工作流。移动端应使用独立入口和壳层，避免加载长编辑器、场景和图谱初始化。
- `vite.config.ts`：已有多个 HTML 构建入口，可加入独立移动入口；自动设备跳转需要单独评估，保留桌面正常入口。
- `src/types.ts`：现有资料、任务和计划类型，是共享身份及协议映射的重要来源。移动阅读投影不必复制整个桌面对象。
- `src/services/storage.ts`：桌面文件与浏览器 IndexedDB 的本地持久化。它不是多设备同步服务；移动远端读取不能以调用本地加载函数冒充桌面数据接入。
- `src/services/ragService.ts`：现有搜索接口。浏览器语义检索依赖本地 embedding 与索引；移动端需要已同步阅读投影或受权限约束的服务端检索。
- `src/services/cognition/store.ts`、`src/services/cognition/types.ts`、`src/services/cognition/restatements.ts`：认知变更、来源和复述映射。浏览器锁只处理本机窗口并发，跨设备仍需服务端版本规则。
- `src/components/quickCheck/QuickCheckProvider.tsx`、`src/components/quickCheck/store.ts`、`src/services/quickCheck/`、`src/services/ui/quickCheckWrite.ts`：复用简测语义、草稿恢复、评价与保存边界。手机页面不能另造掌握度规则。
- `src/services/planViewModel.ts`、`src/services/planAdjustmentService.ts`、`src/services/ui/planWrite.ts`：复用计划派生模型、任务调整和版本检查。移动端另做列表呈现。
- `apps/community-web/src/serviceMessageClient.ts`、`serviceGroupClient.ts`、`serviceNewsClient.ts`、`serviceClient.ts`：复用社区账号、消息、群和资讯接口。真实接入仍要验收身份、权限、错误与发送回执。
- `src/services/speechRecognition.ts`、`src/services/sttClient.ts`：当前语音依赖桌面本机 Python/WebSocket，不能直接当作手机录音转写方案。

主要缺口包括：私人资料跨设备同步服务、移动阅读投影与下载、按账号及资料库隔离的本地缓存、离线操作队列、增量游标和删除传播、冲突处理、系统输入法与键盘的真机适配、系统推送与平台安装交付。这些缺口不能由可操作原型代替；应用自有录音/转写不作为本轮简化体验的前置条件。

## 12. 分期与验收

### 第一阶段：产品方案、架构、可操作原型

- 保留五入口导航；发现聚焦单张卡片切换，复述在极简动画气泡中完成，验证长按状态、松手结束、上滑取消和点击编辑框输入，不实际录音。搜索/详情、简测、演示聊天和计划仍可按需进入。
- 原型持久化与真实资料、认知库、学习状态和账号完全隔离；每个关键写入点明确提示演示范围。
- 覆盖正常、空、离线、失败和冲突状态；支持窄屏和安全区，不依赖桌面侧边栏。
- 文档明确数据权属、可写范围、协议和未接入能力，能据此拆分正式实施任务。

### 第二阶段：私人资料的真实只读同步

- 同一账号和资料库可从桌面发布选定私人内容，手机增量下载、检索、阅读并同步阅读位置。
- 该阶段先验证下行与阅读位置，手机短记录仍保留在本机；真实上行与桌面归档在第三阶段交付。
- 验收重复请求、断网重连、跨端同时修改、删除传播、设备撤销和账号切换，不丢失、不串库、不静默覆盖。

### 第三阶段：正式学习与协作

- 手机短记录可以离线保存，恢复网络后上传，桌面可见原始表达、来源和同步结果；分别验收云端接收和桌面归档回执。
- 手机使用现有简测评价标准及活动幂等规则，桌面能看到一致的作答、评价与学习状态。
- 计划生成/调整经过真实草案与版本校验，确认后的结果跨端一致。
- 社交聊天与资讯使用正式服务；手机有真实发送失败和回执体验。

### 第四阶段：平台交付与完善

- 分别完成 Android 与 iOS 的实际设备验证、安装交付、系统返回、键盘、权限、后台恢复、深色模式与无障碍测试。
- 接入并验收原生长按语音、录音/识别权限、输入法、键盘遮挡、系统分享、可控推送和下载管理，不以缩放桌面界面替代移动端验收。
