# 窗口抽取两阶段实验（v7）

## 目标和影响边界

解决同一请求既确定语义边界又推断关系时，定义/公式被合并、关系错配、修改规则引起别处回退的问题。两阶段只是减少单次任务，不预先声称模型效果已改善。

仅新增scripts实验协议和runner，沿用现有本地窗口、原文坐标、四类角色及四类关系。生产抽取、实体关系RAG、向量化、跨窗口匹配、评分、画像、认知库、AgentSkill均不修改；历史v4/v5/v6响应不改写。旧版继续可预览。

## 请求流程

1. 拆块请求：只发送同一阅读窗口（scope=before/core/after）和精简节点提示词，只返回nodes，不要求连线。同句不同定义/公式分别拆，定义与实验数值分别拆，同一情境的设定/问题/结果保持整体。
2. 本地绑定：检查闭合字段、节点ID、角色、重复JSON键、锚点精确坐标、正文句子至少有一处引用。任何失败不自动修复、不追加请求。
3. 独立节点核对：按原文检查粒度、完整语义、限定条件、正文覆盖。检查通过的node-review记录节点hash、原始响应hash、窗口输入hash。绑定通过本身不允许跳过此步。
4. 连线请求：发送固定节点原话与同一窗口原文，不能新增、合并、改写或删除节点。只返回relations。节点原文帮助模型识别端点，S句提供句间联系及关系证据，避免只凭标签判断。
5. 本地拼接：严格验证关系端点、角色约束、原文证据、固定节点hash。拼接仅为阅读视图，不冒充某一次模型输出；两次原始响应独立保存。
6. 独立关系核对：检查支持/质疑方向、命名指代、展开证据、必要定义依赖和遗漏。未通过不接入正式索引。

第二阶段只接受节点核对全部四项为true的记录，且第一阶段保存的节点及原始响应hash都未变。记录origin明确为assistant_source_review_not_human_gold，不冒充人工金标准。语义合格判定仍有主观性，不是自动证明。

## 本轮验收标准

- 窗口6：三个基础定义各自独立；综合账户的一般定义与实验6小时实例独立；两条节省值公式独立；原文研究归属/参照水平/数值和条件不丢失。
- 窗口7：理性原则下的预期、实际观察、作者解释分别可读；保留原价相同、同量节省、时间账户等限定；命名明确依赖效应描述。
- 第二阶段不得修改已验收节点；观察不一致应质疑一致预期，而非支持；不得通过改角色让不合格边过审。
- 展开须确有整体→具体依据；不靠主题/条件共同词连线，不把后文实验条件倒套前文研究。
- 原文可追溯、不补隐含证据、不强求图连通；关系数量和句子引用率不是语义验收的替代品。
- 对窗口5的完整情景和目的展开有本地兼容性测试；真实窗口5未复测，不能据此宣称无回归。

## 实现与本地验证

`scripts/ap-window-two-stage-pilot.ts`：两个独立提示词、阶段专用解析、节点冻结与关系拼接；用纯合成多定义/公式示例，不预填AP原文答案。

`scripts/run-ap-window-two-stage.ts`：仅允许AP窗口6/7，单窗口每阶段最多一次，独占dispatch文件，零自动重试。准备和每阶段执行都核对源码、模型、参数、原文和输入范围。准备零模型请求；读取生产源只为验证原文，结果必须写到生产根之外。

`scripts/check-ap-window-two-stage.ts`：10项本地检查，涵盖职责分离、固定节点不变、未知端点/重复字段/虚构引用/错误角色拒收、旧窗口5示例兼容，以及节点核对门槛和换窗口/响应/节点的拒绝。它们是协议测试，不是实际模型质量评测。

真实实验须另获当前授权：仍只发送窗口6/7，最多4次请求（拆块各1次，节点核对通过后连线各1次），不自动重试。若节点不合格，该窗口不消费第二次请求。上一轮最多2次复测授权不自动扩展成4次。

## 执行方式

准备：`node --experimental-strip-types scripts/run-ap-window-two-stage.ts --prepare --out-root <实验结果根> --windows 6,7`

节点：`node --experimental-strip-types scripts/run-ap-window-two-stage.ts --execute-nodes --allow-cloud --run <新目录> --windows 6,7`

关系：`node --experimental-strip-types scripts/run-ap-window-two-stage.ts --execute-relations --allow-cloud --run <新目录> --window 6`（窗口7同理）

准备后源码或提示词变更，原目录拒绝执行，须重新准备零请求目录。不得重放已dispatch阶段，也不得复制上轮节点冒充本轮模型输出。

## 2026-10-08 实际测试结果

用户随后确认开始，本轮最多4次授权内实际只用3次：窗口6/7各拆块一次，窗口7连线一次，无自动重试。所有模型响应finish_reason=stop，未截断；正式存储零写入。节点和关系的原始响应分别保存在各窗口nodes/relations目录，源绑定、独立语义注释与拒收结果不相互覆盖。

- 窗口6：15个节点，三个基础定义已分开。但N13一般定义/实验6小时实例仍合并，N14两种节省值公式仍合并，before案例末尾提问与比例被无必要地拆开。节点核对accepted=false，窗口6连线请求0次，不为用满4次而追加。
- 窗口7：12个节点，core的条件化理性规则/预期、实际观察、作者解释、效应描述、命名分别可读；保留原价相同、同量节省和而非等条件，允许进入一次固定节点关系测试。该节点核对是助手原文复核，不是独立人工金标准；N5规则与当前预期合块及冗余after条件仍注明限制。
- 窗口7关系：原始返回9条（5理解前提、1支持、1质疑、2展开）。N6观察→N5预期的challenge、N8描述→N9命名的prerequisite有局部改善；第一阶段节点未修改。但R3引用把S4起始与S3结尾写成同一个S4跨度，导致严格拒收missing_anchor。独立逐项诊断为8/9条关系可绑定，不做引用修复或部分发布。引号形式经实际绑定检查并不是其余关系的失败原因。
- 语义问题还包括：命名→研究安排的两个展开没有足够整体→具体依据，部分理解前提必要性和边证据两端覆盖不足。因此不能只修R3坐标就认定通过，也不能由单次结果证明两阶段普遍可靠。

预览区分仅节点草稿与失败关系诊断，拒收的关系不生成合格图；两次模型JSON分别可见，不伪装成一次模型输出。8/9可绑定不等于8条均已通过语义验收。

后续优先改进方向（本轮不自动实施/复测）：拆块阶段继续集中检查独立定义/公式边界；关系阶段可让模型选择已冻结的原文片段ID，而不是重新抄写sentence/start/end，减少跨句寻址错误。实体抽取、跨窗口、向量索引和评分依然不在本轮范围内。
