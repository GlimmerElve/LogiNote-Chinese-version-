# 文档层级与论证语义分块策略

2026-10-07。状态：第一节点已实现独立本地阅读窗口规划器及只读预览；正式来源构建接入和语义完整度验收尚未完成。面向上传资料、知识点参考笔记和个人认知的分层多 RAG 系统。

核心设计是：保留整份资料的文档结构，另外建立文本内部的命题、论证与修辞结构；先检索实体或最小命题，再按任务扩展必要关系，最后才扩大到完整论证或章节。跨资料比对分别读取双方的必要结构，保留冲突原话，不把多个来源混成一个无来源结论。

分块采用“句子优先、保护依赖、窗口有界、关系组包”：默认不把条件、否定和指代拆为孤立节点；先用规则生成可回放的处理窗口，再在窗口内进行受限语义抽取。原文索引块、模型抽取窗口和论证包是三种不同对象，不共用一种切分尺寸。

本方案只改进资料处理、结构索引、检索与导师理解。现有掌握度评分、分数写入和用户画像评分更新不在改造范围内。历史计划中的新评分准入设想不能作为本轮实施目标；历史实测结果保留，不重解释为成功。

## 1 参考策略及采用边界

### ToulminQA

可核验的来源是齐涵悦、杨颜僖、林泽斐的《融合图尔敏模型与大语言模型的社会科学循证知识库构建方法》。其原型采用主张、证据、保证、支撑、限定、反驳六要素，保存研究设计关联，并以主张向量检索论证记录。论文使用整篇 PDF 的多模态抽取，不是现成的局部分块算法。[论文全文](https://dlf.istic.ac.cn/dlf/ch/reader/create_pdf.aspx?file_no=202510003&flag=1&journal_id=dlf&year_id=2025)

本项目借鉴它的论证框架和“命中主张后取回关联依据”。不照搬仅限实证论文的入口，也不要求每段文字凑齐六要素。原文未说出的推导依据不补成资料事实。论文把适用范围和程度都纳入限定，本设计进一步分开记录适用条件与确定程度，便于检索后比对。

### Disco-RAG

Disco-RAG 在检索片段内部识别基本话语单元和修辞结构，在检索片段之间组织修辞图，并规划答案。它提供了文本衔接的参考，但并不等于“先为整篇资料建立完整论证分块”。[原论文方法部分](https://arxiv.org/html/2601.04377v3)

本项目借鉴局部展开、条件、对照和背景关系辅助连接文本。修辞上的对照不直接判为事实冲突，修辞上的原因不直接认证因果事实，叙述顺序不直接判为推理顺序。第一阶段不要求生成整篇资料的完美修辞树。

### X-RAG 和 ArgRAG

用户提供的题名是“X-RAG: Structured Conflict Resolution for Retrieval-Augmented Generation，IEEE，2026”。当前未定位到可核验的该题名原始论文或作者项目，不能据此指定其算法、准确率或实现依赖。保留这个参考项，取得 DOI 或原文后再比较；本方案的条件敏感冲突接口是项目设计，不冒称 X-RAG 的复现。

可核验的相关工作 ArgRAG 的正式题名是“Explainable Retrieval Augmented Generation using Quantitative Bipolar Argumentation”，采用支持／攻击框架进行可解释推理。[作者论文](https://arxiv.org/abs/2508.20131)

本项目可借鉴双方证据并存、结果可追问的思想，不引入其数值论证强度作为掌握度分数，也不把图推理的确定性误认为上游抽取一定正确。

### Agentic GraphRAG 来源追踪

Agentic GraphRAG 是一类系统，不是唯一算法。这里具体参考“Why Neighborhoods Matter: Traversal Context and Provenance in Agentic GraphRAG”：其研究区分最终引用和检索遍历上下文，说明只保存最终引用不足以解释全部来源路径。[作者论文](https://arxiv.org/html/2605.15109v1)

本项目保存被检索、被读取、被纳入上下文和最终被引用的不同集合，以及扩展关系；这不等于能够证明模型实际用了每个访问节点。只记录工具级证据轨迹，不收集或展示模型内部思维链。

### 层级分块补充参考

HiChunk 结合层级文档分块和 Auto-Merge 检索；TreeRAG 采用树状储存及双向遍历；BookRAG 将文档层级与实体关系关联。这些工作适合参考“从小粒度定位到大粒度读取”，不是论证语义正确性的担保。[HiChunk 正式论文及作者代码](https://aclanthology.org/2026.acl-long.1372/)、[TreeRAG 正式论文](https://aclanthology.org/2025.findings-acl.20/)、[BookRAG 作者论文](https://arxiv.org/abs/2512.03413)

用户列表中的 HiChunk、TreeRAG、BookRAG、ToulminQA、ArgRAG 应以这些可核验题名定位，不直接沿用简写题名的出版断言。综述和个性化研究可作为后续背景，不替代本轮分块、关系及来源合同的具体设计。

## 2 当前代码与要素划分

### 编辑器和既有上传资料论证层

目前有九类语句功能：定义、命名、对比、假设、举例、事实陈述、推理、反例削弱、建议对策；显示为概念、判断、逻辑三层。关系只有 support 和 oppose。

这些标签适合编辑与展示，但不能单独表达完整论证。例如，事实陈述可能是某个结论的证据，也可能是另一个论证的主张；推理句可能同时包含前提、依据和结论；举例可能只是说明，不一定构成支持证据；假设是陈述性质，不意味着它永远只能当作前提。定义、命名、对比、建议也不能强制替换为 Toulmin 的六个角色。

代码依据：[旧类型](../src/types.ts)、[显示层映射](../src/services/argumentDoc/types.ts)、[上传抽取合同](../src/workflows/documentKnowledgeExtractPrompt.ts)。

### 新参考结构投影

现有新投影已经支持十一类节点角色：claim、premise、condition、conclusion、definition、fact、hypothesis、example、comparison、exception、counterexample；六类关系：support、oppose、requires_condition、illustrates、contrasts、exception_of。还包含 all／any／unknown 联合前提组、来源版本、原文区间和按任务读取的完整性状态。

所以不能把项目描述成“完全没有条件、例外或按需读图”。应复用这些能力，解决它们与实际上传分块、全局节点及检索入口的衔接，不另造一套没有互通关系的论证库。

代码依据：[结构与读取合同](../src/services/argumentContext/types.ts)。

### 当前分块与向量化的边界

上传资料原文层先按章节、段落、句界形成小块，默认上限为 600 字符和 440 估算 token。既有知识层以一个小块为抽取输入，论证端点必须位于同一输出内；因此它不是整篇论证先建图再分块。已准入的论证单元以“类型＋原话”生成向量，边另存，不是把整张图压成一个向量。

新投影的物理来源适配器则以物理块建立容器和句子，目前整源物理容器上限为 256；构建输入还有 256 引文、64 节点等单批限制。PDF 物理行块不一定等于完整句或语义段，这与旧原文小块的句界处理不是同一算法。

代码依据：[原文分块](../src/electron/rag/chunking.ts)、[知识层向量化](../src/electron/rag/knowledgeStore.ts)、[物理块适配](../src/electron/rag/argumentSourceAdapter.ts)、[单批预算](../src/services/argumentContext/buildTypes.ts)。

当前本地嵌入使用多语言 MiniLM，输出 384 维。这里的“384”是向量维数，不是可输入的 token 数；字符估算也不是实际分词器长度。[嵌入实现](../src/electron/rag/embedding.ts)

## 3 分开保存四种关系维度

底层保留一个来源身份和原文坐标体系，上层使用不同关系维度。以下四类结构共同服务个人库与参考库，但两个库的权限、归属和版本分别保存。

1. **文档结构。** 文档、章节、段落、句子、表格、图注之间的 contains、parent、previous、next 负责定位和导航。章节是一个容器，不自动成为逻辑前提；相邻段落也不自动相互支持。
2. **实体关系。** 实体、实体指称和带条件的事实关系负责对象定位。实体指称绑定到真实命题和原文区间，而不是凭主题相似就合并观点。“同一实体”不代表“同一事实”。
3. **论证关系。** 命题之间的依据、支持、反对、条件、例外和联合前提负责回答“凭什么、在什么情况下成立”。一个论证框架组织多个命题，允许跨段、跨物理窗口。
4. **修辞关系。** 背景、展开、说明、对照、话题衔接等负责理解作者如何组织文本。这些边帮助选择候选和补上下文，不默认转成论证边。

“大的节点”有两种：章节容器和论证集合。前者覆盖连续原文；后者可以由不连续的多个证据区间构成。两者不能互相冒充，也不要求所有关系组成一棵树。

## 4 最小命题与论证框架

最小命题是可明确定位的一个判断或内容单元，不是随意截取的短字符串，也不必脱离上下文独立成立。一个完整句可以含多个命题；一个命题也可能跨 PDF 视觉行或句子。

默认以完整句为候选单元，而不是以每个逗号／子句生成节点。只有确实存在多个可分别讨论的判断，且能保留共享主体、条件、程度和归属时，才细拆为子命题。不能可靠拆分时保留复合节点和完整原句，不通过强制原子化增加错误。

例如“在 B 条件下，A 可能导致 C，也可能导致 D”，默认保存一个条件性复合命题。需要分别检索 C、D 时，可以生成两个子入口，但二者共同依赖 B 和“可能”；不得生成“B”“可能”“C”“D”四个孤立事实。条件作为本句内锚点或跨句依赖保存，不为其机械创建自边。

保存原话区间，并分别记录：

- **语句功能**：保留九类旧标签，供现有编辑器使用。
- **论证角色**：在具体框架内标注主张、证据、推导依据、依据的支撑、限定、反驳。同一个命题在不同框架中可以承担不同角色，不复制为多个无关联事实。
- **适用范围**：主体、对象、人群、时间、情境、条件、比较基准。未表达的范围标为未知，不猜测。
- **陈述性质**：肯定／否定、可能／必然、部分／全部、假设／研究问题／作者断言，以及作者自己说还是引用他人说。这与事实是否可信分别记录。
- **上下文依赖**：省略的主语、指代、必要标题或前文，及其证据区间。无法消解时保存缺口，不伪造实体或关系。

六种论证角色是完整的表达能力，不是每条资料必须六项齐全的收录门槛。定义、孤立事实、未获证据的用户观点都可保存。缺失的 warrant 标为“原文未表达”，不能为了完整而由模型补出常识规则。

一个框架以主张或其他读取锚点为中心，维护命题成员、角色绑定、必要依赖组和可选说明。针对同一锚点，“它是什么意思”“为什么成立”“何时适用”可能有不同必要读取集合；但否定、确定程度及限定该主张的适用范围不能为了压缩而省略。

现有投影 v1 的角色是节点单值。新增多框架角色绑定、确定程度和修辞维度时需使用明确的新版本合同或独立附属资产，不能在旧严格解码器中悄悄增字段、重解释旧票。先复用十一角色和六关系，再增加 frame-relative 角色绑定；不直接重写编辑器九类标签。

## 5 三种分块粒度

### 原文索引块

原文索引块继续承担全文覆盖、词法与向量召回。保留原始文件、规范正文、文档树、物理定位和解析质量。页眉页脚隔离为非正文元数据；表格保留标题、行列头和单位，不能把一串数值冒充完整事实。纯图片、布局或表格无法可靠解析时显式标记，不宣称已经保真。

规范正文一旦保存，其 UTF-16 半开区间即为本版本基准。PDF 跨行重组使用带映射的阅读视图，不能直接改旧正文后继续沿用旧偏移；确需重新规范化时发布新来源版本并重建受影响锚点。

原文覆盖与语义完整分别验收：正文块不漏字，不代表每块独自表达完整判断。当前 600 字符／440 估算 token 的小块可保留为兼容召回通道，但不得继续当作新论证抽取的唯一上下文。新结构必须能回到完整句和其依赖，而不是只回到被硬切的小块。

### 抽取窗口

抽取窗口是让模型看懂局部结构的工作单元，通常大于嵌入小块。核心区域不重叠，上下文区间允许被相邻窗口重复读取，但不重复存为新的原文或独立证据。章节、句界、预算与窗口归属由程序生成，论证意义由后续抽取判定；不先请求 LLM 对全篇分块，再请求另一个 LLM 重新读全篇。

切分按以下顺序执行：

1. **先恢复可读单位。** 沿正文阅读顺序建立段落和句子。PDF 相同正文阅读区域内的视觉换行可以贯通，但不能跨栏、表格、图注、作者归属或标题误拼。恢复不确定时保留物理片段与解析缺口，不猜测阅读顺序。阅读视图保留到规范正文的区间映射。
2. **标出受保护的依赖组合。** 同一句的“只有／除非／如果……才／否则……”、否定范围、概率表达和比较基准保持在一起；列表共享的条件标题、引语归属和未闭合括号保留为阅读依赖。跨句“因此／这一结果／上述条件”等生成相邻上下文需求，不凭连接词确定具体论证对象。
3. **选择可切边界。** 章节标题和不同正文类型是优先边界；连续正文先选段落末尾，再选完整句末尾。明确的新实验标识或作者归属切换可作为候选边界，并分别保留标签。没有这些标识时不凭主题相似度自动认定新实验、观点或冲突。
4. **在预算内装入核心。** 目标长度是选择边界的参考，不是必须凑满的下限。先选接近目标且不破坏受保护组合的边界；所有合适边界都过长时，退回最近的合法边界。章节很短时可以只有一个窗口，不用拼入下一节凑长度。
5. **附带有界上下文。** 默认最多读取前后各一个相邻完整句；出现明确指代／承接标记时，可扩大到前后合计四句，并受上下文预算约束。标题路径和可定位的作者／实验标签另作为已保存元数据传入，不能拿模型生成的章节总结替代真实前文。
6. **记录切分原因和未满足依赖。** 每个窗口记录核心、上下文、所属章节、正文类型、边界原因、预算和待连接项。超过预算的上下文不默默丢弃；标为缺口，后续从原文按需扩展。

标点不是命题边界。“只有网络可用；客户端才会同步”中的分号不能生成两个可独立使用的论证事实。分号、冒号和转折词可提出边界候选；引号中的“稳健；可回退”、小数、缩写、公式内部标点不能直接切开。旧分句函数目前将分号视为终止标点，新阅读视图需有独立版本，不能悄悄改变已有句子 ID 的意义。[现有分句实现](../src/electron/rag/sentenceBoundaries.ts)

第一阶段拟使用一组固定、可配置的起始预算：核心目标 1500 模型 token，核心硬上限 2200，上下文最多 800，窗口正文合计最多 3000。模型输入还需计入提示、字段菜单并预留输出；旧协议的引文／候选数限制同时生效。有效预算取这些限制与当前模型能力中的更小值；不知道可靠长度上限时标记预算未确认，不把估算冒称实际分词结果。这些参数尚未经过新策略实测，不属于已验证最优值。

窗口过大时，优先沿完整句界拆出多个核心；单句仍超限时，仅生成 continuation 阅读片段和共同父句指针。片段可以帮助原文召回，不单独认证为完整命题。只有在读取足够原话、确认依赖后才能发布完整结构；无法在受限窗口中确认则保留 partial，不无限扩大提示或截取前半句算作完整。

表格采用独立阅读单元：小表整体读取，大表按行组读取并携带真实标题、相关列头和单位引用；脚注／适用范围随相关行组绑定。表格标题和列头只存一次，多个窗口引用它们。表格结构无法恢复时退回原文及解析警告，不把孤立数值行当证据。列表每个独立条目可独立定位，但不能丢掉共享导语；代码或公式片段保留其类型，不强制用自然语言主张规则细拆。

整篇资料的节点、引文和物理块上限与“单窗口请求上限”分开。将 256 容器等限制局部化需要新构建合同和聚合存储验证，不是简单调大常量或截取正文前半段。长文按窗口处理，可恢复断点与局部失败。

### 论证包

论证包是围绕一个锚点、针对一个读取任务组织的必要结构集合。它保存节点及关系引用，不要求对应一个连续字符串，也不需要能放进单个嵌入输入。

一个主张的条件即使远在下一段，仍通过已核对关系归入必要集合。不同框架可共享同一原文命题；存储只保存一次原文和规范节点，包保存引用。例子、背景和其他研究通常为可选，若本任务就是解释该实验或该例子，则它们成为任务必需。

必要内容分两组：第一组是解释本句必需的主体、否定、确定程度、条件、归属和指代；第二组是任务必需的支持依据、联合前提和相关边界。第一组随命题读取，第二组按任务展开。已核对的适用条件和限定主张的例外不能降级为普通“可选邻居”，不能因为 top-k 或上下文太小而被移除。

当两组成员都需要时，读取其依赖闭包；嵌套框架按实际依赖展开并检测循环。预算不足、关键边未核对或指代未解时返回 partial／unknown，保留已有成员和未读项，不把缺口当成用户理解有问题。

因此完整策略不是“切成很多小块后只拿 top-k”，也不是“一个论证越长就生成越大的单向量”。小块负责找到入口，论证包负责不丢必要语义。

### 稳定身份和切分可回放

窗口记录来源版本、切分器版本、核心区间、上下文区间和边界理由；命题记录自己的原文身份，不使用“第几个窗口＋本地节点编号”作为全局身份。同一原文命题不能因窗口尺寸改变就变成多个互不关联的观点。来源版本更新时指针重新绑定，不自动沿用旧语义审核。

核心中的每个可读单位恰好归属一个窗口。标题、页眉和元数据分别登记；仅作为上下文的正文仍须在自己的核心窗口被处理，不能误认为“其他窗口看过了，所以已抽取”。同源同版本的参数固定时，窗口边界和上下文应可重复生成。跨区间命题以主锚点所属窗口为 owner，并完整记录其他依赖区间。

## 6 从窗口抽取到全局关系

处理顺序如下，模型仅负责有语义判断的部分，身份、坐标和预算由宿主维护。

1. 保存来源版本与文档结构，建立完整句和可定位子句的阅读视图；为实体指称、句子及区间提供本批可引用菜单。
2. 在窗口中抽取命题、陈述范围、论证候选和轻量修辞候选。模型返回菜单引用与必要语义字段，不重复生成全文、路径、来源 hash 或全局范围元数据。
3. 宿主校验原话、端点、方向、归属和声明范围；对候选做独立的语义核对时，只发送必要原文和候选。独立请求不是独立模型，不能用一致投票证明正确。
4. 按来源版本和证据区间建立全局节点，合并重叠窗口的重复候选。同一证据区间但不同极性／归属的候选是待核对分歧，不直接去重成一项。不同区间即使同义也保留各自原话与引用身份。
5. 生成边界待连接项，例如“上述结论”“与 X 的结果不同”“见表 2”。先找相邻窗口、同节对应实验及明确引用目标，再用受限候选核对实际指向。待连接项按目标线索组织，读取前后原话，不发送整篇图和全部节点要求模型重新配对。
6. 只为有原文依据的候选补跨窗口边，归并框架和联合前提组；最后按任务编译必要论证包。无法确认的连接保留 unresolved 和原句，不能猜一个同主题节点补边。

所有命题以锚点起始位置确定唯一核心窗口 owner；上下文窗口只能提出关联候选，不因重叠重复计入独立证据。边的证据可以跨窗口，必要时单独绑定表达关系的连接句，不强求源和目标处于同一个物理 chunk。

自动补上下文采用一次有界升级：基础上下文不足且存在具体待连接项时，扩大一次到相邻原文或明确引用对象，再核对关系；仍不确定则停在 unresolved。远距离索引候选读取可以继续服务用户的后续问题，但构建流程不靠无限重试凑一张完整图。涉及云模型的补连接请求计入构建预算，必须处于该来源已授权处理范围内。

跨窗口连接不做整篇命题两两比较。优先处理显式指代、引用、共同实验标识、连续论证和明确连接词，实体相似度仅用于召回候选。正文跨文档引用建立 reference 关系，不在未读取被引原文时将其视为已核验外部事实。

联合前提必须表达“这些依据共同参与这个结论”，不能要求每个前提独自充分。现有 all／any 能表达时复用；混合嵌套逻辑不能压成一个 all，暂存 unknown 或由后续新版依赖表达式表示。

## 7 向量索引与多 RAG 协同

继续保留三条召回通道：原文片段、实体及带范围的实体关系、最小命题／论证锚点。三者返回可解析指针，指向同一来源版本下的原文和结构，不能各自维护互不关联的事实副本。

新增命题索引至少保留主体、否定、条件、确定程度和实验／引用归属。论证包可有一个紧凑的检索视图及成员命题向量，但视图只是入口，不能替代保存的原话和全量依赖。用作索引的模型改写必须单独标为 derived，不成为引用证据。

不是每个内部子句都新增一个向量。默认为可解释的命题单元建立入口，细粒度条件和修辞锚点通过父命题或实体指称定位；只有具有独立检索意义的子命题再增加入口。引用父句、共享条件和明确主体的检索视图优先由宿主组合原话，避免为每个片段额外请求模型生成摘要。

嵌入前以当前本地模型真实 tokenizer 和有效输入上限检查长度，计入标题、类型等前缀以及特殊 token；留出配置化余量。不把 440 的估算值当作实际长度验证，也不在未读取配置前承诺模型上限。长命题用有映射的子视图索引，所有命中仍指向完整命题；条件超预算时拆为有依赖指针的视图，不能默默截掉限定语。

结构关系、条件组和文档树不要求每条边各自向量化。精确邻接读取负责补全结构，向量负责找入口。更换嵌入模型或输入模板时保留版本，不能混用不同向量空间的余弦分数。

实体层继续用于定位“选择过载”“某个实验”及相关命题；实体命中后读取其 asserted、hypothesis、research_question 和 qualifiers，不把研究目的的“是否影响”改成确定的因果边。

## 8 渐进式披露和读取停止条件

披露策略由问题意图驱动，而不是机械地扩大一跳、两跳，也不是每次把整个用户画像和全部参考放入提示。

1. **定位入口。** 在允许范围内混合召回实体指称和最小命题，保留来源、命中理由及候选锚点。实体卡可先显示，但孤立实体名不作为答案依据。
2. **读取最小可解释内容。** 读取主张原话和不可省略的否定、条件、程度、引用归属；补必要指代。不能只发送“选项越多购买越少”而省略“可能”“难以比较时”。
3. **读取必要周边关系。** 按“定义、条件、原因、应用、对比”等任务读取支持、必要前提、例外和相应连接证据。因果问法需要推导依据，举例问法需要对应实例，不默认展开所有背景。
4. **扩大范围。** 必要依赖不完整、原文引用跨段或用户要求完整逻辑链时，上升到完整框架；需要理解篇章立场或远距离引用时再读章节、其他框架或相关来源。
5. **检查其他资料。** 对同一对象和相近主张分别读取其他来源的必要包，再执行范围敏感比对。原文、版本、归属和双方限制全部保留。

读取器根据存储的依赖和本题意图执行，不要求模型在每轮重做整份抽取。停止条件是本题所需集合已经读全，或预算／解析缺口明确阻止继续；不能“没找到反例”就宣布不存在反例。覆盖范围、未读节点与缺口随结果返回。

默认先显示简明答案及关键限制，证据和关系图折叠在“查看依据”中。用户要完整逻辑链时展开原话，不增加每条关系的人工确认。展示可折叠，真实冲突及使结论成立的边界不能从实际推理输入中消失。

最终给导师的内容是本轮问题、必要个人认知、必要参考论证包、来源差异／缺口，以及简短行为约束。无关画像、全图 JSON、全部章节和检索轨迹不一起注入；轨迹留作本地追踪。

## 9 跨资料冲突分析

跨资料相似命中不直接生成 oppose。首先比较主体、谓词含义、时间、人群、条件、实验设计、比较基准、量词、极性和确定程度。语义同义匹配与范围比较仍需要模型或其他语义方法，向量相似度只能提供候选。

比对结果至少分为：一致／互补、适用范围不同、确定程度不同、潜在矛盾、已核对的矛盾、证据不足。只有在范围兼容且命题确实不能同时成立时，才报告该范围下的矛盾；范围不明时不默认一致，也不认证矛盾。

例如“在 B 时 A 可能导致 C”与“在 B 时 A 也可能导致 D”是可并存结果，不应删除 C。出现“在同一 B 下 A 不可能导致 C”才形成需要核对的直接冲突候选。“未达到统计显著”不自动等于“没有影响”，“某个个体没有发生 C”也不自动否定概率性主张。

冲突记录保存双方来源与版本、锚点、必要条件与依赖、原话区间、连接证据、范围比较结果和不确定项。它属于跨来源比对资产，不冒充某篇作者自己写下的反对边。引用同一研究的两篇材料标记证据家族，不能当成两份独立实验多数表决。

展示采用双方并列的主张与条件，标出冲突位置，并可展开各自依据。资料可信度、发布日期、研究设计是辅助信息，不通过“资料库天然正确”“新材料必定更正确”或向量分数选择赢家。

个人认知与参考资料比对采用同样读取合同，但不同归属：展示“你当前的观点”与“资料中的观点”。资料未被用户内化时不得写成用户相信的事实；真实观点修订仍走用户确认和历史版本，不由冲突检测自动覆盖。

## 10 可追溯性和质量要求

追溯链为：来源文件与版本 → 规范正文及物理定位 → 命题原话 → 关系证据及角色绑定 → 论证包 → 检索命中与扩展路径 → 实际上下文 → 答案引用。保存源码级工具轨迹，分别标记 visited、read、included、cited，不声称这些标记证明模型因果依赖。

下列情况必须阻断相应结构发布：原文区间伪造、来源身份错误、跨库越权、版本过期、端点不存在、必要依赖被偷删、JSON 合同不能解析。单个失败不能被过滤后改票为 accept；协议失败保留原始响应和明确原因。

局部无法确定的角色、指代或边标为 unresolved／audit_only；它影响的论证包返回 partial／unknown，其他独立合格内容仍可读取。原文片段始终可以按原文检索，但不能冒充完整论证。未知缺口无法定位时，保守限制相关更大范围，不能一律认定为无关缺陷。

质量至少分开记录：解析是否完整、原文锚点是否有效、语义标注是否支持、任务依赖是否读全、来源事实可信度。原文可追溯不等于事实为真；任务可读不等于用户掌握。个人观点即使缺依据也可以保存，但不能冒充参考证据已核验。

模型输出尽量简短：候选引用、语义标签和核对决定；来源身份、原文内容、坐标、成员去重和检索范围由程序持有。不得通过删除检查或默认 accept 消除失败，也不让同一模型在多份清单重复生成完全相同的条件信息。

## 11 合成示例

以下全部为示意资料，不是经典果酱实验的真实数字或已验证心理学结论。

资料甲“选择数量与购买意愿”章节包含：

> S1 当选项难以比较且认知资源有限时，增加选项可能降低购买意愿。
>
> S2 在本实验中，首次接触产品的参与者被随机分配到 6 项组和 24 项组，后者的购买比例较低。
>
> S3 作者认为，这个结果支持 S1，因为难以比较的选项会增加比较成本，而有限的认知资源使部分参与者放弃决策。
>
> S4 对熟悉产品且目标明确的人，上述推断不一定适用。

### 文档结构与最小节点

文档树保存甲 → 章节 → 四句及其原文位置；实体层定位“选项”“购买意愿”“本实验”等指称。命题层保存 S1 主张、S2 实验结果，以及 S3 的作者解释；S1 的两个条件和“可能”绑定到这个主张，S4 绑定到其适用边界。

第二版默认保留 S3 为一个带解释内容的复合节点；确需分别检索比较成本和放弃决策时才细分子命题。每个子命题引用 S3 的确切区间并保留作者归属和必要指代。不能把“因为”后截下的短片段脱离原句独立展示为通用事实。

论证框架 F1 中，S1 是主张，S2 是证据，S3 的解释充当推导依据，S4 是边界／反驳角色。backing 原文未表达，保持缺项。support 边及其来源同时绑定 S3 表达支持关系的原话，不能仅靠 S1 与 S2 主题相似自动生成。

### 分块和按需读取

这段短资料在正式预算下通常整体属于一个抽取窗口，最终形成四个候选节点和一个框架，而不是机械地切成四个模型请求。为演示跨窗口，可用明确的小预算测试配置让 S1–S3 属于 W1、S4 属于 W2；W1 可带 S4 的后文、W2 可带 S3 的前文，但核心归属不重复。核对“上述推断”确实指向 S1 后形成边界关系；如果指向不明则 F1 保留缺口，不猜连线。

向量索引包含 S1 的主张入口、S2 的实验入口以及相关实体；它们都能回到 F1。F1 引用四句的结构，不因为跨两个窗口被拆为两个互不关联论证。

用户问“选项多就一定买得少吗”：先命中实体／S1，再读取 S1 的两个条件、“可能”和 S4 边界；简答可先不展开 S2 的完整实验细节。用户追问“为什么”：展开 S2、S3 及连接证据。用户问“整个研究如何论证”：扩大到 F1 和实验所在章节，不直接载入整份资料。

### 多资料比对与展示

资料乙说“在本实验的熟悉产品且目标明确的人群中，增加选项未观察到购买意愿下降”。检索相近，但与甲的限定范围不同；系统展示范围差异，不直接判为矛盾。

若资料丙说“在甲的同一实验样本、处理和指标下，24 项组购买比例高于 6 项组”，则对甲 S2 产生直接冲突候选。系统分别取回两边必要实验信息和原话，再核对，并保留三种展示内容：双方说了什么、比较条件是否相同、哪里仍不确定。丙的权威性未核验时不能直接覆盖甲。

## 12 影响边界和实施顺序

第一节点先实施来源阅读视图和窗口划分：完整文档树、PDF 跨行映射、表格定位、非重叠核心窗口、上下文依赖及可解释预算。输出能展示“窗口怎么切、为什么切、哪些原话跨窗口”，暂不依赖模型抽取成功率。

本节点先复用原文解析和来源定位，新增独立版本的窗口规划器；不立即替换旧原文索引分块，不同时引入全篇 RST、冲突推理或节点类型迁移。先通过纯本地边界测试，再讨论受限模型抽取接入。设计完整不意味着第一节点必须一次实现全部语义层。

第二节点实现全局命题、跨窗口候选和论证包：复用现有投影的原文证据、六类关系、联合前提和任务完整性；采用明确新版本扩展多框架角色、范围与修辞附属结构。先固定合成资料，验证断点恢复、重复去重和边界缺口。

第三节点接入三路召回和渐进式读取：先小粒度命中，再编译必要包，显示实际读入与未读内容。复用本地嵌入、知识层及 search bridge；旧索引兼容读取，不将 legacy 结构自动认证为新版完整论证。

第四节点接入跨资料比对、来源轨迹和导师上下文：只帮助导师判断遗漏、提出针对性问题、回答认知查询；确认基本来源处理与检索可用后再做这一节点。个人认知自动修订和评分改造不捆绑上线。

预计涉及 `argumentSourceAdapter`、构建合同及服务、projection store／reader、知识层索引、embedding 长度检查、search bridge 和必要的上下文适配；新增窗口／框架／冲突资产模块。具体 IPC 接口变更需在相应节点审查，不把设计当作已实现代码。

不改现有编辑器九种类型和三层默认展示，不强迫用户手工填 Toulmin 表单；不重写实体 RAG、原文 RAG、旧评分、复习调度或用户画像更新；不改变 AgentSkill 注册、工具权限或写入授权。现有技能的检索结果可以增加有版本的结构附件，但不能重解释旧字段或扩大访问范围。

生产资料重建、付费模型抽取和历史索引迁移单独确认，禁止自动沿用既往样本实测授权。上线采取新索引旁路、按来源版本切换、可撤回指针，保留原文检索回退；资料变更或删除时撤销关联包、冲突记录和引用缓存，不能服务旧版证据。

## 13 验收标准

固定资料覆盖：跨行主张、跨段条件、远距离例外、联合前提、多实验、引用别人观点、定义和孤立事实、只有研究目的、表格单位、未知指代，以及超过 256 物理块的长文。

第二版第一节点另固定以下边界预期，模型不得替代这些本地检查：

- “只有网络可用；客户端才会同步”：不得形成两个独立无条件事实；预算允许时组合读取，强制拆开时保留依赖。
- “在 B 下，A 可能导致 C，也可能导致 D”：保留 B 和“可能”，不把 C／D 切成无条件结论。
- “稳健；可回退”位于引号内部，以及小数／缩写／公式中的标点：不误判为语义切点。
- 跨行、跨页的同一正文句：原话可回读到全部真实物理区间；跨栏阅读顺序不明则标缺口。
- 章节短尾和独立定义：允许小窗口，不为达到目标长度拼入下一节。
- 列表共享的“仅在 B 时适用”导语、表格列头／单位／脚注：所有相关条目命中可回到这些依赖。
- 跨窗口重复的上下文：全文核心覆盖一次、节点不重复、证据不重复累计；相同参数可回放相同切分。
- 单句超过硬上限：只有 continuation 片段及父句指针，不产生虚假的完整节点；正文和失败原因仍可检索。

对边界案例人工确认“应保持同读的区间组”和“允许切开的区间”，再进行参数比较。先满足必要语义与来源不丢失的约束，再比较请求数、向量数和上下文大小；不能只追求块数少或模型格式更容易通过。优化窗口尺寸时使用另一组未参与调整的边界样例验证，不据一次模型失败临时修改金标。

先验收资料处理，不验收用户评分：

- 原文覆盖、坐标回读、来源版本和权限的自动检查全部通过；任何相关来源越权或伪造锚点是阻断问题。
- 固定金标中的否定、条件、程度、引用归属和必要联合前提不得丢失。完整任务输出不能含已知必要缺口；未知连接必须可见，不用虚构边填满图。
- 正向与反向关系分别检查；跨窗口候选有实际连接证据，重复窗口不会生成独立重复证据。
- 每类测试查询能召回金标入口并读到该任务的全部必要节点；不同范围的多来源不误报冲突，直接矛盾保留双方原话与关系。
- 展开过程记录入口、每次扩展原因、节点／字符／请求预算和停止原因。结构建立之后，读取已有结构本身不新增抽取请求；回答生成及必要语义比对调用另行计量。
- 参数优化同时评估入口召回、必要条件召回、完整包率、错边率、假冲突率、上下文大小与处理成本；不能只以 JSON 格式通过或模型自报 confidence 作为成功标准。

固定样例零关键语义错误只是接入条件，不是任意资料准确率承诺。后续真实模型测评需事先冻结样本与人工金标，分别报告遗漏、误连和解析失败；未达要求则局部保留原文回退，不继续无限加审核请求。

### 阅读窗口的语义验收标准

正文窗口的核心文本可独立理解比例至少85%，附带已提供的有限上下文后可理解比例至少95%。完整理解要求能明确看出本段说的是谁、说了什么、适用条件、否定、确定程度和作者／引用归属；不是只看是否以句号结束。局部阅读完整也不等于整章完整、推理正确或资料真实。

定义和孤立事实可以完整，不要求每块都有一套主张加证据。未闭合引语、未解指代、缺表头／单位、被截断的条件或不确定阅读顺序，应记为不完整或待复核。待复核不能算作通过。参考文献、标题和明确出版元数据单列，不能靠增加这类小块抬高正文完整率；混有元数据的正文不能随意剔除出分母。

真实验收逐块冻结来源hash、窗口参数、核心和上下文，保留通过／需上下文／不完整／待复核及理由。第一轮全量本地预览用于发现问题，不充当盲测；参数固定后再用未参与调整的资料做正式语义验收。自动规则结果与语义复核结果分别报告，不把规则边界完整率命名为语义准确率。

## 14 第一节点实现与当前结果

独立模块`src/electron/rag/argumentWindowPlanner.ts`已实现完整句候选、分号／引号保护、跨物理行／页的阅读视图、原文片段映射、核心唯一归属、有限前后文和预算检查。跨页句可以由多个不连续原文片段组成，显示用的连接空白不成为原文引文。共同父句标识让超长续片能回到完整原句；来源正文或文档身份改变后拒绝沿用旧窗口。

重复边缘页眉、页码、明确出版信息和通讯脚注按规则登记为元数据候选，原文仍保存并可展开；不是模型认证的非正文。编号章节标签提供局部导航，但尚未恢复完整多级文档树。跨栏顺序不明会保留已有文本和缺口，不宣称自动纠正了阅读顺序。表格、列表共享标题与条件仍需下一节点绑定，不能把当前告警当作已经完成该功能。

`scripts/preview-argument-windows.ts`只读四份现有上传资料，输出56个抽取阅读窗口、887个阅读单元。所有资料的非空白原文覆盖为100%，正文核心重复字符为0，配置预算检查通过。覆盖统计同时包括单列标题与元数据，不意味着每个字符都进入论证正文。生产RAG目录原有JSON的文件列表及内容SHA256前后相同，模型请求0。

真实预览同时显示核心阅读文本、前后文候选、页码、真实片段区间、切分理由和已知缺口。抽样发现的未闭合引号、跨节指代及跨栏疑点保留，当前语义完整度仍是待复核，不能宣布85%／95%已经达标。窗口用于后续模型理解局部资料，不是已经建好的论证节点、已保存向量或完整章节认证。

本地检查`npm.cmd run check:argument-window`通过23组固定边界案例；既有`check:rag-foundation`、`check:rag-semantics`及24组`check:argument-context`回归通过，TypeScript检查通过。这些验证的是规则、来源与兼容边界，不是模型语义抽取准确率。

下一节点将阅读单元及其原文菜单交给受限语义抽取，识别真实命题、必要条件、归属和有依据的关系；复合句只有在保留共享条件与主体时才细拆。宿主负责坐标和稳定身份，模型不重新自由生成正文或来源编号。跨窗口关系另行连接，未确认的关系保留缺口。接入单批协议前还要检查引文／候选数量、模型实际长度和请求总预算，不能只依据当前估算token直接发送。

本次没有替换旧分块／句子ID、重建生产索引、请求嵌入或语义模型，也没有改变评分、用户画像写分、个人认知修订、AgentSkill注册和权限。正式构建尚未使用新窗口；上传主链路切换须在后续接入节点验证后进行。
